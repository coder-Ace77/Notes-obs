Kubectl commands follow a very simple architecture

```bash
kubectl <verb> <resouce> <name> <flags>
```

Verbs can be - 

- get
- logs
- apply
- exec
- scale
- create
- describe
- edit

Every verb is scoped to one or more resoruces for example logs is acoped to only `pods`. `Scale` is scoped to deployment. Additioanlly some verbs can have additional verbs. For an instance `rollout` has mutiple sub verbs
- rollout status
- rollout history
- rollout undo
- rollout restart
- rollout pause/resume

Then comes resource name `logs` and `exec` since make sence only for pods so resource name there is skipped then we write the name of resource which is optinal. Finally we can have flags

- `-n` namespace 
- `-A` all namespace
- `-l app=web` match and list based on matched label
- `-f` logs streaming
- `-o` for changing output format. Here wide means much more detail, then we have json and yaml options.

```kubectl
kubectl get pod frontend-pod -o wide
```

describe provides the information about the resouce as well its status. Usefull for debugging pods , deployments etc.

```bash
kubectl describe pod frontend-pod
```

Then we have exec , logs etc for pod

```bash
kubectl logs -l app=web # use label for deployment so we can get in one go
kubectl logs test -f # streaming logs
kubectl logs test --previous # get logs from prev pod (good for debug)
```

Exec has a very simple structure it is used to run any command on the pod This also skips `resource name`. Now exec can take multiple options most imp is `-it` for interactive shell. Also we separate the command from kubernetes command itself by `--` separator. 

- `-i` = interactive (keep stdin open)
- `-t` = tty (allocate a terminal, gives you a proper shell prompt)

```bash
# Run a one-off command in a pod
kubectl exec my-pod -- ls /app

# Interactive shell (the two flags you'll use 99% of the time)
kubectl exec -it my-pod -- /bin/bash

# If bash isn't available in the image, try sh
kubectl exec -it my-pod -- /bin/sh

# Specify namespace
kubectl exec -it my-pod -n my-namespace -- /bin/bash

# Multi-container pod — specify which container
kubectl exec -it my-pod -c my-container -- /bin/bash

# Run a command without going interactive
kubectl exec my-pod -- env
```

### Deployments

```bash
kubectl get deployments               # or: kubectl get deploy
kubectl get deploy -n my-namespace
kubectl get deploy -A                 # all namespaces
kubectl get deploy -o wide
kubectl get rs                        # list replicasets
kubectl get rs -l app=myapp           # filter by label
```

Same with describe

```bash
kubectl delete deploy my-app
kubectl delete -f deployment.yaml
```

Edit live 

```bash
kubectl edit deploy my-app
```

Scale 

```bash
kubectl scale deploy my-app --replicas=5
```

Rollout 

```bash
kubectl rollout status deploy my-app          # watch rollout progress
kubectl rollout history deploy my-app         # revision history
kubectl rollout undo deploy my-app            # rollback to previous revision
kubectl rollout undo deploy my-app --to-revision=2
kubectl rollout restart deploy my-app         # restart all pods (rolling)
kubectl rollout pause deploy my-app
kubectl rollout resume deploy my-app
```
