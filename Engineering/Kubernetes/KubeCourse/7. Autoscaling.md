There are three kinds of autoscaling. 

- HPA - Horizontal Pod Autoscaler - chanes replica count - Replica count
- VPA - Vertical Pod Autoscaler - Requests/limits
- Cluster Autoscaler - Node count

For example  -

- HorizontalPodAutoscaler - Here spec first defines which kind to autoscale for example we are autoscaling the web Deployment ref via name. And then we define metric to autoscale against and finally `behaviour`. Note `v2` supports multiple resources. `v1` supports `cpu` only. 

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 3
  maxReplicas: 50
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
        - type: Percent
          value: 100                # may double
          periodSeconds: 30
        - type: Pods
          value: 4                  # or add 4
          periodSeconds: 30
      selectPolicy: Max             # whichever is larger
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Percent
          value: 10
          periodSeconds: 60

```

The HPA needs **metrics-server** for CPU and memory, and every container in the target needs a CPU **request** — without it there is no denominator and the HPA reports `unknown`.

```yaml
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl top nodes         # verify
```

Karpenter replaces Cluster Autoscaler on AWS with a different model: rather than resizing pre-defined node groups, it **provisions individual instances** matched to pending Pods.

```yaml
apiVersion: karpenter.sh/v1
kind: NodePool
metadata:
  name: general
spec:
  template:
    metadata:
      labels:
        workload-class: general
    spec:
      requirements:
        - key: kubernetes.io/arch
          operator: In
          values: [amd64, arm64]
        - key: karpenter.sh/capacity-type
          operator: In
          values: [spot, on-demand]
        - key: karpenter.k8s.aws/instance-category
          operator: In
          values: [c, m, r]
        - key: karpenter.k8s.aws/instance-generation
          operator: Gt
          values: ["5"]
      nodeClassRef:
        group: karpenter.k8s.aws
        kind: EC2NodeClass
        name: default
      expireAfter: 720h            # recycle nodes every 30 days
  limits:
    cpu: "1000"
    memory: 1000Gi
  disruption:
    consolidationPolicy: WhenEmptyOrUnderutilized
    consolidateAfter: 1m
    budgets:
      - nodes: "10%"
```
