To write a test in Go, you must follow three strict conventions:

1. **File Naming:** The file must end in `_test.go` (e.g., `math_test.go`).
2. **Function Signature:** The function must start with `Test` followed by a capitalized word, and take exactly one argument: `(t *testing.T)`.
3. **Package:** Usually, the test sits in the same package as the code it tests.

```go
func TestAddition(t *testing.T) {
    result := Add(2, 3)
    expected := 5
    if result != expected {
        t.Errorf("Expected %d, but got %d", expected, result)
    }
}
```

This is manual way of testing. Now there is another way to test.

#### Table driven tests

This is the idiomatic "Go way" to test. Instead of writing separate functions for every case, you define a slice of anonymous structs containing inputs and expected outputs, then loop over them.

```go
func TestCalculateTotal(t *testing.T) {
    tests := []struct {
        name     string
        input    []int
        expected int
    }{
        {"positive numbers", []int{1, 2}, 3},
        {"with zero", []int{0, 5}, 5},
        {"empty slice", []int{}, 0},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := CalculateTotal(tt.input)
            if got != tt.expected {
                t.Errorf("got %d, want %d", got, tt.expected)
            }
        })
    }
}
```

Note that this is the signature of anonymous structs

```go
var_name:= {
	f1 t1
	f2 t2
	...
}{v1,v2..}
```

Notice that our variable was slice. Then you run the same function with different params and expect to get the results. 

```bash
go test # simple test
got test -cover # test covarage
got test 
```
