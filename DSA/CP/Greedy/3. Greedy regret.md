The **Greedy Regret** strategy (often called "Greedy with Rollback" or "Undo Greedy") is an elegant paradigm used when a standard greedy approach fails because taking a locally optimal choice early on might consume resources that block a strictly better choice later.

Greedy Regret allows you to make the greedy choice _tentatively_. If you later realize you made a mistake (because you ran out of capacity/time/health), you can "regret" your worst previous decision, undo it, and swap in the better option.

This paradigm almost always relies on a **Priority Queue (Heap)** to track the decisions you have made so far.

The general algorithm follows this structure:

1. **Sort the input:** Usually by a limiting factor like deadlines, end times, or position.
2. **Accept everything greedily:** As you iterate through the items, tentatively accept every valid item. Update your current state (e.g., total time elapsed, total capacity used) and push the "cost" of this item into a Max-Heap.
3. **Trigger the Regret:** If accepting an item makes your state _invalid_ (e.g., you exceed a deadline or your health drops below zero), look at the top of your Max-Heap.
4. **Undo the worst choice:** If the current item's cost is cheaper than the maximum cost you've paid so far (the top of the Heap), you pop the top element, subtract its cost from your state, and effectively "swap" it with the current item. If the current item is worse than anything in the heap, you simply discard the current item.

Note that we almost always keep in the heap what are choices we took so that we can redo them later. 

**The Problem:** You have $N$ courses. Each course has a `duration` and a `lastDay` (deadline). You start at day 0 and can only take one course at a time. Maximize the number of courses you can take.

Solution: 

Conceptually we take the courses if we can take them. Note we sort the courses via deadline. To understand that we need to ask ourselves what is the most restricting resource for us. Its actually time in this case. We should be completing the earliest ending course first since any course can be started at any time. 

**Standard Greedy Failure:** If you sort by deadline and take courses that finish earliest, a course with a very early deadline but a massive duration might consume all your time, preventing you from taking three shorter courses that have slightly later deadlines.

Now to start with we see the courses and pick them if they can done along with earlier picked courses. Now if we get a course A which can not be done with earlier picked courses pure greedy would have been to discard that courses. However here we also check if there exist a course B with longer dureation than this one. If that is the case then we can pick A instead of B along with outher courses. And answer will remain the same since insead of picking B we pick A. However we get a bit of relaxation with the times since if keep the time of picking of all the other courses same and just instead of starting this B start A at its place. A is guaranteed to get completed since it takes less time. And not only that all the other courses we will be able to do earlier. 

So Code

```cpp
class Solution {
public:
    int scheduleCourse(vector<vector<int>>& courses) {

        sort(courses.begin(),courses.end(),[&](vector<int> &a,vector<int> &b){
            return a[1]<b[1];
        });
        
        priority_queue<int> seen;
        int t=0;
        int ans=0;
        for(auto c:courses){
	        // when the course can be icked with earlier ones
            if(t+c[0]<=c[1]){
                ans++;
                t+=c[0];
                seen.push(c[0]);
            }else if(!seen.empty() && seen.top()>c[0]){
                t-=seen.top(); // IF we are trying to regret. 
                t+=c[0];
                seen.pop();
                seen.push(c[0]);
            }
        }
        return ans;
    }
};
```


### Complimentary variant

Sometimes in the greedy regret we can store in the heap what is not being choosed or deferred. This is done in the case usually where the minimum is being asked. For an example 

#### Problem

A car travels from a starting position to a destination which is `target` miles east of the starting position.

There are gas stations along the way. The gas stations are represented as an array `stations` where `stations[i] = [positioni, fueli]` indicates that the `ith` gas station is `positioni` miles east of the starting position and has `fueli` liters of gas.

The car starts with an infinite tank of gas, which initially has `startFuel` liters of fuel in it. It uses one liter of gas per one mile that it drives. When the car reaches a gas station, it may stop and refuel, transferring all the gas from the station into the car.

Return _the minimum number of refueling stops the car must make in order to reach its destination_. If it cannot reach the destination, return `-1`.

Note that if the car reaches a gas station with `0` fuel left, the car can still refuel there. If the car reaches the destination with `0` fuel left, it is still considered to have arrived.

#### Solution

Here we keep in the heap what ever we are not taking. So if we reach the station say `i`. We diectly push the fuel to the heap. In the feature if we will not be able to reach the station `y` then we will regret and may choose this station in retrospective. 

So idea is simple first we see if we can reach upto current index. Using unused fuels. If we can then good and we push current fuel to the heap. In the end of loop we would have reached final station now there is no station and we should check if we can reach in the end. 

```cpp
class Solution {
public:
    int minRefuelStops(int target, int startFuel, vector<vector<int>>& stations) {
        // max_reach represents the furthest we can go right now
        int max_reach = startFuel;
        priority_queue<int> max_heap;
        int stops = 0;
        
        for (int i = 0; i < stations.size(); i++) {
            int station_pos = stations[i][0];
            int station_fuel = stations[i][1];
            
            // If we can't reach the current station, we MUST refuel
            // from the best past stations we skipped.
            while (max_reach < station_pos) {
                if (max_heap.empty()) {
                    return -1; // Out of fuel and no stations left to use
                }
                max_reach += max_heap.top();
                max_heap.pop();
                stops++;
            }
            
            // We have reached this station. Store its fuel in the heap
            // as an option to use later if we need it.
            max_heap.push(station_fuel);
        }
        
        // After passing all stations, do we still need more fuel to reach the target?
        while (max_reach < target) {
            if (max_heap.empty()) {
                return -1; 
            }
            max_reach += max_heap.top();
            max_heap.pop();
            stops++;
        }
        
        return stops;
    }
};
```

### Variation 2

You can perfectly predict the price of a certain stock for the next _N_ days. You would like to profit on this knowledge, but only want to transact one share of stock per day. That is, each day you will either buy one share, sell one share, or do nothing. Initially you own zero shares, and you cannot sell shares when you don't own any. At the end of the _N_ days you would like to again own zero shares, but want to have as much money as possible.

### Solution 

At its core, this approach solves a chronological pairing problem. You are given a sequence of elements over time, and your goal is to form pairs $(Start, End)$ such that the $Start$ comes strictly before the $End$, in order to maximize the sum of all $(End - Start)$ differences.

The challenge is that forming a pair removes the $Start$ element from the pool. A naive greedy choice might pair a highly valuable $Start$ with a mediocre $End$ simply because that $End$ arrived first, blinding you to a massive $End$ arriving later.

Here is the generalized mechanism of how the "Ghost Token" (or synthetic node) solves this abstractly.

To solve this, you maintain a dynamic pool of available lower bounds (usually a Min-Heap) and a running total of the maximized difference. As you process each element in the sequence chronologically, you perform a two-phase operation:

You treat every incoming element as a potential $Start$ and add it to your pool.

Simultaneously, you check if the current element could act as a profitable $End$. You compare it against the absolute lowest $Start$ available in your pool. If the current element is greater, you greedily pair them, add their difference to your running total, and remove that $Start$ from the pool.

This secures a baseline delta. You have locked in _some_ value, but you must acknowledge this might have been a suboptimal pairing.

Phase 2: The Synthetic Node (The Regret Pathway)
Immediately after making a greedy match, you inject a **synthetic node** back into the pool. This synthetic node has the exact same value as the $End$ element you just used.

This node acts as a regret token. It represents the "right to upgrade" the previous transaction. By putting the $End$ value back into the pool of $Start$ candidates, you are telling the algorithm: _"If you find a strictly better element in the future, you can pair it with this synthetic node."

The elegance of this strategy lies in how the math resolves itself without you ever needing to track which element paired with which.

Imagine three chronologically ordered elements: $A$, $B$, and $C$, where $A \lt B \lt C$.

1. When $B$ arrives, it greedily pairs with $A$. The running total increases by $(B - A)$.
2. You inject a synthetic node with value $B$ into the pool.
3. When $C$ arrives, it finds the synthetic node $B$ in the pool. It pairs with it, and the running total increases by $(C - B)$.

Look at the cumulative addition to the running total:

$$ (B - A) + (C - B) $$

The positive $B$ from the first match and the negative $B$ from the second match create a telescoping sum. They perfectly cancel each other out:

$$ -A + B - B + C = C - A $$

**The result:** The intermediate node $B$ is completely erased from the equation. The math organically bridges the original $Start$ ($A$) directly to the ultimate $End$ ($C$). The baseline delta was seamlessly upgraded to the global maximum without ever having to backtrack or recursively search the array.
