**Everything in Go's I/O system is built on two interfaces:**

```go
type Reader interface {
    Read(p []byte) bool (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}
```

Files, network connections, HTTP request bodies, gzip streams, bytes in memory — they all implement these. Now what happens in most of the i/o can be summarized as - 

![[Pasted image 20260512164540.png]]

The three cases in that diagram are the entire mental model for `io.Reader`. Every read loop in Go must handle all three. Here's what that looks like in practice:

```go
f, err := os.Open("data.txt")
if err != nil {
    log.Fatal(err)
}
defer f.Close()

buf := make([]byte, 4096) // your buffer — you control the size
for {
    n, err := f.Read(buf)
    if n > 0 {
        process(buf[:n]) // ALWAYS process n bytes first, even if err != nil
    }
    if err == io.EOF {
        break
    }
    if err != nil {
        log.Fatal(err)
    }
}
```

The critical rule: **process `n` bytes before checking `err`**. The spec allows `Read` to return both `n > 0` and `io.EOF` simultaneously on the last chunk. Beginner code checks the error first and discards the final bytes. 

### Files

In Go, the `os` package is your primary interface for interacting with the file system. Because Go was designed by systems engineers, the file API closely mirrors the low-level Unix system. 

Three ways to open

First method is using the `os.Open()` , This is the most common function. It opens a file with a **read-only** flag. If the file doesn't exist, it returns an error.

```go
f, err := os.Open("data.txt")
if err != nil {
    log.Fatal(err)
}
defer f.Close() // Essential for resource management
```

Second is to create file  - `os.Create` creates a file if it doesn't exist. If it **does** exist, it **truncates** it (wipes the content to zero length)

```go
f, err := os.Create("output.txt")
if err != nil {
    log.Fatal(err)
}
defer f.Close()
```

- **Behind the scenes:** It opens the file with `O_RDWR|O_CREATE|O_TRUNC` and a permission mode of `0666`.
- **Use case:** Starting a fresh log file or generating a repor

This is the low-level function that `Open` and `Create` call internally. It gives you absolute control over **flags** and **permissions**.


```go
func OpenFile(name string, flag int, perm FileMode) (*File, error)
```

Flags - 

| **Flag**          | **Meaning**                                                    |
| ----------------- | -------------------------------------------------------------- |
| **`os.O_RDONLY`** | Open the file read-only.                                       |
| **`os.O_WRONLY`** | Open the file write-only.                                      |
| **`os.O_RDWR`**   | Open the file for both reading and writing.                    |
| **`os.O_APPEND`** | Append data to the file when writing (don't overwrite).        |
| **`os.O_CREATE`** | Create a new file if none exists.                              |
| **`os.O_TRUNC`**  | If possible, truncate the file when opened.                    |
| **`os.O_EXCL`**   | Used with `O_CREATE`; the file **must not** exist (atomicity). |

We can combine the flags with the or flag `os.O_RDONLY | os.O_CREATE`  Finally the FileMode perm is octal value for the "Owner: Read/Write, Group: Read, Others: Read"). 

Example opening log for appending - 

```go
// Open for writing, create if missing, append if it exists
f, err := os.OpenFile("app.log", os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
if err != nil {
    log.Fatal(err)
}
defer f.Close()
```

What `os.Open` returns is a pointer to an `os.File` struct. This struct satisfies both the **`io.Reader`** and **`io.Writer`** interfaces. This is why you can pass a file directly into `io.Copy`, `bufio.Scanner`, or even your own custom `Read` logic.

Once files are opened in the appropriate mode our task is to read the file and there are two ways either to read entire file all at once which is good for small files but bad for large files. ReadFile opens as well as writes the files as well.  

```go
data , err := os.ReadFile(filename) // reading file
```

This call returns the `data` as slice of bytes `[]byte`

Similarly we can write the files using `os.WriteFile()`

```go
err := os.WriteFile("test.txt", []byte("Hello.go"),0644)
```

**Warning:** Never use `ReadFile` on a multi-gigabyte file (like a database data file). It will attempt to load the entire file into RAM, which will likely trigger an Out of Memory (OOM) crash.

Second way is to use `io.Reader` This is the "pro" way. You open the file and read it in chunks into a buffer. This allows you to process files of **any size** using a constant, small amount of memory.

```go
f,_ :=os.Open("logs.txt")
defer f.Close()

buffer := make([]bytes,1024)

for {
	
	n,err := f.Read(buffer)
	if err == io.EOF{
		break
	}
	
	process(buffer[:n]) // kind of using first n bytes only and is important for last chunk
}
```

Similarly we can use f.Write to write small amount of data. 

```go
f, _ := os.Create("output.bin")
defer f.Close()

n, err := f.Write([]byte("some data"))
```

Note that `f.Read()` is a syscall and is expensive. In systems programming, making a "syscall" (asking the OS to talk to the disk) is expensive. 

**`bufio`** acts as a middleman. It stores your writes in a memory buffer (usually 4KB) and only hits the disk when that buffer is full or when you call `Flush()`.

Buffered reading

```go
f, _ := os.Open("big.log")
defer f.Close()
scanner := bufio.NewScanner(f)
for scanner.Scan() {
    line := scanner.Text() // string, no trailing newline
    fmt.Println(line)
}
if err := scanner.Err(); err != nil {
    log.Fatal(err)
}
```

Finally we can use `f.Seek(offset,mode)` to jump to a specified position. 

`f.Seek(offset, whence)` allows you to move the file pointer:
- `0`: Seek relative to the **start** of the file.
- `1`: Seek relative to the **current** position.
- `2`: Seek relative to the **end** of the file.

```go
// Jump to the 100th byte from the start
newPos, err := f.Seek(100, 0)
```

### Reader and writer

The genius of these interfaces is their simplicity: they decouple the **source/destination** of data from the **logic** that processes it. The `Reader` interface represents an entity from which you can read a stream of bytes.

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
```


The caller provides the bucket (`p []byte`), and the `Reader` fills it with as much data as it currently has or as much as the bucket can hold.

- **`p []byte`**: This is the buffer provided by the caller. The `Reader` doesn't allocate memory; it just fills what it's given.
- **`n`**: The number of bytes actually read.
- **`err`**: Usually `nil`, but returns `io.EOF` (End of File) when the stream is finished.


The `Writer` interface represents an entity to which you can write a stream of bytes.

```go
type Writer interface {
    Write(p []byte) (n int, err error)
}
```

- **`p []byte`**: The data you want to send.
- **`n`**: How many bytes were successfully written.
- **`err`**: Returns a non-nil error if the write failed (e.g., "disk full" or "connection reset").

Because so many types implement these interfaces, you can write a single function that works with **anything**. 

```go
func ProcessData(r io.Reader) {
    b := make([]byte, 1024)
    n, _ := r.Read(b)
    fmt.Printf("Processed %d bytes", n)
}
```

You can pass an `os.File`, a `net.Conn` (network socket), a `http.Response.Body`, or a `bytes.Buffer` into `ProcessData`. The function doesn't care where the bytes come from; it just knows it can `Read` from them. 

Finally since one side provides the Reader and second side provides writer we can simply connect both of them using functions. 

`io.Copy` is the most efficient way to move data from a `Reader` to a `Writer`. Instead of you manually creating a loop, reading into a buffer, and then writing that buffer, `io.Copy` handles it all.

```go
func Copy(dst Writer, src Reader) (written int64, err error)
```

**How it works under the hood:**
1. It allocates a small, fixed-size buffer (usually 32KB).
2. It reads from the source into that buffer.
3. It writes from that buffer to the destination.
4. It repeats this until the source returns `io.EOF`.

Its useage

- **Memory Efficiency:** It doesn't matter if you are copying a 10KB file or a 10GB file; `io.Copy` only uses 32KB of RAM at any given time.
- **Optimization:** If the `Writer` implements a special method called `ReadFrom`, or the `Reader` implements `WriteTo`, `io.Copy` will bypass its own buffer and use those optimized methods directly (sometimes achieving "zero-copy" at the OS level).

`io.Pipe` creates a synchronous, in-memory pipe. It returns a pair: an `*io.PipeReader` and an `*io.PipeWriter`. Anything written to the writer can be read from the reader.

```go
pr, pw := io.Pipe()
```

**The Catch (And why it's powerful):**
- **It is Synchronous:** A call to `Write` will **block** until someone calls `Read` on the other end, and vice versa. There is no internal buffering. The data is passed directly from the writer's buffer to the reader's buffer.
- **Goroutines are Required:** Because it's blocking, you **must** run the reader and writer in separate goroutines. If you try to do both in the same goroutine, your program will deadlock.
