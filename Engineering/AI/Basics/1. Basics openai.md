LLM is basically a  transformer doing completion of existing statements by most probable next word. 

### Types of prompts

- System prompt - The System Prompt sets the **persona, constraints, and tone** for the AI. It is usually hidden from the end-user in an app, but it tells the AI _how_ to behave before the conversation even starts.
- User prompt - The User Prompt is the **actual question or instruction** you type into the chat box. It is the specific task you want the AI to perform right now.

### Chat completion api

The **ChatCompletion API** is the primary interface used to interact with modern AI models (like GPT-4o or your local Gemma 3). Unlike older "Completion" APIs that just finished a single sentence, the ChatCompletion API is designed for **conversations**.

The most important thing to understand is that the API is **stateless**. This means the AI has "goldfish memory"—it does not remember anything you said in a previous request.

To make the AI remember what you just talked about, you must send the **entire conversation history** back to the model every single time you ask a new question.

A standard API call consists of a list of `messages` objects. Each object has two parts:

- **Role:** Who is speaking? (`system`, `user`, or `assistant`)
- **Content:** What are they saying?

```python
response = client.chat.completions.create(
  model="gemma3",
  messages=[
    {"role": "system", "content": "You are a helpful travel agent."}, # Set the personality
    {"role": "user", "content": "Suggest a city in Japan."},         # First question
    {"role": "assistant", "content": "I recommend Tokyo!"},          # AI's previous answer
    {"role": "user", "content": "What is the best food there?"}      # Current question
  ]
)
```

We can also tune the paramters of the model.

| **Parameter**     | **What it does**                                                          | **Range**         |
| ----------------- | ------------------------------------------------------------------------- | ----------------- |
| **`model`**       | Specifies which model to use (e.g., `gpt-4o`, `gemma3`).                  | —                 |
| **`temperature`** | Controls "creativity." High = random/creative; Low = focused/predictable. | 0.0 – 2.0         |
| **`max_tokens`**  | Limits how long the response can be.                                      | 1 – Context Limit |
| **`stream`**      | If `True`, the AI sends text back word-by-word (like ChatGPT typing).     | True/False        |

When the API replies, it doesn't just send back a string of text. It sends a large JSON object containing metadata. You usually have to "dig" to get the actual message:

```python
# The response 'content' is nested like this:
answer = response.choices[0].message.content
```

**Inside the response object, you also find:**

- **`usage`:** How many tokens (words/parts of words) you used. This is how you are billed.
- **`finish_reason`:** Why the AI stopped talking (usually `stop` for a finished thought, or `length` if it hit the token limit).

Other than this openai also exposes chat completion api by simple http requests. 

Full example - 

```python
from openai import OpenAI

# Initialize the client to point to your local Ollama server 
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"  # Required by the library but ignored by Ollama
)

client = OpenAI(api_key=api_key) # if using api key normally base url will be pointing towards openai

response = client.chat.completions.create(
    model="gemma3",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "What are the three laws of robotics?"}
    ],
    temperature=0.7
)

print("--- Gemma 3 Response ---")
print(response.choices[0].message.content)
```

Also we can use simple http requests infact the OpenAI is an wrapper on this http requests format only. 

```python
import requests
import json

url = "http://localhost:11434/api/chat"

payload = {
    "model": "gemma3",
    "messages": [
        {"role": "user", "content": "Write a short poem about Linux."}
    ],
    "stream": False  # Set to False to get the whole response at once
}

response = requests.post(url, json=payload)

if response.status_code == 200:
    data = response.json()
    # Ollama's native API returns the message inside a 'message' object
    print("--- Gemma 3 Response ---")
    print(data['message']['content'])
else:
    print(f"Error: {response.status_code} - {response.text}")
```

### System prompt

We should define what kinds of user prompts we want and also what kind of output we want. That's it. Models are generated on three types of data and so is best for three types of data in dealing - 

-  json
- text
- code

So if we want to have output in some format model will easily return the result. 

| **Technique**           | **Core Purpose**                      | **Best Used For**                                         |
| ----------------------- | ------------------------------------- | --------------------------------------------------------- |
| **System Instructions** | Establishing "Who" the AI is.         | Setting tone, language, and safety guardrails.            |
| **Few-Shot**            | Showing "How" the output looks.       | Classification, data extraction, and specific formatting. |
| **Chain-of-Thought**    | Explaining "Why" the answer is right. | Math, coding logic, and complex decision making.          |

Finally node that the ml models are actually not trained on regualr text for on formatted text variation called chatML(chat markup language). Models are trained to recognise the system prompt and give very high weightage to it. 

Example of chatML

```
<|im_start|>system
You are a professional auditor. Never use emojis.<|im_end|>
<|im_start|>user
How's the weather?<|im_end|>
<|im_start|>assistant
```

During the model's training, researchers use a process called **Instruction Tuning**. They feed the model thousands of examples where:

1. The **System Prompt** says "Do X."
2. The **User Prompt** says "Do NOT do X."
3. The model is **rewarded** only if it follows the System Prompt and ignores the User.

Through millions of these "adversarial" examples, the model learns a hierarchical priority. It understands that the `system` role is the "boss" and the `user` role is the "client." If the client asks the boss to break the rules, the model is trained to say no.
