When a cached method is called, Spring Boot doesn't immediately run the code inside. Instead:

1. It checks if the result for those specific parameters is already in the cache.
2. **If found (Cache Hit):** It returns the result instantly without executing the method.
3. **If not found (Cache Miss):** It executes the method, saves the result in the cache, and then returns it to the user.

Spring Boot makes caching almost effortless with a few key annotations. To start, you just add `@EnableCaching` to your main configuration class.

| **Annotation**    | **Purpose**                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------ |
| **`@Cacheable`**  | Triggers cache population. Use this on methods where you want the result stored.                             |
| **`@CacheEvict`** | Removes data from the cache. Use this when data changes (e.g., an update or delete) to prevent "stale" info. |
| **`@CachePut`**   | Updates the cache without skipping the method execution. Useful for keeping the cache fresh.                 |

While Spring Boot provides a simple `ConcurrentHashMap` provider by default (great for local testing), it’s usually swapped out for more robust "distributed" caches in production:

- **Redis:** The most popular choice. It’s an in-memory data structure store that lives outside your application, so the cache persists even if you restart your app.
- **Ehcache:** A Java-based, feature-rich cache that is very easy to integrate.
- **Caffeine:** A high-performance, near-optimal Java caching library (the successor to Guava’s cache).

Example 

```java
@Service
public class UserService {

    @Cacheable(value = "users", key = "#userId")
    public User getUserById(Long userId) {
        // Simulate a slow database call
        simulateSlowService(); 
        return userRepository.findById(userId);
    }
}
```

Here cache is considered to be the simple `Key` value store. So we also define the `key` and `value`.  `Value` means which cache you want to delete from and `key` is the key to remove.  

Finally if you want to remove the data from cache we do `@CacheEvict`.

```java
@CacheEvict(value = "products", key = "#id")
public void deleteProduct(Long id){
	productRepository.deleteById(id);
}
```

|**Part**|**What it does**|
|---|---|
|**`@CacheEvict`**|This tells Spring: "After this method runs successfully, go find a specific entry in the cache and **kick it out** (delete it)."|
|**`value = "products"`**|This specifies the "bucket" or namespace. It tells Spring to look specifically in the `products` cache and ignore others like `users` or `orders`.|
|**`key = "#id"`**|This identifies the specific item to remove. Using SpEL (Spring Expression Language), `#id` refers to the `Long id` parameter passed into the method.|

### Cache providers

Add dependency

```
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
```

Configure cache

```java
# Redis Connection Settings
spring.data.redis.host=localhost
spring.data.redis.port=6379

# Cache Configuration
spring.cache.type=redis
spring.cache.redis.time-to-live=600000ms 
spring.cache.redis.cache-null-values=false
```

By default, Spring uses Java Serialization, which turns your objects into a messy binary format. Most developers prefer **JSON** because it's human-readable and compatible across different languages. You can do this by creating a configuration bean:

```java
@Configuration
public class CacheConfig {

    @Bean
    public RedisCacheConfiguration cacheConfiguration() {
        return RedisCacheConfiguration.defaultCacheConfig()
          .entryTtl(Duration.ofMinutes(10))
          .disableCachingNullValues()
          .serializeValuesWith(SerializationPair.fromSerializer(new GenericJackson2JsonRedisSerializer()));
    }
}
```

Also if cacheConfiguration bean is missing hibernate will not start. SO its better to do it like this. Othe settings can also be done. 

```java
@Configuration
@EnableCaching
public class CacheConfig {
    
    @Bean
    public CacheManager cacheManager(){
        ConcurrentMapCacheManager concurrentMapCacheManager = new ConcurrentMapCacheManager();
        return concurrentMapCacheManager;
    }
}
```
