### The Abstract Mechanism

You must build the sequence left-to-right, maintaining a running structural prefix (often implemented via a Stack).

**Phase 1: The Eager Append.** As you process the input sequence chronologically, you treat every incoming element as a valid continuation of your prefix.

**Phase 2: The Bounded Eviction.** Before appending the current element, you compare it to the tail of your current prefix. If the incoming element is strictly superior (e.g., smaller in value) to the tail, you want to replace the tail. However, you only execute this eviction if an invariant holds: _the number of remaining elements in the unprocessed input must be sufficient to complete the required global length if you delete the tail._

If the invariant holds, you pop the tail. You cascade this logic backward, continually deleting the tail until you either hit an inferior incoming element, or you hit the mathematical boundary of the remaining input capacity.

### The Mathematical Justification (Left-Weighted Domination)

In lexicographical comparisons, the mathematical weight of an element is entirely dependent on its index. An optimal choice at index $i$ infinitely dominates any arrangement from index $i+1$ onward. (For example, $19999 \lt 20000$).

Therefore, any time you find a superior element, you are mathematically obligated to pull it as far to the left as possible. The stack acts as a localized monotonic boundary. By continuously evicting elements that violate this monotonicity, you ensure the prefix is always locally optimal.

The "remaining capacity" invariant serves as the sole structural safeguard. It allows you to aggressively pursue left-weighted optimization up to the exact limit where doing so would break the global length requirement of the subsequence.
