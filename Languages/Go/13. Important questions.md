1. Go key features

Go (Golang) is a statically typed, compiled language developed by Google. Key features: fast compilation, garbage collection, built-in concurrency via goroutines and channels, strong typing, simple syntax, and excellent standard library.

2.  var vs `:=`

`var` can be used anywhere (package or function level) and allows explicit type declaration. `:=` is a short variable declaration used only inside functions and infers the type automatically. Note that in go variables can be declared at package level (outside of a function) or inside of a function (function level)

3. Blank identifier

The blank identifier `_` discards a value. Used when a function returns multiple values and you only need some of them, or to satisfy interface requirements without using the variable.

4. Go package

A package is a collection of Go source files in the same directory that are compiled together. Every Go file starts with a package declaration. `package main` is special — it defines an executable. All other packages are libraries.

5. Exported vs unexported identifiers

Identifiers starting with an uppercase letter are exported (public) and accessible from other packages. Lowercase identifiers are unexported (private) to the package. E.g., `Foo` is exported, `foo` is not.

6. constants 

Constants are declared with `const` and must be assigned at compile time. They can be typed or untyped. `iota` is a special constant generator that increments in each const block. Constant can be typed or untyped. 

```go
const MAX=1000
```

7. Init functions

`init()` is a special function that runs automatically before `main()`. Each file/package can have multiple `init()` functions. Commonly used for setup like registering drivers or initializing package-level variables.

8. new vs make

`new(T)` allocates zeroed memory for type T and returns a pointer `*T`. `make(T, ...)` is only for slices, maps, and channels — it initializes internal structure and returns the type T (not a pointer).

9. Basic types

Go has: bool, string, int/int8/int16/int32/int64, uint variants, float32/float64, complex64/complex128, byte (alias for uint8), rune (alias for int32 for Unicode code points).

10. int vs int32

`int` is platform-dependent (32-bit on 32-bit systems, 64-bit on 64-bit systems). `int32` is always exactly 32 bits. Prefer `int` for general use unless you need a specific size.

11. rune

A `rune` is an alias for `int32` and represents a Unicode code point. Go source is UTF-8 encoded. Iterating a string with `for range` yields runes (proper characters), while indexing a string yields bytes.

12. Pointers

A pointer stores the memory address of a variable. Declared with `*T`, address taken with `&`, dereferenced with `*`. Go does not have pointer arithmetic. Nil pointers exist and must be checked before dereferencing.

13. A struct is a composite type grouping named fields. Structs support methods but not inheritance.

14. Anonymous structs

Structs without a type name, declared inline. Useful for one-off data structures, test cases, or JSON parsing where you don't want to define a full type.

```go
p := struct{ X, Y int }{X: 1, Y: 2}
```

They are really helpfull while writing response to a json in webservers. 

```go
c.JSON(200,gin.H{
	"msg":struct{
		Name string
		Username string
		}{
			Name: "Adil"
			Username:"adil"
		}
})
```

An **anonymous struct** is a structure type defined without a bound identifier (a name). Instead of declaring a named struct at the package level and then instantiating it, you declare the structural layout and instantiate it inline simultaneously.

The compiler allocates memory for the struct and enforces type safety exactly as it would for a named struct, but the type itself has no global or package-level reference. Two anonymous structs with the exact same fields in the exact same order are considered identical by the compiler (structural typing).

Example 

```go
// Declaration and initialization in one step
config := struct {
    Host string
    Port int
}{
    Host: "localhost",
    Port: 8080,
}
```

2. Struct embeddings

Embedding includes one struct's fields/methods into another without naming it. The outer struct promotes the embedded type's fields and methods. **Struct embedding** is Go's mechanism for achieving **composition**. It allows you to declare a field within a struct using only a type name, omitting the explicit field name. 

```go
type Animal struct { Name string }
type Dog struct { Animal; Breed string }
```

When a struct is embedded, all of its fields and methods are "promoted" to the parent struct. They can be accessed directly as if they were declared on the outer struct. However, the outer struct does _not_ become a sub-type of the embedded struct (this is strict composition, not classical inheritance). Memory-wise, the embedded struct is laid out sequentially within the parent struct's memory footprint. 

```go
d:=Dog{Name:"Tony",Breed:"ABC"}
d.Name // Name field is directly accessible.
```

```go
type Logger struct {
    Prefix string
}

// This method will be promoted.
func (l *Logger) Log(msg string) {
    fmt.Println(l.Prefix, msg)
}

type Server struct {
    Logger // Embedded struct (no field name given)
    Port   int
}

func main() {
    s := Server{
        Logger: Logger{Prefix: "[SERVER]"},
        Port:   8080,
    }
    // The Log method is promoted to the Server level
    s.Log("Starting up...") 
}
```

3. Type alias

A **type alias** creates an alternative identifier for an existing type without creating a technically distinct new type. This is explicitly denoted by the `=` operator in Go (introduced in Go 1.9).

Unlike a **Type Definition** (`type MyInt int`), which creates a strongly typed, entirely new type that requires explicit casting to interact with its base type, a **Type Alias** (`type MyInt = int`) points to the exact same underlying type. The compiler treats them as completely interchangeable. They share the same method set and can be assigned to one another without conversion.

```go
// Type Definition (creates a new type)
type Duration int64 

// Type Alias (creates an alternative name for the same type)
type EpochTime = int64 

func main() {
    var a int64 = 5
    var b EpochTime = 10
    
    // Valid: Both are technically int64 under the hood
    a = b 
    
    var c Duration = 15
    // Invalid: c = a (Requires explicit conversion: c = Duration(a))
}
```

4. Type convertion

In go we have explicit type conversion(no implicit type conversion) using `T()` syntax. Go does not support implicit type conversion. 

```go
var i int = 42
f := float64(i)
s := string(rune(65)) // "A"
```

In Go, the `type` keyword is the fundamental declaration tool used to introduce a new type or an alias into your program's scope. It is incredibly versatile and serves as the gateway for defining several different constructs. The `type` keyword binds an identifier (the name) to a type specification. This specification can be a built-in type, a composite type (like a struct or interface), or a function signature.

```go

type User struct { ... }
type Reader interface { ... }

type HTTPHandler func(ResponseWriter, *Request)

type ID = string
type ID string
```

Unlike a Type Alias, a Type Definition creates a hard boundary in the compiler. Even if `type Celsius float64` and `type Fahrenheit float64` share the same memory layout (a 64-bit float), the compiler treats them as fundamentally incompatible. You cannot add a `Celsius` to a `Fahrenheit` without explicit conversion.

##### Valid conversions

The syntax is `T(v)`, where `T` is the target type and `v` is the value being converted. The compiler checks if the conversion is valid at compile-time. If the underlying memory layout changes (like `int32` to `float64`), the CPU performs the actual instruction to convert the bitwise representation during runtime.

Between numeric types (e.g., `int` to `float64`, `int32` to `int64`).
Between a string and a slice of bytes (`[]byte`) or runes (`[]rune`).
Between custom defined types that share the exact same underlying type. (IMP)

15. Zero value 

Every type has a zero value assigned by default: `0` for numeric types, `false` for bool, `""` for string, `nil` for pointers/slices/maps/channels/interfaces/functions.

16. Slicing operation

`s[low:high]` creates a new slice sharing the same underlying array. `low` is inclusive, `high` exclusive. Modifying elements in the sub-slice also modifies the original. Use `copy()` to avoid this.

17. Map

A map is a hash table: `map[KeyType]ValueType`. Must be initialized with `make` or a literal before use; a nil map panics on write.

Use the built-in `delete(m, key)` function. It's a no-op if the key doesn't exist — no panic.

18. Passing slice or maps

Both are reference types — the function operates on the same underlying data. Modifying slice elements or map entries inside the function affects the caller. However, `append` on a slice may create a new backing array, so the caller won't see length changes unless the slice is returned.

19. Copying slice 

Use `copy(dst, src)` which copies `min(len(dst), len(src))` elements. For a full independent copy:

20. Use `for range`. For slices it returns index and value. For maps it returns key and value (order is random).

21. Interface

An interface defines a set of method signatures. Any type that implements all the methods implicitly satisfies the interface — no explicit declaration needed (duck typing). The empty interface `interface{}` (or `any`) accepts any type.

Unlike Java/C#, Go doesn't require `implements` keywords. A type satisfies an interface automatically if it has all the required methods. This allows decoupling — a type can satisfy interfaces it never knew about.

22. Empty interface

`interface{}` has no methods, so every type satisfies it. Used for generic containers before generics were added. `any` is an alias added in Go 1.18. Type assertions or type switches are needed to recover the concrete type.

23. Type assertion

Extracts the concrete value from an interface.

```go
var i interface{} = "hello"
s := i.(string)       // panics if wrong type
s, ok := i.(string)   // safe form, ok is bool
```

24. Type switch 

A switch statement that matches based on type, not value. Used when handling multiple possible concrete types stored in an interface.

```go
switch v := i.(type) {
case int:    fmt.Println(v+1)
case string: fmt.Println(v)
}
```

25. Pointer receiver vs value receiver

Methods are functions with a receiver. Pointer receivers can modify the original; value receivers get a copy. Use pointer receivers when the method modifies state or the struct is large.

```go
func (p *Person) Greet() string {
  return "Hi, " + p.Name
}
```

Value receiver: method gets a copy, cannot mutate original. Pointer receiver: method gets the address, can mutate original. Consistency matters — if any method needs a pointer receiver, prefer using pointer receivers for all methods on that type.

26. Inheritance 

Go has no inheritance. Instead it uses composition via struct embedding and interfaces for polymorphism. Embedding promotes methods, giving an "is-a" feel without an inheritance chain.

27. nil pointer

A nil interface has neither type nor value — comparing to nil is true. An interface holding a nil pointer has a type but nil value — it is NOT nil when compared to nil. This is a common gotcha.

28. Select

`select` waits on multiple channel operations and executes the first one that is ready. If multiple are ready, one is chosen at random. A `default` case makes it non-blocking.

```go
select {
case msg := <-ch1: handle(msg)
case <-quit: return
default: // non-blocking
}
```

Select statement is made in go specifically for the concurrency. It allows a single goroutine to wait on multiple channel operations simultaneously (both sends and receives)

When a `select` statement is executed, the Go runtime evaluates all channel operations present in its `case` clauses:

**Blocking:** If none of the channel operations are ready (e.g., no data to receive, or no buffer/receiver for a send), the `select` statement blocks the current goroutine until at least one channel becomes ready. First case that is ready is procedded if multiple cases are ready anyone is selected at random. **Expression Evaluation:** All channel expressions (e.g., function calls returning a channel) are evaluated sequentially from top to bottom before the `select` blocks.

```go
select {
case msg1 := <-chan1:
    fmt.Println("Received from chan1:", msg1)
case chan2 <- "ping":
    fmt.Println("Sent 'ping' to chan2")
}
```

By adding a `default` case, the `select` statement becomes non-blocking. If no channels are immediately ready, the runtime executes the `default` block instead of pausing the goroutine.

`time.After(d time.Duration)` returns a channel that will send the current time after the specified duration `d`. The channel is made however the value to this channel is injected by the runtime after specified time. Now when we receive this value we can do many things like cancelling req etc. 

```go
select {
case res := <-apiResponse:
    fmt.Println("Received response:", res)
case <-time.After(2 * time.Second):
    // If apiResponse takes longer than 2 seconds, this case triggers
    fmt.Println("Error: API request timed out")
}
```

Done channel pattern 

```go
func worker(done <-chan bool, work <-chan int) {
    for {
        select {
        case task := <-work:
            fmt.Println("Processing task:", task)
        case <-done:
            // The done channel is closed, signaling the worker to exit
            fmt.Println("Worker shutting down")
            return 
        }
    }
}
```

29. Context 

The `context` package provides a standardized way to pass **cancellation signals, deadlines (timeouts), and request-scoped values** across API boundaries and down the entire tree of goroutines handling that specific request.

The most important technical concept to understand is that **contexts are immutable and hierarchical**.

You never modify an existing context. Instead, you wrap a parent context to create a new child context. This creates a tree structure.

**The Golden Rule of Cancellation:** When a parent context is canceled, **all of its children are canceled cascadingly**. However, canceling a child does _not_ cancel the parent.

**The `Done()` Channel:** Under the hood, cancellation relies on the channel mechanics we discussed previously. The `Context` interface exposes a `Done()` method that returns a channel (`<-chan struct{}`). When the context is canceled, the Go runtime **closes** this channel. Because receiving from a closed channel immediately returns the zero-value, this acts as a broadcast mechanism to wake up any goroutine waiting on it in a `select` statement.

Every context tree must start somewhere. Go provides two empty, non-cancelable contexts to serve as the root:

- `context.Background()`: The standard root. Used in `main()`, `init()`, and at the top level of incoming requests.
    
- `context.TODO()`: Used when you aren't sure what context to use yet, or if a function signature requires a context but you haven't refactored the higher levels to provide one.

Because contexts are immutable, you use these functions to create a new child context from a parent.

`context.WithCancel(parent)` - Returns a copy of the parent with a new `Done` channel, plus a `cancel` function. You call the `cancel` function to close the channel and signal worker goroutines to stop.

`context.WithTimeout(parent, duration)` / `context.WithDeadline(parent, time)`

Returns a context that automatically cancels itself when the timeout/deadline is reached. It also returns a `cancel` function so you can cancel it early if the work finishes before the timeout.

`context.WithValue(parent, key, value)`

Returns a context carrying a key-value pair. Used strictly for request-scoped data (like authentication tokens, trace IDs, or user IP addresses), **not** for passing optional function parameters.

Example 

```go
package main

import (
    "context"
    "fmt"
    "time"
)

// fetchDatabase simulates a slow database query
func fetchDatabase(ctx context.Context) (string, error) {
    // Create a channel to receive the result of our work
    resultCh := make(chan string)

    // Spin up a goroutine to do the actual heavy lifting
    go func() {
        // Simulate a query that takes 3 seconds
        time.Sleep(3 * time.Second)
        resultCh <- "Database Results: User Data"
    }()

    // The critical select block
    select {
    case res := <-resultCh:
        // The work finished before the context was canceled
        return res, nil
    case <-ctx.Done():
        // The context was canceled (either by timeout or manually)
        // ctx.Err() tells us WHY it was canceled (e.g., context.DeadlineExceeded)
        return "", ctx.Err() 
    }
}

func main() {
    // Create a context that will automatically cancel after 2 seconds
    ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
    
    // CRITICAL: Always defer the cancel function. 
    // This releases resources associated with the context immediately 
    // after main finishes, rather than waiting for the garbage collector.
    defer cancel() 

    // The query takes 3 seconds, but the context times out in 2.
    res, err := fetchDatabase(ctx)
    if err != nil {
        fmt.Println("Query failed:", err) // Output: Query failed: context deadline exceeded
        return
    }
    fmt.Println("Success:", res)
}
```

30. Race condition

A race condition occurs when two goroutines access shared data concurrently without synchronization, and at least one is writing. Detect with `go run -race` or `go test -race` which uses Go's built-in race detector.

31. Done channel

A pattern where a channel signals goroutines to stop. The goroutine selects between its work channel and a done channel. Closing the done channel broadcasts to all goroutines listening on it simultaneously.

32. Errors

Unlike many mainstream languages (such as Java, Python, or C++) that use `try/catch` blocks and exceptions, Go treats errors as **ordinary values**. The core philosophy of Go's error handling is that errors are not exceptional events that should break the control flow of a program; they are expected states that should be explicitly checked, handled, or returned at the point of failure.

At the compiler level, an error in Go is simply anything that implements the built-in `error` interface.

```go
// The built-in error interface
type error interface {
    Error() string
}
```

Any type that has an `Error()` method returning a string can be used as an error. Because it is just an interface, an `error` can be a simple string, a complex struct containing HTTP status codes, or a pointer to a custom type.

When a function executes successfully, the conventional standard is to return `nil` for the error value.

The Go standard library provides two primary ways to construct simple string-based errors.

Used for creating static, unformatted error messages.

```go
import "errors"

var ErrDivideByZero = errors.New("cannot divide by zero")
```

Used for creating formatted error messages that include dynamic data.

```go
import "fmt"

func loadConfig(path string) error {
    return fmt.Errorf("failed to load config at %s: file not found", path)
}
```

Modern error handling 

In Go 1.13, the standard library introduced major features for **Error Wrapping**, allowing developers to build a "chain" of errors to preserve context as an error moves up the call stack. You can wrap an underlying error inside a new error using `fmt.Errorf` with the special `%w` verb.

```go
func queryUser(id int) error {
    err := db.Query(id)
    if err != nil {
        // Wraps the original DB error with additional context
        return fmt.Errorf("queryUser failed for id %d: %w", id, err) 
    }
    return nil
}
```

Before Go 1.13, you checked error equality using `==` (e.g., `if err == sql.ErrNoRows`). However, if the error is wrapped, `==` will fail. You must use `errors.Is`, which recursively unwraps the error chain to see if _any_ error in the chain matches the target.

```go
import "errors"

var ErrNotFound = errors.New("resource not found")

// ... somewhere later in the code ...
if errors.Is(err, ErrNotFound) {
    fmt.Println("The item was missing, but we can safely continue.")
}
```

Because `error` is just an interface, you can attach context by implementing it on your own structs. This is crucial for domain-driven design where a simple string is not enough.

```go
package main

import (
    "fmt"
    "time"
)

// Define a custom struct
type RequestError struct {
    Timestamp time.Time
    Endpoint  string
    Err       error // The underlying error
}

// Implement the error interface
func (r *RequestError) Error() string {
    return fmt.Sprintf("[%v] Request to %s failed: %v", r.Timestamp, r.Endpoint, r.Err)
}

// Unwrap allows errors.Is and errors.As to see the underlying error
func (r *RequestError) Unwrap() error {
    return r.Err
}

func main() {
    err := &RequestError{
        Timestamp: time.Now(),
        Endpoint:  "/api/v1/users",
        Err:       fmt.Errorf("timeout"),
    }
    
    fmt.Println(err)
}
```


Since Go 1.13, use `fmt.Errorf("...: %w", err)` to wrap errors with context. `errors.Is(err, target)` checks the chain, `errors.As(err, &target)` extracts a specific type from the chain. `errors.Is` checks if any error in the chain matches a specific error value (sentinel). `errors.As` checks if any error in the chain can be assigned to a specific error type, and if so, sets the target.

`panic` stops normal execution and unwinds the stack, running deferred functions. Use only for truly unrecoverable situations (programming errors, impossible states). Do not use for ordinary error handling — return errors instead. 

`recover` stops a panic and returns the panic value. Must be called inside a deferred function. Used to implement graceful shutdown or to convert panics to errors at API boundaries.

`defer` schedules a function call to run when the surrounding function returns (or panics). Multiple defers execute in LIFO order. Commonly used for cleanup: closing files, unlocking mutexes, etc. Deferred function arguments are evaluated immediately when the `defer` statement is encountered, not when the deferred function runs. The function itself runs later.

Define a struct implementing the `error` interface by adding an `Error() string` method. This lets callers use `errors.As` to extract typed error info like HTTP status codes or field names.

Sentinel errors are predefined error values that callers compare against, e.g. `io.EOF`, `sql.ErrNoRows`. Declared with `var ErrNotFound = errors.New("not found")`. Use `errors.Is` to match them through wrapped chains.

34. Memory 

Go uses a concurrent, tri-color mark-and-sweep GC. It runs concurrently with the program, minimizing stop-the-world pauses (usually sub-millisecond). The runtime manages memory automatically; you don't free memory explicitly.

35. Memory leak 

Common causes: goroutines that never terminate (goroutine leak), storing pointers to old data in global maps/slices, timers or tickers not stopped, or long-lived caches that grow unboundedly. The GC can't collect reachable objects.

36. stack vs heap

The Go runtime decides at compile time (escape analysis) whether a variable lives on the stack (function-local, fast) or heap (must outlive function, GC-managed). You don't control this directly; returning a pointer typically causes heap allocation.

The compiler analyzes whether a variable's reference escapes the function. If a local variable's address is returned or stored somewhere that outlives the function, it "escapes" to the heap. Use `go build -gcflags="-m"` to inspect.

38. Sync.Pool

`sync.Pool` is a cache of temporary objects to reduce GC pressure. Objects can be retrieved (`Get`), used, then returned (`Put`). The pool may be cleared by the GC at any time, so only use for reusable, stateless buffers.

39. goroutine leak

A goroutine leak occurs when goroutines are started but never terminate, consuming memory and resources indefinitely. Common causes: blocking on an unbuffered channel with no sender/receiver, or infinite loops without an exit condition.

40. Unsafe package

The `unsafe` package allows bypassing Go's type safety — pointer arithmetic, accessing struct field offsets, converting between pointer types. Used in performance-critical low-level code. Generally avoided; the name is intentional.

41. String modification

Strings in Go are immutable byte sequences. You cannot modify a string in place. To "mutate" a string, convert to `[]byte`, modify, then convert back. String concatenation with `+` in a loop is inefficient — use `strings.Builder`.

42. String builder

Both are used for efficient string building. `strings.Builder` is write-only and slightly more efficient (no copy on `String()`). `bytes.Buffer` supports reading and writing, more versatile but slightly heavier.

In Go, strings are immutable. This means that every time you use the `+` or `+=` operator to concatenate strings, Go creates a brand new string in memory and copies the contents over. If you are building a string dynamically (e.g., inside a loop), this can become highly inefficient and cause significant performance overhead.

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	// 1. Declare the builder
	var sb strings.Builder

	// 2. Write to the builder
	sb.WriteString("Hello")
	sb.WriteString(", ")
	sb.WriteString("Go Developers!")

	// You can also write runes or bytes
	sb.WriteRune(' ')
	sb.WriteByte('🚀') // Note: '🚀' is a rune, WriteByte is for single bytes. Let's use WriteRune for emojis or strings.WriteByte('!') 
    sb.WriteRune('🚀')

	// 3. Convert to a standard string
	result := sb.String()

	fmt.Println(result)
}
```

### Key Methods

- **`WriteString(s string) (int, error)`**: Appends a string to the builder.
    
- **`WriteRune(r rune) (int, error)`**: Appends a single UTF-8 character.
    
- **`WriteByte(c byte) error`**: Appends a single byte.
    
- **`String() string`**: Returns the accumulated data as a standard Go string. **Crucially, this step performs zero memory allocation**; it simply returns the underlying byte slice cast as a string.
    
- **`Reset()`**: Clears the builder so it can be reused without allocating a new underlying slice.

If you know roughly how large your final string will be, you can use the `Grow(n int)` method. This pre-allocates memory for the internal buffer, preventing Go from having to resize the buffer dynamically as you add more text.


43. Closure

A closure is a function that captures variables from its surrounding scope. The captured variables are shared changes in the closure affect the original and vice versa. Not only that closure variables remain for more than the scope of outer function. This pattern is highly use to inject some the argument to a handler function. 

44. Variadic functions

Functions that accept a variable number of arguments, declared with `...` before the type. Inside the function, the parameter is a slice.

```go
func sum(nums ...int) int {
  total := 0
  for _, n := range nums { total += n }
  return total
}
```

45. Reflection 

The `reflect` package allows inspecting and manipulating types and values at runtime. Use `reflect.TypeOf()` and `reflect.ValueOf()`. Powerful but slow and bypasses type safety — use sparingly.

46. Stringer

Any type implementing `String() string` satisfies `fmt.Stringer`. The `fmt` package calls this method automatically when formatting with `%v` or `%s`, enabling custom string representation.

47. Functional types

Functions are first-class values. You can assign functions to variables, pass them as arguments, and return them. `type HandlerFunc func(http.ResponseWriter, *http.Request)` is an example of a named function type.

48. go.sum

`go.sum` contains cryptographic hashes of module versions to verify integrity. Go tools check this file before using downloaded modules to detect tampering. It should be committed to version control.

49. go routine vs os.thrreads

OS threads are heavyweight (~1MB stack, kernel-managed). Goroutines start with a tiny stack (~2KB) that grows as needed, managed by the Go runtime on top of a small number of OS threads using the M:N scheduler.

50. `GOMAXPROCS`

`GOMAXPROCS` sets the maximum number of OS threads that can execute Go code simultaneously. Defaults to the number of CPU cores. Set via `runtime.GOMAXPROCS(n)` or `GOMAXPROCS` env variable.

51. time package 

`time.Sleep(d)` pauses once for duration d. `time.NewTicker(d)` fires repeatedly at interval d, sending on a channel. Stop tickers with `ticker.Stop()` to prevent goroutine leaks.
