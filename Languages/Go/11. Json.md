**JSON** (JavaScript Object Notation) is a lightweight, text-based format for storing and transporting data. Technically, JSON is a string that follows a specific set of syntax rules to represent data structures: **Objects** (maps/dictionaries) and **Arrays** (lists).

For a string to be valid JSON, it must adhere to these strict requirements:

- **Data is in name/value pairs:** A name is followed by a colon, then the value.
- **Double Quotes Only:** All keys (names) and string values must be enclosed in double quotes (`"key"`). Single quotes are invalid.
- **Commas:** Multiple name/value pairs or array elements must be separated by commas.
- **No Trailing Commas:** The last item in an object or array cannot have a trailing comma.

JSON is limited to a specific set of "primitive" and "structured" types:

|**Type**|**Description**|**Example**|
|---|---|---|
|**String**|Unicode characters in double quotes.|`"Hello World"`|
|**Number**|Integer or floating point.|`42` or `3.14`|
|**Boolean**|Logical values.|`true` or `false`|
|**Null**|An empty value.|`null`|
|**Object**|Unordered set of name/value pairs.|`{"id": 1}`|
|**Array**|Ordered list of values.|`[1, 2, 3]`|

JSON mimics two universal data structures found in nearly all programming languages:

An object begins with a left brace and ends with a right brace. Each name is followed by a colon, and the name/value pairs are separated by commas.

```json
{
  "username": "Dev_User",
  "isAdmin": true,
  "reputation": 1500
}
```

An array begins with a left bracket and ends with a right bracket. Values are separated by commas. Arrays can hold any valid JSON type, including other objects or arrays (nesting). A json string can also be the array.

```json
[
	{},
	{},
	"Hello"
]
```

```go
{
  "tags": ["programming", "api", "data"],
  "recent_scores": [95, 88, 92]
}
```

In technical workflows, you'll often hear these terms:

- **Serialization (Stringify):** Converting a data structure (like a Python Dictionary or Java Object) into a JSON string so it can be sent over a network.
- **Deserialization (Parse):** Converting a received JSON string back into a native data structure that the programming language can manipulate.

In the Go (Golang) ecosystem, JSON handling is primarily managed by the standard library's `encoding/json` package. Because Go is a statically typed language and JSON is dynamic, the "technical" part involves mapping JSON keys to Go **Structs** or **Maps**.

Go uses **Struct Tags** to define how a struct field should be mapped to a JSON key. These are literal strings attached to field definitions.

```go
type User struct {
    ID        int    `json:"id"`        // Maps "id" in JSON to ID in Go
    Username  string `json:"username"`
    Email     string `json:"-"`         // The "-" tells Go to ignore this field
    IsActive  bool   `json:"is_active,omitempty"` // Omits from JSON if false/zero
}
```

We write them as `json:"name_of_key_in_json"`  In Go, **struct tags** are small pieces of metadata attached to the fields of a struct. While they are technically just strings, they are incredibly powerful because they allow you to control how your data is handled by external libraries (like JSON encoders, database drivers, or ORMs). Think of them as "instructions" that other packages can read using **reflection**. 

Also note that field names must be capitalised so that other frameworks are able to see the fields. 

A struct tag is placed after the field type, enclosed in backticks (`` ` ``). The standard format is a space-separated list of `key:"value"` pairs.

The `encoding/json` package is the most frequent user of struct tags. They allow you to map Go's `PascalCase` field names to `snake_case` or `camelCase` for APIs.
Libraries like **GORM** or `sqlx` use tags to map struct fields to database columns or define constraints.


**Marshalling (Encoding)**

```go
user := User{ID: 1, Username: "Gopher"}
jsonData, err := json.Marshal(user)
// Result: {"id":1,"username":"Gopher"}
```

The `Marshal` function just takes the object. 

**Unmarchalling**

Parsing a JSON byte slice into a Go pointer.

```go
jsonInput := []byte(`{"id": 1, "username": "Gopher"}`)
var user User
err := json.Unmarshal(jsonInput, &user)
```

Here we need to give as input first the `data` and secondly the pointer variable in which we need to put data. 

For network connections or large files, using `Marshal` is inefficient because it loads the entire dataset into memory. Instead, use `json.Encoder` and `json.Decoder` to stream data directly to/from an `io.Writer` or `io.Reader`.

```go
// Streaming to an HTTP response
json.NewEncoder(w).Encode(user)

// Streaming from a file
json.NewDecoder(file).Decode(&user)
```

The standard library `encoding/json` relies heavily on **Reflection** (inspecting types at runtime), which can be slow in high-performance environments.

### Working of marchelling and unmarchelling

To understand how Go handles JSON, you have to look under the hood at **Reflection**. Because Go is statically typed, the library doesn't know the structure of your data at compile time.

#### The Inspection Phase (Reflection)

When you call `json.Marshal(v)`, the library uses the `reflect` package to inspect the type of `v`.
- **Type Discovery:** It identifies if it’s a struct, map, slice, or primitive.
- **Tag Parsing:** It iterates through every field in a struct and parses the string inside the backticks (e.g., `` `json:"user_id"` ``).
- **Recursive Walk:** If a struct contains another struct, it recursively repeats this process.

#### The Buffering Phase

Once it knows the structure, the library begins writing the output to a byte buffer. It handles escaping special characters (like `<` or `&`) to ensure the JSON is safe for web transmission.

#### The Unmarshalling Bottleneck

Unmarshalling is more expensive than marshalling. The library must:

1. Scan the JSON string to find keys.
2. Match those keys against the struct field names or tags.
3. Convert the string representation of values (like `"123"`) into the target Go type (like `int`).

### Jsoniter

**Jsoniter** ("JSON iterator") is a high-performance replacement for the standard library. It is designed to be a "drop-in" replacement, meaning you can swap it in with minimal code changes.

While the standard library uses a generic reflection approach for every call, Jsoniter uses several optimizations:
- **Codec Caching:** Instead of reflecting on a struct every time you call the function, Jsoniter reflects once, builds a "codec" (a specialized instruction set for that specific struct), and caches it.
- **Lazy Decoding:** It can skip parts of the JSON that you don't actually need to access, saving CPU cycles.
- **Avoidance of Interface{}:** It minimizes the use of `interface{}`, which reduces memory allocations and "boxing/unboxing" overhead.

Usage - 
Install

```go
go get github.com/json-iterator/go
```

The easiest way to use it is to alias the package. This allows you to keep using `json.Marshal` and `json.Unmarshal` syntax:

```go
import (
    "fmt"
    // Alias jsoniter as 'json'
    jsoniter "github.com/json-iterator/go"
)

var json = jsoniter.ConfigCompatibleWithStandardLibrary

func main() {
    type Product struct {
        Name  string `json:"name"`
        Price int    `json:"price"`
    }

    p := Product{Name: "Keyboard", Price: 100}
    
    // This looks like standard library code but uses jsoniter logic
    data, _ := json.Marshal(p)
    fmt.Println(string(data))
}
```
