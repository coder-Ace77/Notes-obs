Interacting with llm model using langchain is straightforward.

```python
from langchain.chat_models import init_chat_model
model = init_chat_model(model="gpt-5-nano")

response = model.invoke("What's the capital of the Moon?")
response
print(response.content) # response object
print(response.response_metadata) # metatdata object
```


`init_chat_model` - First field has to be the name of model. Model will automatically get the api key if env is giving it out in format `OPENAI_API_KEY`, temperature(defines creativity),max_tokens and many more. It returns the model. 

`model.invoke` - First field is the text input. resturns a response object with two fields content and response_metadata. 

## Agents

To create agent we use create_agent build on top of langraph. 

```python
from langchain.agents import create_agent
agent = create_agent(model=model,system_prompt="You are a pirate.")
or 
agent = create_agent("gpt-5-nano")
```

To interact with agent we simply invoke it. So we pass messages as a simple dictionay which again is the array of messages using HumanMessage , or AIMessage. Note that we can provide system prompt during the create_agent. 

```python
from langchain.messages import AIMessage

response = agent.invoke(
    {"messages": [HumanMessage(content="What's the capital of the Moon?"),
    AIMessage(content="The capital of the Moon is Luna City."),
    HumanMessage(content="Interesting, tell me more about Luna City")]}
)

pprint(response)
```


This dictionary is actually contains the history. We can reduce the perceived latency of system by streaming tokens. 

```python
for token, metadata in agent.stream(
    {"messages": [HumanMessage(content="Tell me all about Luna City, the capital of the Moon")]},
    stream_mode="messages"
):

    # token is a message chunk with token content
    # metadata contains which node produced the token
    
    if token.content:  # Check if there's actual content
        print(token.content, end="", flush=True)  # Print token
```

Usefull prompt strategies - 

- First to get the desired output we should include the instruction in the system prompt. Like give out short answers. 
- Second way is to give examples of how and what kind of answers we want to have. This is called few shot examples. 
- Or best we can use both. 
- Finally we should provide the structure of the response and will give out the best structure of project. 
- Finally to have exact structure we can use pydantic library create a data model and pass it as the response format in system prompt. 
``
```python
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from pydantic import BaseModel

class CapitalInfo(BaseModel):
    name: str
    location: str
    vibe: str
    economy: str

agent = create_agent(
    model='gpt-5-nano',
    system_prompt="You are a science fiction writer, create a capital city at the users request.",
    response_format=CapitalInfo
)

question = HumanMessage(content="What is the capital of The Moon?")

response = agent.invoke(
    {"messages": [question]}
)

response["structured_response"]
```

Note that result however is written in the `structured_response` of response and we can call the fields like `response["structured_response"].name` etc. 
### Tools

Agents can take tools and decide on which tool to use at a given point. In the basic a tool is simply a function to make a function a tool we need to decorate with tool. 

```python
from langchain.tools import tool

@tool("square_root")
def square_root(x: float) -> float:
    """Calculate the square root of a number"""
    return x ** 0.5
```

However to be able to understood by agent. It should have the detailed account of tool. Name of tool is by default name of function which can be overwritten by giving out the name beside tool. 
The behaviour of tool is understood by the llm using doc string on top of tool. However we can also pass the description as the string to the tool. 

Finally to invoke the tool we use tool.invoke and pass params.

```python
square_root.invoke({"x":467})
```

Agent will be invoking the tool in the similar way. Now we can provide the tools to the agents in the following way.

```python
from langchain.agents import create_agent

agent = create_agent(
    model="gpt-5-nano",
    tools=[tool1],
    system_prompt="You are an arithmetic wizard. Use your tools to calculate the square root and square of any number."
)
```

Now when this agent is invoked it may try to put the tool call and the tool's response is also given back messages. Finally agent may use tool call and then construct response based on tool as well.  

```python
from langchain.messages import HumanMessage

question = HumanMessage(content="What is the square root of 467?")
response = agent.invoke(
    {"messages": [question]}
)
print(response['messages'][-1].content)
```

Note that unlike previously where ai agent used to have one resquest and one reponse for it. Here it can choose to do multiple model calls. For example here at first it will try to understand and all and then will decide to run a tool. It will return one response instructing llm to run a tool call. 

And then at second tool will be called and passed back to llm and then it will try to use it as well and construct final response. 

### Web search as tool 

One of the important point about the llms is they have cutoff training and no information after the cutoff date is known to llm. So to get latest information we can use web search and provide it as a tool. TavilyClient is a library designed for taking questions and providing answers which can be injested by the llm. 

```python
from langchain.tools import tool
from typing import Dict, Any
from tavily import TavilyClient

tavily_client = TavilyClient()

@tool
def web_search(query: str) -> Dict[str, Any]:
    """Search the web for information"""
    return tavily_client.search(query)
web_search.invoke("Who is the current mayor of San Francisco?")
```

Now creating agent - 

```python
agent = create_agent(
    model="gpt-5-nano",
    tools=[web_search]
)

question = HumanMessage(content="Who is the current mayor of San Francisco?")

response = agent.invoke(
    {"messages": [question]}
)
```

### Adding the memory to agents

We can simply add the short term memory this can be done from langgraph library.

```python
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
		"gpt-5-nano",
		checkpointer=InMemorySaver(),
	)
```

Now we can provide a config which is meant to track which agents will be able to use which memory. All agents on the common thread id will have same look to memory. 

```python
from langchain.messages import HumanMessage

ques = ""
config = {"configurable":{"thread_id":"1"}}

response = agent.invoke(
	{"messages"=[ques]},
	config,
	)
```

### Mutlimodel

Current llm models are multimodel meaning they can also take video/audio as input. We can simply pass them to the model where now the content will also have type. And to pass the input video we will process it at our end and will pass it to the llm as input in base64 encoded form. 

Image input 

```python
from ipywidgets import FileUpload
from IPython.display import display

uploader = FileUpload(accept='.png', multiple=False)
display(uploader)

import base64

# Get the first (and only) uploaded file dict
uploaded_file = uploader.value[0]
# This is a memoryview
content_mv = uploaded_file["content"]
# Convert memoryview -> bytes
img_bytes = bytes(content_mv)  # or content_mv.tobytes()
# Now base64 encode
img_b64 = base64.b64encode(img_bytes).decode("utf-8")

# observe the question is now a list and constains type as well
multimodal_question = HumanMessage(content=[
    {"type": "text", "text": "Tell me about this capital"},
    {"type": "image", "base64": img_b64, "mime_type": "image/png"}
])

response = agent.invoke(
    {"messages": [multimodal_question]}
)

print(response['messages'][-1].content)
```
