Its really hard to reason about the networking when looking at once. Therefore the network have been abstracted into the multiple layers to make the reasoning and implementation about them easier. The layers works by using the layer beneath and offers some services to layers above it. 

#### OSI model

(OSI) Open Systems Interconnection, written by the International Organization for Standardization in the late 1970s and 80s. It uses seven layers. 

- Layer 1 - Physical layer - Deals with the calbes , radio waves.
- Layer 2 - Data link layer - It makes sure that two devices which are directly connected can send chunks of data called frames using something called `MAC` address. 
- Layer 3, the Network layer - handles getting data across many connected networks , which is where IP addresses and routers live.
- Layer 4, the Transport layer, deals with the two computers at the ends
- Layer 5, the Session layer, is about opening, keeping alive, and closing a conversation.
- Layer 6, the Presentation layer, is about the format of the data, such as encryption, compression and character encoding.
- Layer 7, the Application layer, is the protocols that programs actually speak, like HTTP for the web, DNS for looking up names, and SMTP for email.

Seen as one story, loading a web page goes like this. Your browser creates the request (Application). The operating system splits it up and attaches port numbers and sequence numbers so that the server can put it back together and confirm what arrived (Transport). IP stamps your address and the server’s address on it, so routers across the world know where to send it (Internet). Your Wi-Fi card wraps it in a frame addressed to your router and turns it into radio signals (Link). The router strips off the Link envelope, looks at the IP address, builds a new Link envelope for the next hop, and sends it on. This repeats across many routers until it reaches the server, which unwraps everything in the opposite order. Notice that the routers in the middle only ever open the bottom two envelopes, since they only need to read addresses, never the web request itself.

#### Differences

First, the number of layers: OSI has seven because it carves things finely, and TCP/IP has four because it describes what real protocols do. Second, the purpose: OSI is mostly a vocabulary for talking and troubleshooting, and TCP/IP is the actual blueprint the internet runs on. 

When someone says “that’s a layer 7 load balancer” they mean it reads HTTP, and when they say “layer 4” they mean it only looks at TCP/UDP and ports. Those numbers come from OSI, even though the software underneath follows TCP/IP.

#### History

So the International Organization for Standardization (ISO) started a project in 1977 to define a vendor-neutral way of building networks. The word “open” in Open Systems Interconnection is the whole point: a system built to the standard would be open to talk to any other system built to it, no matter who made it. The committee ended up with seven layers, and they were chosen with some thought.

While the OSI committees were still debating, a different group had already started building. In 1974, Vint Cerf and Bob Kahn published the design for a way to join different networks into one “internetwork”, which became TCP, and in 1978 the work was split so that IP handled addressing and routing while TCP handled reliable delivery. This was funded by the US defence research agency for ARPANET. 

On 1 January 1983, ARPANET switched over to TCP/IP for good. Around the same time, the Berkeley version of Unix (4.2BSD, 1983) shipped with TCP/IP built in, which put working networking, with source code, on the computers of nearly every university for free.


> [!NOTE] 
> OSI is a reference model: a seven-layer way of describing how networks should be organised, designed by a standards committee so that different vendors’ equipment could interoperate. TCP/IP is the model the internet actually runs on. It has four layers (Application, Transport, Internet, Link) and it was written down after the protocols already existed, so it describes working software. The practical difference is that OSI splits things more finely, for example separating Session and Presentation from Application, whereas TCP/IP folds those three into one Application layer and folds Physical and Data Link into one Link layer. In day-to-day engineering we use TCP/IP for what really runs, and OSI numbering as a shared vocabulary, like saying ‘layer 4 load balancer’ or ‘layer 7 firewall’.


### Layers apart from very important

#### Layer 7 - Application

The first thing to clear up is that the Application layer is not the application. Chrome is a program. The Application layer is the language that Chrome speaks over the network, which means the rules for how a request is worded, what a reply looks like, and what each word means. For the web, that language is HTTP. 

For looking up names it’s DNS, for sending email it’s SMTP, for remote login it’s SSH, and for file transfer it’s FTP. For a feel of what a protocol is, here’s a real HTTP request as it travels. It’s just structured text:

```
GET /accounts HTTP/1.1
Host: mybank.com
Accept: text/html
```

It says what you want (GET /accounts), who you’re asking (the Host), and what format you’d like back. The server replies in the same style, with a status line like “200 OK”, some headers, and then the page. That is the whole idea of the layer: agreed wording for requests and replies. Your program usually reaches the network through the operating system’s socket interface, which is the doorway between layer 7 and everything below.

#### Layer 6 - Presentation

The Presentation layer is about representing data so that both ends read it the same way. 

That covers three things. One is serialisation and character encoding, like turning a Python dictionary into JSON and then into UTF-8 bytes, or packing a request into protobuf for gRPC. 
Two is differences between machines, such as byte order: a number can be stored big-endian or little-endian, so the network standardises on big-endian, called network byte order. 
Three is compression and encryption, like gzip and TLS. 

In practice this work is done by libraries inside the application, which is a big reason TCP/IP folds it into the Application layer, and TLS is the classic case that doesn’t fit neatly into one box.

#### Layer 5 - session layer

The Session layer manages a conversation between two programs: opening it, keeping it going, and closing it cleanly. In the OSI design it also handled dialogue control, meaning whose turn it is to talk, and synchronisation with checkpoints, so that a large transfer can resume from the last checkpoint instead of starting from zero.

#### Layer 2 - Data link layer

The Data Link layer moves data between two devices directly connected on the same link, which is one hop. It does four things: framing, which groups bits into frames with clear boundaries; local addressing using MAC addresses; error detection with a checksum called the FCS at the end of each frame; and controlling who may transmit when the medium is shared. Note that we described that layer 1 only cares about bits so , data link layer actually converts a stream of bits on some kind of message. 

The Data Link layer groups bits into frames, with clearly marked starts and ends. The second is addressing on the local link. Who on this link is this frame meant for? That’s the job of the MAC address, a 48-bit hardware address written like a4:5e:60:c1:2b:9f. The first half identifies the manufacturer, and the second half is a number the manufacturer assigns, so the address is meant to be unique to each network card.

A real Ethernet frame is a good thing to see once, because every other layer ends up inside it.

Reading the frame from left to right: the preamble is a fixed pattern that lets the receiver’s hardware lock onto the timing, and then comes the frame itself. The destination and source MAC addresses say who it’s for and who sent it. The Type field says what is inside, so the receiver knows which protocol to hand the payload to (for example, one value means IPv4, another IPv6, another ARP). The payload is the actual cargo, which is the packet from the Network layer above. Its upper size limit of 1500 bytes is the famous MTU, the maximum transmission unit. Finally, the FCS is the checksum (a CRC) that lets the receiver detect damage.

A switch is the typical Layer 2 device, and it learns which MAC address is on which port by watching source addresses, then forwards frames only to the right port, unlike a hub which repeats everything to everyone. The key idea is that a MAC address only matters on one link: at each router the frame is stripped off and a new one is built with new MAC addresses, while the IP addresses inside stay the same from end to end.

#### Layer 1 - Phyiscal layer 

The Physical layer is responsible for moving raw bits as physical signals across a medium: voltage on copper, light pulses in fibre, or radio waves in Wi-Fi. It deals with cables, connectors, network card signalling, repeaters, and hubs. It has no idea what the bits mean; it only cares that a 1 or 0 sent at one end is measured correctly at the other. 

The practical things you worry about here are bandwidth, which is how much the link can carry per second, latency, which is how long a bit takes to arrive, and problems like signal fading with distance and interference. For example, standard Ethernet copper is limited to about 100 metres, and latency has a physical floor, since light in fibre travels at about two thirds of its speed in a vacuum, so Delhi to London can’t be faster than roughly 33 milliseconds one way.

The kinds of things that live at this layer are all physical: cables and connectors (the RJ45 plug on an Ethernet cable), the network card’s signalling chip, repeaters that boost a weak signal, hubs that blindly copy a signal to every port, and the radio hardware in your phone. Each medium has strengths and weaknesses worth knowing.

> [!NOTE] 
> Where does TLS go? In OSI it’s usually placed at Presentation, but it actually runs on top of TCP and beneath HTTP, so in TCP/IP it just sits within the Application layer. It’s one of the cases where the model doesn’t map cleanly.

##### Layer 1 devices (Hubs , Repeater , Moderm)

These devices work with signals and know nothing about addresses. A repeater takes a weakening signal and boosts it so it can travel further. A hub is a repeater with many ports: whatever comes in on one port is blindly copied out of every other port. A modem converts between the digital bits your computer uses and the signal a particular medium carries, such as a phone line or a cable line.

##### Layer 2 devices (Switch, Bridges)

A switch looks at the destination MAC address in each frame and sends it out of only the port where that device lives. It learns this by noting the source MAC of every incoming frame and remembering which port it arrived on. If the destination is unknown or the frame is a broadcast, it floods the frame out of all the other ports. A bridge is the older, simpler cousin of a switch, and a Wi-Fi access point also bridges between wireless clients and the wired network at this layer.

##### Layer 3 Router

A router connects different networks together. It reads the destination IP address in the packet, looks it up in its routing table to find the best next hop, and forwards the packet that way.

A Layer 3 switch is a switch that can also route between VLANs, doing the routing in fast hardware, and it’s common inside data centres and offices.

##### Layer 4 (L4 Load balancer , statefull firewall , NAT)

At layer 4 a device looks at the IP addresses and the TCP or UDP port numbers, and not at the content of the message. A stateful firewall tracks connections, so it can say “this reply belongs to a connection that an inside machine started, so let it through”.

##### Layer 7 (Application layer)

At layer 7 we have L7 Load balancer something which can read the actual contents of package and then route the request. Other tools which work here are - Reverse proxy , API gateway and web application firewall. 
### Firewalls

A firewall is a gatekeeper for the network traffic at the network edge. It looks at the packet and decides if it is allowed to go or not based on the rules and configuration of firewall. The name comes from the physical wall built into buildings to stop a fire spreading from one section to another, and the idea is similar: keep a problem in one area from reaching the others.

A firewall rule is a simple condition plus an action. The condition matches on a few fields of the packet: the source address, the destination address, the protocol (TCP, UDP, ICMP), the source and destination ports, and sometimes the direction (inbound toward the protected machine, or outbound away from it). The action is usually allow or deny. Together, the source address, source port, destination address, destination port and protocol are often called the five-tuple, and it’s essentially the identity of a connection.

A proxy firewall (also called an application gateway) sits in the middle of a conversation and talks to both sides separately, so the client connects to the firewall and the firewall opens a second connection to the server. A web application firewall (WAF) is specialised for HTTP. It understands web requests and looks for the patterns of common web attacks, such as SQL injection, where an attacker slips database commands into a form field, and cross-site scripting. It sits in front of a web application, typically as part of a layer 7 load balancer or a cloud service, and it’s the right tool for protecting a website. It’s not a general-purpose network firewall, though, because it understands only web traffic.

##### Where firewall lives

Firewalls can be placed in different spots - 

- A host-based firewall runs on the machine itself, as iptables or nftables do on Linux, or Windows Defender Firewall does on Windows, and protects just that one machine.
- A network firewall is a separate device or cloud service that protects everything behind it, often at the edge of a network.
- Cloud platforms offer a third form, where the firewall is part of the virtual network and attached to individual virtual machines or network interfaces.
