Process a tree by repeatedly finding a **leaf**, making an **irrevocable local decision** about it, then **deleting** it which exposes new leaves until the tree is consumed. The whole computation flows from the fringe inward toward the root. A leaf touches exactly one edge, so it participates in exactly one constraint. That makes it the _most constrained, least flexible_ node in the tree: its best choice is usually either forced or provably safe to make in isolation. Interior nodes are hard precisely because they couple many decisions together; leaves don't couple anything. So you resolve the easy, forced decisions first and let their consequences ripple inward.

"Commitment" means the decision is **final** you never revisit it. What licenses that is an _exchange argument_: you prove that at least one optimal solution agrees with your greedy leaf-decision, so committing to it can never rule out an optimum. And because a tree minus a leaf is still a tree (no cycles ever appear), the leftover subproblem has identical structure you just recurse.

The mechanical loop:
1. Find a leaf `v` (its single neighbor is `u`).
2. Decide `v`'s fate by a fixed local rule.
3. Commit — and often fix `u`'s fate at the same time.
4. Delete `v` (and possibly `u`); decrement neighbor degrees.
5. Deletions may create new leaves. Repeat until nothing remains.

Note although this technique is mostly usable on trees in some schenarios it can also be used in the graphs. 

The max-independent set problem - Find out the subset of nodes in a graph such that two neightbouring nodes do not come into the set is `NP complete` problem on general graph since vertex cover and max-independent set are duality. However max-independent set problem is solvable on `O(n)` time over the trees. 

The simple algorithm is to move from leaves remove all the leaves first and for each leaf mark its parent as not usable remove it as well. Do it repeatedly. The idea is that for any node either it or its parent can be in set. For the leaf node its optimal to choose leaf instead of its parent. Proof - 

If `parent u` does not comes into the set `S`. We choose leaf however if it does we can simply exchange the leaf for its parent and will atleast as good solution. This concludes the proof.

### Problem

You are given an undirected tree consisting of 𝑛 vertices. An undirected tree is a connected undirected graph with 𝑛−1 edges.

Your task is to add the minimum number of edges in such a way that the length of the shortest path from the vertex 1 to any other vertex is at most 2. Note that you are not allowed to add loops and multiple edges.

### Solution 

So think about a leaf node which is from larger distance than 2 from 1. What we think about it. Obviously `dist=2` puts a constraint on us that either a leaf or its parent needs to be connected directly to the root. This is most important point in these problems to find greedy invariance. Now its obvious that its better to connect to parent. So we move from leaves we push them to queues and then when we get to a node we have multiple options if its a leaf we will be connecting its parent to the root. Meansing not only the childs of this parent but its grand children are now at dist of atmost 2. So what you get is You are given an undirected tree consisting of 𝑛 vertices. An undirected tree is a connected undirected graph with 𝑛−1 edges.

Your task is to add the minimum number of edges in such a way that the length of the shortest path from the vertex 1 to any other vertex is at most 2. Note that you are not allowed to add loops and multiple edges.that we lift up multiple nodes and reduced their depths. Result is pretty amazing we can just work with lowest hanging leaves at any time if thier distance is atmost 2. We know this entire branch is completely done as covered. So we can move up. This kind of logic is quite vital here we maintain the distance invariant cover as each parent is reached and then move up. 

```cpp
void solve() {
    int n;
    cin >> n;
    vector<vi> adj(n);
    f(n - 1){
        int u, v;
        cin >> u >> v;
        u--; v--;
        adj[u].pb(v);
        adj[v].pb(u);
    }

    vi d(n, 0), p(n, -1);
    function<void(int, int)> dfs = [&](int node, int par) {
        for (auto ch : adj[node]) {
            if (ch == par) continue;
            d[ch] = d[node] + 1;
            p[ch] = node;
            dfs(ch, node);
        }
    };

    dfs(0, -1);

    set<pii> q;
    for (int i=0;i<n;i++){
        if(d[i]>2)q.insert({-d[i], i});
    }

    vector<bool> covered(n, false);
    
    for (int i = 0; i < n; i++) {
        if(d[i]<=2)covered[i] = true;
    }

    int ans = 0;

    while(!q.empty()){
        int node =(*q.begin()).S;
        q.erase(q.begin());
        if(covered[node])continue;
        int par = p[node];
        ans++;

        covered[par] = true;
        if (p[par] != -1)covered[p[par]] = true;
        for (auto ch : adj[par])covered[ch] = true;
    }   
    cout << ans;
}
```

### General discussion

Leaf-stripping (a.k.a. peeling, or Kahn's algorithm on trees) is worth slowing down on, because the same mechanic powers a surprising range of "greedy on tree" solutions and the correctness proof is almost always the _same_ exchange argument. 

A leaf has exactly one neighbor. That's the whole reason the technique is safe: a leaf's only interaction with the rest of the tree is a single edge, so whatever decision that edge forces can be resolved _locally_ without knowing anything about the far side of the tree. Once you commit the leaf's decision and delete it, its parent may become a new leaf, and the same argument applies recursively. You're essentially doing a topological order on a tree, from the outside in.

The mechanic stays fixed; what changes is _what you do when you pop a leaf_:

- **Pure peeling / round counting** — remove all current leaves, repeat. You're computing each node's "distance from the boundary." Implementation is a BFS from all leaves simultaneously.
- **Greedy commit** — when a leaf's constraint can no longer be deferred, make an irreversible choice, usually about the _parent_.
- **Accumulation** — push a cost/count/state up to the parent as you delete (children hand their surplus operations upward).
- **Priority peeling** — instead of any leaf, always pop the _extremal_ leaf by some key (heap-driven). This is the trickiest variant because the exchange argument has to justify the ordering, not just the local decision. Used earlier

```
deg[v] = adjacency size
q = all v with deg[v] == 1

```

A path graph collapses from _both_ ends, and the final one or two central nodes can hit degree 0 (not 1) decide up front whether your problem wants those treated as leaves or as a separate base case. Easy off-by-one to miss.
