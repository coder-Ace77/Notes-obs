Routers allow you to split your API into smaller, logical building blocks. Routers can organise the logically similar endpoints. They are specifically used to prefix all the end points described. 

To do that we import `APIRouter` from `fastapi`. Then to describe router we need to define two important arguments. What is the prefix we need to be added and secondly tags we need to add. 

Then instead of using app directly we use `@router` which logically works mostly like `@app` but with api path prefixed. 

```python
from fastapi import APIRouter

# Define the router
router = APIRouter(
    prefix="/users",
    tags=["users"],
    responses={404: {"description": "Not found"}},
)

@router.get("/")
async def read_users():
    return [{"username": "Rick"}, {"username": "Morty"}]

@router.get("/{username}")
async def read_user(username: str):
    return {"username": username}
```

Finally we need to import the routers. we just import the `router` object into the `app` object using `include_router` option and we are good to go. 

```python
from fastapi import FastAPI
from .routers import users

app = FastAPI()

# This merges the users routes into the main app
app.include_router(users.router)

@app.get("/")
async def root():
    return {"message": "Hello World"}
```

| **Parameter**      | **Description**                                                                                |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| **`prefix`**       | Prepends a string to all paths (e.g., `/users` makes the route `/users/` instead of just `/`). |
| **`tags`**         | Groups these routes in the automatic Swagger UI documentation.                                 |
| **`dependencies`** | Applies specific security or logic (like a global API key) to _every_ route in that router.    |
| **`responses`**    | Defines default error responses for the entire group.                                          |
