Transformers are the class of neural networks that introduced parallelization using attention mechanisms. There are broadly three kinds of transformers - 

- GPT-like (also called _auto-regressive_ Transformer models)
- BERT-like (also called _auto-encoding_ Transformer models)
- T5-like (also called _sequence-to-sequence_ Transformer models)

A transformer is first trained as the language model meaning it is trained on large amount of texts in self supervised fashion. Self-supervised learning is a type of training in which the objective is automatically computed from the inputs of the model. 

This type of model develops a statistical understanding of the language it has been trained on, but it’s less useful for specific practical tasks. Because of this, the general pretrained model then goes through a process called _transfer learning_ or _fine-tuning_. During this process, the model is fine-tuned in a supervised way  that is, using human-annotated labels  on a given task.

An example of a task is predicting the next word in a sentence having read the _n_ previous words. This is called _causal language modeling_ because the output depends on the past and present inputs, but not the future ones. 

```
My name is [PREDICT]
```

Another example is _masked language modeling_, in which the model predicts a masked word in the sentence.

```
My [PREDICT] is Albert.
```

_Pretraining_ is the act of training a model from scratch: the weights are randomly initialized, and the training starts without any prior knowledge. This pretraining is usually done on very large amounts of data. Therefore, it requires a very large corpus of data, and training can take up to several weeks. _Fine-tuning_, on the other hand, is the training done **after** a model has been pretrained. To perform fine-tuning, you first acquire a pretrained language model, then perform additional training with a dataset specific to your task. 

```
[Raw model] --- [Pretrained] -- [Fined tuned model]
```

## Architecture of transformer

The main architecture model of transformer has two parts - 

- Encoder - The encoder receives an input and builds a representation of it (its features). This means that the model is optimized to acquire understanding from the input.
- Decoder - The decoder uses the encoder’s representation (features) along with other inputs to generate a target sequence. This means that the model is optimized for generating outputs.

![[Pasted image 20260219132111.png]]

Each of these parts can be used independently, depending on the task:

**Encoder-only models**: Good for tasks that require understanding of the input, such as sentence classification and named entity recognition.
**Decoder-only models**: Good for generative tasks such as text generation.
**Encoder-decoder models** or **sequence-to-sequence models**: Good for generative tasks that require an input, such as translation or summarization.

#### What attention actually is?

A transformer has two phases -

- Communication phase - This is encompased of multihead attention
- Computation stage - This is later stage of multilayer perceptron. Basically final layer of neural nets.

Computation stage is simpler what we need is communication phase. In communication  phase, the model doesn't create "new" information; instead, it **moves** existing information between tokens. Think of it as a boardroom meeting where every word in a sentence "talks" to every other word to gain context.

To communicate, each token is transformed into three vectors:

- **Query (Q):** "What am I looking for?"
- **Key (K):** "What information do I contain?"
- **Value (V):** "If I am relevant, what should the others know about me?"

The "communication" happens via the **Attention Score**. The model calculates the dot product of Q and K to determine how much attention token A should pay to token B.

Instead of having just one conversation, the model splits the communication into multiple "heads."
- **Head 1** might focus on **Grammar** (e.g., matching a verb to its subject).
- **Head 2** might focus on **Entity Relations** (e.g., connecting "He" to "Adil").
- **Head 3** might focus on **Local Context** (e.g., looking at the words immediately next to it).

Now to implement this - Attention is consist of multiple nodes each representing a token and they can communicate with each other. This actually forms a directed graph where a node can communicate to some other node. In addtion to the vector of a node. A node also has key , query and value all are obtained by linear transformation of node vector called `data`. 

Now the node will have access to matrix `key,query and value` and these matrices will be multiplied with the data to get corresponding vectors. 

```python
class Node:
	# vector
	self.data = np.random.randn(20)
	
	# weigths governing how will nodes interact
	self.wkey = np.random.randn(20,20)
	self.wquery = np.random.randn(20,20)
	self.wvalue = np.random.randn(20,20)
	
	def key(self):
		# what i have
		return self.wkey@self.data
	def query(self):
		# what i am looking for
		return self.wquery@self.data
	def value(self):
		# what i broadcast to others
		return self.wvalue@self.data
```

## Architecture of transformer

A general transformer is made of encoder and decoder. In encoder we are trying to find and grasp the idea of the sentence at hand. In decoder we try to translate so in general decoder part of machine translation transformer decoder will be generating the given some tokens generate next one. 

### Multiheaded attention

Now with single attention modelled as the nodes in graphs communicating with each other. In multiheaded attention we have multiple heads working independent of each other. The way we work is by dividing the actual token vector into multiple smaller onces. In reality if token is 128 units long and we have 8 heads then each head will have only subpart of token which is 128/8. With multihead we can get to evolve different sets of `(K,Q,V)` meaning each head can work on the different set of attributes of language for example `verb` or `noun`. This means each head will come forward with the specific set of data. This is effectively communication part. 

The communication part differs in encoder and decoder considerabilty- 

- In encoder each node has access to every other node in the graph meaning we can exchange the informations with any other node.
- In decoder each node has access to the nodes which correspond to the token comming before itself. This is becuase we can not allow the decoder to look into the next token which actually its trying to predict. 

Now once multiheaded data is computed we combine them using next layer which usually is 2 layer mlp(multi layer perceptron). This is combine phase. So after this phase we again go back to the original dimentional token vectors. 

These two layers multiheaded attention layer and compute layer form actually one `layer` of encoder or decoder.  Multiple such layers combine in series to form one encoder or decoder.

Now when the `key,query and value` all belong to the same set of nodes we call it self attentions. This is the kind of attention working `95%` of the times. One notable exception is cross attention which is needed to go from the final layer of encoder and come into the some layer of decoder. This is done so that decoder has the context of the information held by the encoder. Here the multiheaded layer will have key and values comming from encoder layer but the query from decoder part. 

Finally the final layer of decoder is lineared and softmax to the dimention of token in vocab this softmax gives out the probability of the next word.

### Transformers trainings

Most modern Transformers (decoders) use **Self-Supervised Learning**. We feed them billions of sentences and hide the next word. The model’s job is to predict that hidden word. This is called **Autoregressive Language Modeling**. During training, we don't wait for the model to generate a full sentence. Instead, we use a technique called **Teacher Forcing**. Even if the model predicts the wrong word for "The cat sat on the...", we still feed the _correct_ ground-truth word ("mat") into the next step. This prevents errors from compounding early in training.

We use the **Adam Optimizer**, often paired with a **Learning Rate Warmup**. At the start, we keep the learning rate very low so the model doesn't "explode" with random weights, then gradually increase it once the gradients stabilize.

Learning types 

| **Type**      | **Description**                                                                                            | **Example Prompt**                                                                            |
| ------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **Zero-Shot** | You give the model an instruction with **no examples**. It relies entirely on its pre-trained "knowledge." | "Translate the following sentence to French: 'Where is the library?'"                         |
| **One-Shot**  | You provide **one example** to show the model the pattern or format you want.                              | "Input: 'Happy' -> Output: 'Positive'. Input: 'Sad' -> Output: ?"                             |
| **Few-Shot**  | You provide a **handful of examples** (usually 2–10). This is best for complex or niche tasks.             | "I love this: Positive. I hate this: Negative. This is okay: Neutral. The weather is nice: ?" |
These terms describe how much "guidance" or context you give a pre-trained model to perform a new task **without** retraining its weights. This is often called **In-Context Learning**. These are prompting techniques used at the run time not when the model is being trained.
