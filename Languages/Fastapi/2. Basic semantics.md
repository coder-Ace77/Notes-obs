### Hello world program

Now that we have the env set up we return simple `Hello world` get request. 

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
async def root():
    return {"msg":"Hello wrold"}
```

`FastAPI` is the actual class which returns the instance of `FastAPI` class and is the main entry point for creation of all apis. 

The `@app.get("/")` tells **FastAPI** that the function right below is in charge of handling requests that go to:
- the path `/`
- using a `get` operation

`@something` syntax in python is called decorator and decorator takes the function below and does something with it. Here the fastapi will do something with the `root` function. Other decorators are - 

`@app.post()` etc. 

### Anatomy of a http call

Http request is the call from the client side having the data it wants from the server. Its basically kind of communication. An http request has following components - 

- **Method (Verb):** Defines the action. Common ones include `GET` (fetch data), `POST` (send data), `PUT` (replace data), and `DELETE`.
    
- **Path (URI):** The specific location on the server (e.g., `/api/v1/users`).
    
- **Headers:** Metadata about the request, such as `Content-Type: application/json` or `Authorization: Bearer <token>`.
    
- **Body (Payload):** The actual data being sent to the server (used in POST, PUT, and PATCH).


Once the server processes your request, it sends back a **Response**. This tells the client if the mission was successful and provides any requested data.

- **Status Code:** A three-digit number indicating the result.
    
- **Headers:** Info about the server and the data being sent (e.g., `Set-Cookie` or `Server: nginx`).
    
- **Body:** The content you see, like an HTML page, an image, or JSON data.

Http status codes - 

| **Range** | **Category**     | **Meaning**                                             | **Example**                         |
| --------- | ---------------- | ------------------------------------------------------- | ----------------------------------- |
| **1xx**   | Informational    | Request received, continuing process.                   | 101 Switching Protocols             |
| **2xx**   | **Success**      | The action was successfully received.                   | **200 OK**, 201 Created             |
| **3xx**   | Redirection      | Further action needed to complete.                      | 301 Moved Permanently               |
| **4xx**   | **Client Error** | The request contains bad syntax or cannot be fulfilled. | **404 Not Found**, 401 Unauthorized |
| **5xx**   | **Server Error** | The server failed to fulfill a valid request.           | **500 Internal Server Error**       |

#### Predefined values 

If you have a _path operation_ that receives a _path parameter_, but you want the possible valid _path parameter_ values to be predefined, you can use a standard Python `Enum`.

```python
from enum import Enum

from fastapi import FastAPI


class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"


app = FastAPI()


@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):
    if model_name is ModelName.alexnet:
        return {"model_name": model_name, "message": "Deep Learning FTW!"}

    if model_name.value == "lenet":
        return {"model_name": model_name, "message": "LeCNN all the images"}

    return {"model_name": model_name, "message": "Have some residuals"}
```

### Query parameters

In web development, **Query Parameters** are a set of key-value pairs that appear at the end of a URL, separated from the main path by a question mark (`?`). 

Notable example is -`https://example.com/items/5?skip=20&limit=10`. `?` defines that query paramter has started. We define the key value pairs `key=val`. Finally to define multiple key value pairs separated by `&`. 

When you declare other function parameters that are not part of the path parameters, they are automatically interpreted as "query" parameters. 

```python
from fastapi import FastAPI

app = FastAPI()

fake_items_db = [{"item_name": "Foo"}, {"item_name": "Bar"}, {"item_name": "Baz"}]

@app.get("/items/")
async def read_item(skip: int = 0, limit: int = 10):
    return fake_items_db[skip : skip + limit]
```

Example of query  - `http://127.0.0.1:8000/items/?skip=0&limit=10` In above example we have default values as well. 

The same way, you can declare optional query parameters, by setting their default to `None`:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/items/{item_id}")
async def read_item(item_id: str, q: str | None = None):
    if q:
        return {"item_id": item_id, "q": q}
    return {"item_id": item_id}
```

You can declare multiple path parameters and query parameters at the same time, **FastAPI** knows which is which.



### About normal and async functions

Since FastAPI is built on top of Starlette and uses an "Asynchronous Server Gateway Interface" (ASGI) like Uvicorn, it handles these two types of functions very differently.

With async functions - it will use the single threaded event loop. If the code reaches an `await` line, the loop pauses that specific function, moves on to the next person's request, and comes back only when the data is ready. This is really good for `I/O` bound task. 

If you define a normal `def` function, FastAPI assumes it is **blocking**. If it ran this on the main Event Loop, the entire server would freeze until that function finished. To prevent a freeze, FastAPI automatically runs regular `def` functions in a **separate thread pool**. While this keeps your server responsive, creating threads has a higher "overhead" (uses more memory and CPU) than the event loop. So these functions are best for heavy mathematical operations. 

Note - if you are using a library that is NOT async (like the standard `requests` library or `pymongo`): **Use regular `def`**. If you use `async def` with a blocking library, you will accidentally freeze your entire server for every user.

### CORS 

CORS (cross origin resource sharing) is a browser led mechanismthat restricts the web page from making the request to different domain than one that served the page. Same origin policy is a rule followed by the browsers that restricts the `script` on `site-A.com` to access the data on `site-B.com`. Cors works through http headers. When your browser makes a cross-origin request, it adds an `Origin` header. The server then responds with headers that tell the browser whether that origin is allowed. 

For basic actions (like a standard `GET` or `POST` with certain content types), the browser just sends the request adding the header `Origin` which contains the domain of the website it allows.  

1. **Client:** "Hey API, I'm `my-app.com`. Can I have this data?"
2. **Server:** Sends the data back with a header: `Access-Control-Allow-Origin: my-app.com`.
3. **Browser:** Checks the header. If it matches, it lets your code see the data. If not, it hides the data from you.

For "riskier" requests—like those using `PUT`, `DELETE`, or custom JSON headers—the browser doesn't want to risk sending the data without checking the rules first. It sends a **Preflight request** using the `OPTIONS` method.

1. **Preflight:** "Yo server, I’m about to send a `DELETE` request from `my-app.com`. Is that cool?"
2. **Response:** "Yeah, I allow `DELETE` from `my-app.com`."
3. **Actual Request:** Only now does the browser send the real `DELETE` request.

Headers send by browsers are - 

- Origin - The domain where request is comming from.
- Access-Control-Request-Method - Used in preflight to tell the server "I want to use a `DELETE` request."
- **`Access-Control-Request-Headers`**: Used in preflight to say "I'm also going to send a custom `X-Auth-Token` header."

The headers that can be send back by the response are - 

| **Header**                             | **Description**                                                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **`Access-Control-Allow-Origin`**      | Specifies which domains are allowed. Can be a specific URL or `*` (wildcard, though dangerous with credentials).             |
| **`Access-Control-Allow-Methods`**     | A list of permitted HTTP methods (GET, POST, PUT, etc.).                                                                     |
| **`Access-Control-Allow-Headers`**     | A list of which custom headers the client is allowed to send.                                                                |
| **`Access-Control-Allow-Credentials`** | Tells the browser whether it’s okay to send cookies or auth headers with the request.                                        |
| **`Access-Control-Max-Age`**           | Tells the browser how long (in seconds) it can "cache" the preflight permission so it doesn't have to ask every single time. |

However when these is a `api-server` or `loadbalancer` in between then there can be many ways to handle 

- If middleman is transparent then it will take the request as it is and send request to the backend and to and forth. In this case backend needs to handle and allow it. 
- Preflight - Sometimes loadbalancers need to confiugre the preflight to intercept and send back the response based on their request. 


```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

origins = [
    "http://localhost.tiangolo.com",
    "https://localhost.tiangolo.com",
    "http://localhost",
    "http://localhost:8080",
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


@app.get("/")
async def main():
    return {"message": "Hello World"}
```

We usually add the cors middleware.
