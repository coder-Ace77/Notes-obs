In Gin, the **Handler** is the "brain" of your route. It is any function that matches the  `gin.HandlerFunc` signature: `func(*gin.Context)`. Therefore each handler function must have this `*gin.Context` as input paramter. It is a **wrapper** around the standard Go `http.ResponseWriter` and `*http.Request`. And contains almost all data about the request and response. 

**What it manages technically:**
- **Request Encapsulation:** It provides methods to extract data from the `*http.Request` without manually parsing strings.
- **Response Abstraction:** It buffers the response and allows you to write JSON, HTML, or XML with a single method call.
- **Metadata Storage:** It has a `Keys` map (`map[string]any`) that allows you to pass data between middleware (e.g., an `Auth` middleware can store a `userId` in the context for the final handler to use).
- **Flow Control:** It manages the execution flow via `.Next()` (move to next middleware) and `.Abort()` (stop the chain immediately).

When handling a GET request, your primary goal is to retrieve data from the URL. There are three main ways to do this in Gin:

These are parts of the URL path itself, defined with a colon (`:`).

- **Route:** `/user/:name`
- **URL:** `/user/satoshi`

```go
router.GET("/user/:name", func(c *gin.Context) {
    // Extracting the path parameter
    name := c.Param("name") 
    c.String(200, "Hello %s", name)
})
```

Note that in the router.Get we indicate that paramter can have something like id. 

Then we have query params - These are the key-value pairs after the `?` in a URL.

```go
router.GET("/search", func(c *gin.Context) {
    // Get parameter, or use a default if it doesn't exist
    firstname := c.DefaultQuery("firstname", "Guest")
    
    // Get parameter (returns empty string if missing)
    lastname := c.Query("lastname") 

    c.JSON(200, gin.H{
        "first": firstname,
        "last":  lastname,
    })
})
```

- `c.DefaultQuery("key", "default")` returns the value, or the specified **default value** if the key is not present.
- `c.Query("key")` returns empty string if query not present. 

Instead of manually grabbing strings, you can "bind" the entire request into a Go struct. Gin uses tags to map the URL fields to your struct fields.

```go
type Filter struct {
    Page  int    `form:"page"`
    Limit int    `form:"limit"`
    Sort  string `form:"sort"`
}

router.GET("/products", func(c *gin.Context) {
    var f Filter
    // ShouldBindQuery checks the query string and parses types (e.g., string to int)
    if err := c.ShouldBindQuery(&f); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }
    
    c.JSON(200, f)
})
```

Once your logic is done, you use the context to send the response back. Gin handles the `Content-Type` header automatically based on the method you call.

| **Method**                  | **Use Case**                                               |
| --------------------------- | ---------------------------------------------------------- |
| `c.JSON(code, obj)`         | Serializes a map or struct to JSON (most common for APIs). |
| `c.String(code, fmt, args)` | Sends plain text.                                          |
| `c.HTML(code, name, obj)`   | Renders an HTML template.                                  |
| `c.File(path)`              | Streams a local file to the client.                        |
| `c.AbortWithStatus(code)`   | Stops the request and sends a specific error code.         |

When a GET request hits your server:

1. **Gin Engine** matches the path.
2. It creates a new **`gin.Context`** (recycling from a pool for performance).
3. It passes that context through **Middleware** (Logger/Recovery).
4. It lands in your **Handler function**.
5. You use **`c.Param`** or **`c.Query`** to read data.
6. You call **`c.JSON`** (or similar), which writes to the response stream.
7. The context is "put back" into the pool for the next request.

Now we also have some other ways to send response even if we need to send json such `IndentJson` etc. 

### Body

While GET requests typically rely on URL parameters, **POST, PUT, and PATCH** requests use the **Request Body** to send complex data (like JSON objects or file uploads).In Gin, accessing the body is handled through a process called **Binding**

If you just want the "raw" bytes of the request body (e.g., for logging or custom parsing), you can use:

```go
data, err := c.GetRawData()
```

Note: Once you read the body this way, the stream is consumed. You usually shouldn't do this if you plan to use Gin's automatic binding later.

The most efficient way to access the body is to map it directly to a Go **struct** using tags. Gin uses the `binding` package under the hood to handle this.

```go
type RegisterRequest struct {
    // "json" tag matches the key in the incoming JSON
    // "binding:'required'" tells Gin to return an error if the field is missing
    Username string `json:"user" binding:"required"`
    Email    string `json:"email" binding:"required,email"`
    Password string `json:"password" binding:"required"`
}

func RegisterHandler(c *gin.Context) {
    var body RegisterRequest

    // ShouldBindJSON reads c.Request.Body and parses it based on the Content-Type
    if err := c.ShouldBindJSON(&body); err != nil {
        c.JSON(400, gin.H{"error": "Invalid data: " + err.Error()})
        return
    }

    // Now you can access the data via the struct
    fmt.Println(body.Username)
    c.JSON(200, gin.H{"status": "success"})
}
```

Note the `c.ShouldBindJSON` takes just one pointer the struct we want to bind to and that's it. 

Gin is smart enough to handle different `Content-Type` headers using different binding methods:

| **Method**               | **Content-Type Header**                              |
| ------------------------ | ---------------------------------------------------- |
| `c.ShouldBindJSON(&obj)` | `application/json`                                   |
| `c.ShouldBindXML(&obj)`  | `application/xml`                                    |
| `c.ShouldBindYAML(&obj)` | `application/x-yaml`                                 |
| `c.ShouldBind(&obj)`     | **Automatic:** Guesses based on Content-Type header. |

If you are building a traditional website where a `<form>` submits data, you have two options:

First one is to use individual fields

```go
user := c.PostForm("username")
pass := c.DefaultPostForm("password", "secret123")
```

Use the `form` tag in your struct instead of `json`.

```go
type LoginForm struct {
    User string `form:"user"`
    Pass string `form:"password"`
}

// In handler:
var form LoginForm
c.ShouldBind(&form) // Works for both JSON and Form-urlencoded
```

you will see two versions of every binding function. It is critical to know the difference:

1. **`c.ShouldBind...()`**:
    - **Returns an error** if binding fails.
    - **Best Practice:** You catch the error and decide how to handle it (usually returning a 400).
2. **`c.Bind...()`**:
    - If binding fails, it **automatically calls `c.AbortWithError(400, ...)`** and writes a 400 status to the response.
    - Only use this if you want Gin to take over the error response entirely.

By default, the HTTP request body in Go is a stream that can only be read **once**. If you have a middleware that reads the body and then your handler tries to read it again, the handler will get an "EOF" error.

Or better yet, bind the data into a struct once in a middleware and store that struct in the `gin.Context` using `c.Set("body", myStruct)`.

Sometimes you need to receive a set of key-value pairs where the keys are not known in advance — for example, dynamic filters or user-defined metadata. Gin provides `c.QueryMap` and `c.PostFormMap` to parse bracket-notation parameters (like `ids[a]=1234`) into a `map[string]string`.

```go
router.POST("/post", func(c *gin.Context) {
    ids := c.QueryMap("ids")
    names := c.PostFormMap("names")

    fmt.Printf("ids: %v; names: %v\n", ids, names)
    c.JSON(http.StatusOK, gin.H{
      "ids":   ids,
      "names": names,
    })
  })
```
