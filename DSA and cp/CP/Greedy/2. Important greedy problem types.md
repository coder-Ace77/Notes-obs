### Interval problems

In these problems we are given a set of intervals and we are required to solve the problem for certain metric to be calculated. 

Now in interval problems we are mostly required to asked about three main questions.

- Coverage - What is the minimum numbers of intervals to cover a range.
- Piercing  - What is the min number of points to stab all the intervals.
- Selection - What is max number of overlapping intervals I can keep.

Coverage - Jump game 2 - In this problem if we are at the given position i we can jump at most `nums[i]` positions. It is quaranteed that we can always reach end. What is the minimum number of jumps to reach end. 

The idea is to keep two things curr_end which is the fartest index reachable with the current number of jumps. and `fartest` which states the fartest index taking one more jump. Think in terms of bfs or search we move jump by jump. Say we are at some `curr_end` and want to reach to the `fartest`.  Note that `curr_end` is actually fixed in the previous jump not current one. Which means if start the search for next fartest we can move from prev curr_end to new curr_end. And that's it. 

```cpp
int jump=0;
int fartest = 0;
int curr_end = 0;

for(int i=0;i<n-1;i++){
	fartest = max(fartest,i+nums[i]);
	if(i==curr_end){
		jump++;
		curr_end=fartest;
	}
}

return jump;
```

Piercing - Here we need to pick up certain points so atleast one point of every interval is picked. 

From here we start with the true greedy problems. Most of the interval problems can be solved by simplyn sorting. Now once sorted based on start of intervals or end of intervals. We can simply apply some greedy strategy. For example here think about the intervals. What should the first optimal point. Clearly first interval (which ends first) needs to be covered so we can pick the ending point of first interval. And then remove all the next intervals which are covered and move forward again. To prove it mathematically we can look at the exchange argument after sorting based on the end. It is clear that our strategy is correct. 

Selection - Pick the maximum possible intervals such that no two intervals have common points. 

Again we observe that interval to end first should be picked first reason being its chances are strictly minimal with the collision possibility of any other interval. This can also be proved by the exchange argument of the intervals. Had we choosen any other interval other than ending first we could stretched more towards right and which could have been not that good. 

Merge intervals - Here given some intervals we need to merge overlapping intervals. 

The idea again is sort but here we need to sort according to the start not end. Reason being think about any intermediate step say last interval ended at `x` then if current intervals start point is ahead of `x` then we can say next interval has to be started otherwise we need to merge. So given we had merged some previous intervals we actually need to be able to find the first interal not merged till now. 

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& v) {
        sort(v.begin(),v.end());
        vector<vector<int>> ans;
        for(auto x:v){
            if(ans.size()==0){
                ans.push_back(x);
            }
            else{
                if(ans.back()[1]>=x[0]){
                    ans.back()[0] = min(ans.back()[0],x[0]);
                    ans.back()[1] = max(ans.back()[1],x[1]);
                }
                else{
                    ans.push_back(x);
                }
            }

        }
        return ans;
    }
};
```
