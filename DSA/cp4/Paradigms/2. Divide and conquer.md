In divide and conquer technique we first divide our problem into smaller set of problems each of which are more easily solvable. Then we solve each of them and then finally find out the answer by combining.

- Divide
- Solve sub problems
- Combine to solve bigger one

OG strategy of this paradigm is binary search. And the OG problem it solves is the search in the static sorted array. However true power of binary search is assumed when we see that it can be used to solve the problems with 

- Monotonic implicit sequences
- Implicit arrays
- Bianry search over non linear data structures.

#### Tree problem 

Given a rooted tree with values increasing from root to leaves. You need to answer the queries -- `q(v,P)` = `What is the first node from root to v that is atleast P`

Idea is not to answer queries one by one rather store them. Now when we reach a vertex we keep the entire path with us on which we can do the binary search. This solves problem in `O(qlogn)`

#### Binary search on answer

Some problems which have very easy simulation can also be solved using the binary search on answer technique where what we do is to simulate the problem given we have some quantity to start at. We mostly define a `can(x)` function which defines weather simulation can be done with atmost x quantity or not if yes we reduce x else we increase it. 

Sometimes if answer is req to be a decimal number instead of solving it using standard binary search we try to iterate for some constant times this removes changes of infinite loop.

```cpp
double lo = 0.0, hi = 10000.0;
for (int i = 0; i < 50; ++i) {
	double mid = (lo+hi) / 2.0;
	can(mid) ? hi = mid : lo = mid;
}
```

#### Ternary search

A **unimodal function** is a function that has exactly one local maximum (or one local minimum) and is monotonic on either side of that extremum it strictly increases up to a single peak (or decreases down to a single valley), then strictly moves the other way after it. There's no oscillation, no multiple peaks/valleys.

Ternary search is a divide-and-conquer technique to find the extremum (max or min) of a **unimodal function** in O(log₃ n) or more precisely O(log(3/2) n) time, without checking every point.

Since the function has exactly one peak (or valley), at any two points inside the search range, you can compare their values and immediately discard **one third** of the range because whichever side is "worse" cannot contain the extremum.

Given range `[lo, hi]`:
1. Pick two interior points that split the range into thirds:

```
m1 = lo + (hi - lo) / 3
m2 = hi - (hi - lo) / 3
```

2. Compare `f(m1)` and `f(m2)`
3. **If f(m1) < f(m2):** the peak cannot lie in `[lo, m1]`, because the function is strictly increasing up to the peak — if the peak were in `[lo, m1]`, then by unimodality f(m1) would have to be ≥ f(m2) (since m2 is further past a supposed peak). So discard the left third → `lo = m1`
4. **If f(m1) > f(m2):** symmetric argument discard the right third → `hi = m2`.
5. **If equal:** the peak lies between m1 and m2 (or at one of them) you can shrink to `[m1, m2]`.
6. Repeat until `hi - lo` is smaller than your precision/tolerance (real-valued) or a small constant (integer-valued).

Note that we can merge arg of 4 and 5 to be `f(m1)>=f(m2)`. 

Code for maxima

```cpp
double ternarySearch(double lo, double hi, function<double(double)> f) {
    for (int iter = 0; iter < 100; iter++) {  // ~100 iters gives near machine precision
        double m1 = lo + (hi - lo) / 3;
        double m2 = hi - (hi - lo) / 3;
        if (f(m1) < f(m2))
            lo = m1;
        else
            hi = m2;
    }
    return (lo + hi) / 2;  // x-coordinate of the extremum
}
```
