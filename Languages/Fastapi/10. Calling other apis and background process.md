### Calling 

Earlier we used to have request package for http calls they were synchronous but now we use the `httpx` which is ayncronous. 

```python
from fastapi import FastAPI, HTTPException
import httpx

app = FastAPI()

@app.get("/github-profile/{username}")
async def get_github_profile(username: str):
    # We use an async context manager to ensure the connection closes properly
    async with httpx.AsyncClient() as client:
        try:
            # Python "delegates" the request to GitHub here
            response = await client.get(f"https://api.github.com/users/{username}")
            
            # If GitHub returns a 404, we pass that error to our user
            response.raise_for_status()
            
            data = response.json()
            return {
                "name": data.get("name"),
                "company": data.get("company"),
                "followers": data.get("followers")
            }
        except httpx.HTTPStatusError as exc:
            raise HTTPException(status_code=exc.response.status_code, detail="User not found on GitHub")
```

### Background process

First one is background tasks which are kind of fire and forget. 

```python
from fastapi import FastAPI, BackgroundTasks

app = FastAPI()

def send_welcome_email(email: str):
    print(f"Sending welcome email to {email}")
    # Code to send email goes here

@app.post("/signup")
async def signup(email: str, background_tasks: BackgroundTasks):
    # 1. We hand the function and its arguments to FastAPI
    background_tasks.add_task(send_welcome_email, email)
    
    # 2. The user gets this response instantly. The email sends AFTER this.
    return {"message": "User created! Welcome email is on the way."}
```

You just directly call `add_task` first passing function name and then the params.

#### API scheduler

If you need to run tasks on a strict schedule (like a cron job) without setting up entirely separate servers, **APScheduler** is the standard tool.

**Best for:** Daily database cleanups, hourly cache refreshes, or running reports at midnight. **The Catch:** If you run multiple instances of your API (like multiple Docker containers), the scheduler will run on _every_ container, meaning your task might run three times instead of once unless you configure a shared database lock.

```python
from fastapi import FastAPI
from apscheduler.schedulers.background import BackgroundScheduler

app = FastAPI()
scheduler = BackgroundScheduler()

def daily_cleanup():
    print("Running midnight database cleanup...")

# Start the scheduler when the app starts
@app.on_event("startup")
def start_scheduler():
    # Run every day at midnight
    scheduler.add_job(daily_cleanup, 'cron', hour=0, minute=0)
    scheduler.start()
```

When your application grows and tasks become mission-critical, you cannot rely on in-memory tasks. You need a **Distributed Task Queue**.

**How it works:**

1. Your API doesn't do the work. It packages the instructions into a message and sends it to a **Broker** (usually Redis or RabbitMQ).
2. The API responds to the user instantly.
3. Completely separate servers, called **Workers**, constantly monitor the broker. They grab the message and execute the heavy task.
