Dependency injection is a design pattern where a piece of code asks for the things it needs to work rather than creating them by themselves. 

In the context of a web API, a **dependency** is any logic or data that your endpoint needs to function. Common examples include:

- Database connections or sessions.
- Security and authentication (e.g., getting the current user).
- Configuration settings.
- Query parameter validation logic.

FastAPI uses a special function called `Depends()` to declare dependencies. When FastAPI sees `Depends(your_function)`, it executes `your_function` first and passes the result into your endpoint.

We can pass the paramter to the dependency function which will be comming from the requests as either path paramter or entire requests. whatever will the paramter of the dependent function can be passed to the dependency function. 

#### Class dependencies

This is the most common way to "parameterize" a dependency. When you use a class, you can use its `__init__` method to define the parameters.

```python
from fastapi import FastAPI, Depends

app = FastAPI()

class FilterParams:
    def __init__(self, q: str | None = None, skip: int = 0, limit: int = 100):
        self.q = q
        self.skip = skip
        self.limit = limit

@app.get("/items/")
# FastAPI instantiates the class and fills the __init__ arguments from the request
async def read_items(params: FilterParams = Depends(FilterParams)):
    return params
```

We can also omit the type in Depends.

```python
from fastapi import FastAPI, Depends

app = FastAPI()

class FilterParams:
    def __init__(self, q: str | None = None, skip: int = 0, limit: int = 100):
        self.q = q
        self.skip = skip
        self.limit = limit

@app.get("/items/")
# FastAPI instantiates the class and fills the __init__ arguments from the request
async def read_items(params: FilterParams = Depends()):
    return params
```

### Multilevel dependencies

Dependencies can also have dependencies. In FastAPI, **multilevel dependencies** (also known as a "dependency graph" or "nested dependencies") occur when a dependency function itself requires another dependency.

FastAPI is designed to handle this automatically. It traverses the tree of dependencies, resolves them in the correct order, and ensures that if multiple parts of your code require the same dependency, it is (usually) calculated only once per request.

Imagine a security flow where:

1. **Level 1:** A function gets a raw token from the request headers.
2. **Level 2:** A function takes that token and verifies it to return a User object.
3. **Level 3:** Your actual endpoint takes that User object to perform an action.

Example 

```python
from fastapi import FastAPI, Depends, HTTPException, Header

app = FastAPI()

# --- Level 1: Extract API Key ---
def get_api_key(x_api_key: str = Header(...)):
    if not x_api_key:
        raise HTTPException(status_code=403, detail="API Key missing")
    return x_api_key

# --- Level 2: Get User from API Key ---
# This dependency "Depends" on the Level 1 function
def get_current_user(api_key: str = Depends(get_api_key)):
    # In a real app, you'd look this up in a database
    if api_key == "secret-admin-key":
        return {"username": "admin", "is_admin": True}
    return {"username": "guest", "is_admin": False}

# --- Level 3: Check for Admin Status ---
# This dependency "Depends" on the Level 2 function
def verify_admin(user: dict = Depends(get_current_user)):
    if not user.get("is_admin"):
        raise HTTPException(status_code=403, detail="Admin rights required")
    return user

# --- The Endpoint ---
@app.get("/admin/dashboard")
async def admin_dashboard(admin: dict = Depends(verify_admin)):
    return {"message": f"Welcome, {admin['username']}. Access granted."}
```

Fianlly we can have global dependencies which are the dependencies. While dependencies are usually added to specific **path operations** (functions), FastAPI allows you to apply them to the **entire application** at once. These are called **Global Dependencies**.

When you define a global dependency, it runs for every single request that hits your API, regardless of which endpoint is being called.

You define global dependencies when you initialize the `FastAPI` class by passing a list to the `dependencies` parameter.

```python
from fastapi import FastAPI, Header, HTTPException, Depends

# 1. Define the logic
async def verify_header(x_token: str = Header(...)):
    if x_token != "secret-token":
        raise HTTPException(status_code=400, detail="X-Token header invalid")

# 2. Apply it globally
app = FastAPI(dependencies=[Depends(verify_header)])

@app.get("/items/")
async def read_items():
    return [{"item": "Portal Gun"}, {"item": "Plumbus"}]

@app.get("/users/")
async def read_users():
    return [{"username": "Rick"}, {"username": "Morty"}]
```
