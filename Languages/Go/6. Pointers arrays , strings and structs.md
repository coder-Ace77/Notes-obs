Go has pointers. A pointer holds the memory address of a value. The type `*T` is a pointer to a `T` value. Its zero value is `nil`.

```go
var p *int
```

The `&` operator generates a pointer to its operand.

```go
i := 42
p = &i
```

The `*` operator denotes the pointer's underlying value.

```go
fmt.Println(*p) // read i through the pointer p
*p = 21         // set i through the pointer p
```

This is known as "dereferencing" or "indirecting". Unlike C, Go has no pointer arithmetic.

Note that `*` before the type means the variable can hold the address location of the type. However `*` before the `var` means the deferencing of the variable. 

In Go, everything is **passed by value**. This means when you pass a variable to a function, Go makes a complete copy of it. So if a struct has another struct inside it. Entire struct will be copied recursively. 

```go
package main

import "fmt"

type Address struct {
	city        string
	postal_code int
}

type User struct {
	name    string
	age     int
	address Address
}

func myFunc(user User) {
	user.address.city = "Lucknow"
	fmt.Println(user, "Inside myfunc")
}

func main() {
	user := User{name: "adil", age: 23, address: Address{city: "LKO", postal_code: 10}}
	fmt.Println(user)
	myFunc(user)
	fmt.Println(user)
}
```


```bash
{adil 23 {LKO 10}}
{adil 23 {Lucknow 10}} Inside myfunc
{adil 23 {LKO 10}}
```

Observe that value was not changed. 

However if struct has the pointer as field. Although the field will be copied inside value of internal ptr will remain the same. 

```go
package main

import "fmt"

type Address struct {
	city        string
	postal_code int
}

type User struct {
	name    string
	age     int
	address *Address
}

func myFunc(user User) {
	user.address.city = "Lucknow"
	fmt.Println(user, "Inside myfunc")
}

func main() {
	user := User{name: "adil", age: 23, address: &Address{city: "LKO", postal_code: 10}}
	fmt.Println(user, *(user.address))
	myFunc(user)
	fmt.Println(user, *(user.address))
}
```

Result 

```bash
{adil 23 0x39afeb44c090} {LKO 10}
{adil 23 0x39afeb44c090} Inside myfunc
{adil 23 0x39afeb44c090} {Lucknow 10}
```



### Structs

A `struct` is a collection of fields. In go when defining we first define using `type` keyword followed by the name and then `struct`. We declare structs in the parenthesis. var can be ommited but we need to write the type after field name.

```go
type User Struct{
	field_name field_type,
	...
}
```

We can declare the structs using the `{}` parenthesis syntax. Here we can either use ordered initialization or named field intialization.

```go
var user User = User{name:""}
```

This line creates new struct. Not only that we can decalre the struct inside struct and the intialization is done recursively.

```go
user := User{name:"",address:Address{}}
```

Note that for the primitive types type defining is not req but req for the struct types. 

Struct fields can be accessed through a struct pointer.
To access the field `X` of a struct when we have the struct pointer `p` we could write `(*p).X`. However, that notation is cumbersome, so the language permits us instead to write just `p.X`, without the explicit dereference.


A struct literal denotes a newly allocated struct value by listing the values of its fields. You can list just a subset of fields by using the `Name:` syntax. (And the order of named fields is irrelevant.)

```go
var (
	v1 = Vertex{1, 2}  // has type Vertex
	v2 = Vertex{X: 1}  // Y:0 is implicit
	v3 = Vertex{}      // X:0 and Y:0
	p  = &Vertex{1, 2} // has type *Vertex
)
```

### Arrays

A type `[n]T` is an array of n values of type T. 

```go
var a[10]int // declares the array of size 10
```

An array has a fixed size. A slice, on the other hand, is a dynamically-sized, flexible view into the elements of an array. In practice, slices are much more common than arrays.

Go’s arrays are values. An array variable denotes the entire array; it is not a pointer to the first array element (as would be the case in C). This means that when you assign or pass around an array value you will make a copy of its contents. (To avoid the copy you could pass a _pointer_ to the array, but then that’s a pointer to an array, not an array.) One way to think about arrays is as a sort of struct but with indexed rather than named fields: a fixed-size composite value.

An array literal can be specified like so:

```go
b := [2]string{"Penn", "Teller"}

// or allow go compiler to compute values for you
b := [...]string{"Penn", "Teller"}
```

Higher dimentional zero arrays can be declared as follows.

```go
var arr [10][10]int // array of size 10*10
```

Finally note that array variable represents the value so when passed as the argument to the function entire array is copied usually its prefereed to copy arrays.

```go
func get_data(arr *[8][8]int){
	// getting array of size 8*8
}
```

Note that the array length comes with type so only the array of size `8*8` will be passed. 
#### Slices

The type specification for a slice is `[]T`, where `T` is the type of the elements of the slice. Unlike an array type, a slice type has no specified length. A slice literal is declared just like an array literal, except you leave out the element count:

```go
letters := []string{"a", "b", "c", "d"}
```

A slice can be created with the built-in function called `make`, which has the signature,

```go
func make([]T, len, cap) []T
```

When the capacity argument is omitted, it defaults to the specified length. The length and capacity of a slice can be inspected using the built-in `len` and `cap` functions.

It’s important to understand that even though a slice contains a pointer, it is itself a value. Under the covers, it is a struct value holding a pointer and a length. It is _not_ a pointer to a struct. However slice contains the pointer to the underlying array. This means whenever slice is passed to a function although slice is passed by value, it includes pointer to the underlying array therefore if any modification is done to slice it will be reflected.

```go
func SubtractOneFromLength(slice []byte) []byte {
    slice = slice[0 : len(slice)-1]
    return slice
}
```


```go
len(letters)
cap(letters)
```

The zero value of a slice is `nil`. The `len` and `cap` functions will both return 0 for a nil slice. 
A slice can also be formed by “slicing” an existing slice or array. Slicing is done by specifying a half-open range with two indices separated by a colon. For example, the expression `b[1:4]` creates a slice including elements 1 through 3 of `b` (the indices of the resulting slice will be 0 through 2).


```go
b := []byte{'g', 'o', 'l', 'a', 'n', 'g'}
// b[1:4] == []byte{'o', 'l', 'a'}, sharing the same storage as b
```

The start and end indices of a slice expression are optional; they default to zero and the slice’s length respectively: This is also the syntax to create a slice given an array:

A slice is a descriptor of an array segment. It consists of a pointer to the array, the length of the segment, and its capacity (the maximum length of the segment).

Slicing does not copy the slice’s data. It creates a new slice value that points to the original array. This makes slice operations as efficient as manipulating array indices. Therefore, modifying the _elements_ (not the slice itself) of a re-slice modifies the elements of the original slice:

Earlier we sliced `s` to a length shorter than its capacity. We can grow s to its capacity by slicing it again

```go
s = s[:cap(s)]
```

A slice cannot be grown beyond its capacity. Attempting to do so will cause a runtime panic, just as when indexing outside the bounds of a slice or array. Similarly, slices cannot be re-sliced below zero to access earlier elements in the array.

To add the element we have built in append function. It adds the element to the underlying array if space is there. If space is not there new array is created with updated capacity and older elements are copied from earlier array to the new one. This is mainly same as in other languages.

```go
func append(s []T, x ...T) []T
```

GO provides the built in copy function whose task is just to copy the content of src slice to dest slice. 

```go
func copy(dst, src []T) int
```

Its implementation is roughly similar to the for loop listed here where the values from the s are being copied to `t`. This block of code shows how to increase the capacity of the slice. 

```go
t := make([]byte, len(s), (cap(s)+1)*2) // +1 in case cap(s) == 0
for i := range s {
        t[i] = s[i]
}
s = t
```

The `copy` function supports copying between slices of different lengths (it will copy only up to the smaller number of elements). In addition, `copy` can handle source and destination slices that share the same underlying array, handling overlapping slices correctly. Note the copying will be done upto length not upto capacity. That is why is sometimes so crucial to change the length of slice and so we have this operation to extend the length of slice to some length `l<cap()`. 

```go
slice = slice[0:l] // Capcity needs to be more than l
```

Finally we have rough implementation of `Append`

```go
func AppendByte(slice []byte, data ...byte) []byte {
    m := len(slice)
    n := m + len(data)
    if n > cap(slice) { // if necessary, reallocate
        // allocate double what's needed, for future growth.
        newSlice := make([]byte, (n+1)*2)
        copy(newSlice, slice)
        slice = newSlice
    }
    slice = slice[0:n]
    copy(slice[m:n], data)
    return slice
}
```

To append one slice to another, use `...` to expand the second argument to a list of arguments.

```go
a := []string{"John", "Paul"}
b := []string{"George", "Ringo", "Pete"}
a = append(a, b...) // equivalent to "append(a, b[0], b[1], b[2])"
// a == []string{"John", "Paul", "George", "Ringo", "Pete"}
```

Since the zero value of a slice (`nil`) acts like a zero-length slice, you can declare a slice variable and then append to it in a loop:

```go
func Filter(s []int, fn func(int) bool) []int {
    var p []int // == nil
    for _, v := range s {
        if fn(v) {
            p = append(p, v)
        }
    }
    return p
}
```

Higher dimentinal slices

We usually make use of make

```go
mat :=make([][]int,10)

	mat[i]=make([]int,10)

// mat is now 10*10 array
```

Unlike arrays, the rows of a multidimensional slice are not guaranteed to be next to each other in memory. Each row is allocated independently.

| **Feature**    | **Multidimensional Array**          | **Multidimensional Slice**                     |
| -------------- | ----------------------------------- | ---------------------------------------------- |
| **Size**       | Fixed at compile time.              | Can grow or shrink.                            |
| **Memory**     | One contiguous block.               | Multiple separate blocks (one per row).        |
| **Row Length** | Every row must be the same length.  | Each row can have a different length (Jagged). |
| **Pass by...** | Value (the whole matrix is copied). | Reference (only the header is copied).         |
### Strings

Strings are actually very simple: they are just read-only slices of bytes with a bit of extra syntactic support from the language. For starters, we can index them to access individual bytes:

```go
slash := "/usr/ken"[0] // yields the byte value '/'
```

We can slice a string to grab a substring:

```go
usr := "/usr/ken"[0:4] // yields the string "/usr"
```

We can also take a normal slice of bytes and create a string from it with the simple conversion:

```go
str := string(slice)
```

And in reverse direction as well. 

```go
slice := []byte(usr)
```

The array underlying a string is hidden from view; there is no way to access its contents except through the string. That means that when we do either of these conversions, a copy of the array must be made.

An important consequence of this slice-like design for strings is that creating a substring is very efficient. All that needs to happen is the creation of a two-word string header. Since the string is read-only, the original string and the string resulting from the slice operation can share the same array safely. 

It’s important to state right up front that a string holds _arbitrary_ bytes. It is not required to hold Unicode text, UTF-8 text, or any other predefined format. As far as the content of a string is concerned, it is exactly equivalent to a slice of bytes.

To find out what that string really holds, we need to take it apart and examine the pieces. There are several ways to do this. The most obvious is to loop over its contents and pull out the bytes individually, as in this `for` loop:

```go
 for i := 0; i < len(sample); i++ {
        fmt.Printf("%x ", sample[i])
    }
```

As implied up front, indexing a string accesses individual bytes, not characters.
Using `+` is fine for small things, but in a loop, it is a performance killer because it re-allocates memory every time. **The Better Way:** Use `strings.Builder`. It allocates a buffer and grows it efficiently, similar to a `StringBuilder` in Java

```go
var b strings.Builder
for i := 0; i < 100; i++ {
    b.WriteString("data ")
}
result := b.String()
```

Go provides the `strings` package for most logic:

```go
strings.Contains("hello","ll") // returns true or false
strings.Index(str1,str2) // first point where str2 is starting in str1
strings.HasPrefix() // Similarly HasSuffix() also exists
strings.Join([]string{"a","b"},separator) // first param is slice of strings returns joined string sep by param
strings.Split(str,sep) // returns the slice of strings. 
```

Converting between a `string` and a `[]byte` is common in systems programming (e.g., writing a string to a file or network socket).

```go
// String to Byte Slice
data := []byte("Hello") 

// Byte Slice to String
str := string(data)
```

Every time you convert between these two, Go makes a **full copy** of the data to ensure the string remains immutable.

If you iterate over the standard `for i := 0` loop, you iterate over **bytes**. `for range`, Go automatically decodes the UTF-8

```go
s := "世界" // "World" in Chinese
for i, r := range s {
    fmt.Printf("Index %d is %c\n", i, r)
}
```
## Zero values and initialization in go

In go for every primitive type there is a corresponding `zero` value. Unlike the `C/C++` where newly created primitive type has garbage value. The primitive variables in go are always initialized with zero value. 

Zero value of int,float etc is `0` for strings its empty string and so on. For the slices and arrays zero value is nil. 

Now when the `struct` is created go first allocates memory and then recursively fills in the struct with the zero value. 

Now with this there are three modes to operate in- 

#### new(T)

`new` is a built-in function that allocates memory, but it does **not** initialize it beyond zeroing it out. 
 - **Returns:** A pointer (`*T`) to a newly allocated zero value of type `T`.   
- **Best for:** Structs and basic types when you want a pointer and are happy with the default zero values.

```go
type Database struct {
    ID    int
    Name  string
}

db := new(Database) 
// db is of type *Database
// db.ID is 0, db.Name is ""
```

##### make()

`make` is specialized. It only works for **Slices, Maps, and Channels**. Unlike `new`, it actually prepares the internal data structure so it's ready for immediate use.

- **Returns:** An initialized **value** (not a pointer) of type `T`.
- **Why it's unique:** These three types are headers that point to underlying data (like a slice pointing to an array). `new` would only zero the header (making it `nil`), whereas `make` sets up the actual memory the header points to.

```go
s := make([]int, 0, 10) // Ready to append
m := make(map[string]int) // Ready to set keys
c := make(chan int) // Ready to send/receive
```

#### composite literals

This is the most common way to initialize structs, slices, and maps when you know the values upfront. It uses the `{}` syntax.

- **Flexibility:** You can create either a value or a pointer (using the `&` operator).
- **Control:** You can set specific fields and leave others as zero values.

Note that if the struct is nested struct we can simply create literal by nesting values. Also to access and update the values we use the syntax `arr[index]`. 

```go
// A value
u1 := User{ID: 1, Name: "Adil"} 

// A pointer (The "Idiomatic" way to replace new)
u2 := &User{ID: 2}
```


1. **Avoid `new` for Slices/Maps:** If you do `p := new(map[string]int)`, you get a pointer to a `nil` map. Trying to do `(*p)["key"] = 1` will cause a **panic**. Always use `make` or a literal for these.
    
2. **Pre-allocation is King:** In high-throughput systems, always prefer `make(type, len, cap)` for slices. Telling Go exactly how much memory you need upfront prevents the "allocation-and-copy" tax during execution.
    
3. **The `&Struct{}` Preference:** You will see `&User{...}` much more often than `new(User)` in Go codebases. It’s more readable and allows you to pass specific values immediately. 

### Maps

A map maps keys to values. The zero value of a map is `nil`. A `nil` map has no keys, nor can keys be added. The `make` function returns a map of the given type, initialized and ready for use

Note that data type of map is written as

```go
map[key_type]val_type
mp:=make(map[string]int)
```

Map literals are like struct literals, but the keys are required. Here we have map of string as keys and Vertex as values. 

```go
var m = map[string]Vertex{
	"Bell Labs": Vertex{
		40.68433, -74.39967,
	},
	"Google": Vertex{
		37.42202, -122.08408,
	},
}
```

Insert or update an element in map `m`:

```go
m[key]=val // update or add
elem = m[key] // get val
delete(m,key) // delete from map
elem ,ok = m[key] // test if present
```

If `key` is in `m`, `ok` is `true`. If not, `ok` is `false`.
