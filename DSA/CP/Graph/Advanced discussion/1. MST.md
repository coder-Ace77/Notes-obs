## Properties

Almost everything about MSTs reduces to two exchange arguments. 

**Cut property.** Take any cut (S,V∖S)(S, V\setminus S) (S,V∖S). If an edge e is the _strictly_ minimum-weight edge crossing that cut, then e belongs to every MST. 

Now why is it true. Conceptually we can assume our cut to be dividing the graph into two connected components. One component say is connected by a tree `t1` and another by `t2`. To build entire tree `t`. We just need one edge if `t1` and `t2` are mst for sub problem it turns out that minimum wt edge crossing cut will form the MST with `t1` and `t2`. 

Proof - Suppose we don't take this edge `e` min across cut then what happens is some edge with more wt `f` is picked. If we add `e` into MST it forms cycle. The `f` and `e` both belong to same cut. Now remove `f` and add `e` we get strictly better MST which is a contradiction. 

**Cycle property.** Take any cycle CC. If e is the _strictly_ maximum-weight edge on  C, then e belongs to no MST.

Proof - If an MST contained e, removing it splits T into two components; some other edge of C reconnects them at lower cost, contradiction.

The cut property tells you which edges to _include_; the cycle property tells you which to _exclude_. Every greedy MST algorithm is a scheduling of these two rules.

### Kruskal algorithm

A general kruskal algorithm sorts the edges first then at any step it keeps `F` some forest of MST.
Now it tries to make this `F` a MST `T` by adding edges iteratively in the increasing order. Kruskal will have an edge iwth nodes conneted by edges lie in the different components. Now by cut property it is optimal to use minimum wt edge connecting two parts. And that's proof.

Similarly prims algorithm. Keep a subset of `t1` `MST` at every step and tries iteratively add another node to the MST `t1` so that it becomes proper  MST `t`. Now how to do this we just pick next closest node to the `t1` which is again optimal due to cut property. 

#### Second best MST

A Minimum Spanning Tree  $T$  is a tree for the given graph  $G$  which spans over all vertices of the given graph and has the minimum weight sum of all the edges, from all the possible spanning trees. A second best MST  $T'$  is a spanning tree, that has the second minimum weight sum of all the edges, from all the possible spanning trees of the graph  $G$ .

Now important observation is that second best `MST` differs by just one edge. 
Proof - Think about what a spanning tree is: every vertex connected, no loops, exactly the right number of edges. Your MST is the cheapest such thing.

Now here's the key mental picture. **Take any edge that's _not_ in your MST and force it in.** The moment you add it, you've created a loop — because the two endpoints were already connected through the tree. A tree plus one extra edge always makes exactly one loop, never more.

You can't keep a loop in a tree, so you have to break it by removing one edge from that loop. And now you've got a valid tree again — same size, still connected, no loops. You did exactly one trade: one edge in, one edge out.

So _every_ alternative tree you can reach with a single swap is just "pick a non-tree edge, throw it in, kick out one edge from the loop it made." The natural question becomes: is the second-best tree always reachable this way, or might it need several swaps?

Imagine all possible spanning trees lined up by price. The very cheapest is your MST — call its price the floor. The second-best tree is the cheapest tree that costs _more_ than the floor. Crucially, **there's a gap**: nothing exists between the MST's price and the second-best's price. The second-best is, by definition, the _next_ price up. No tree lives in that gap.

Now suppose, for contradiction, the second-best tree were far away from the MST — many swaps different. Here's the trick: pick any one edge the MST has that the second-best tree lacks, and trade along it. Because the MST is the cheapest thing in existence, this trade can only make the second-best tree _cheaper or keep it the same_ — it can't get more expensive, since you're swapping toward the optimal structure.

But "cheaper" is impossible! There's nothing in the gap between the floor and the second-best price. So a strictly cheaper tree would have to drop _all the way down_ to the floor — meaning it'd be another MST. And if one swap turns the second-best into an MST, then the second-best was only one swap away from an MST the whole time. Contradiction with "far away."

### Critical and pseudo critical edges

Given a weighted undirected connected graph with `n` vertices numbered from `0` to `n - 1`, and an array `edges` where `edges[i] = [ai, bi, weighti]` represents a bidirectional and weighted edge between nodes `ai` and `bi`. A minimum spanning tree (MST) is a subset of the graph's edges that connects all vertices without cycles and with the minimum possible total edge weight.

Find _all the critical and pseudo-critical edges in the given graph's minimum spanning tree (MST)_. An MST edge whose deletion from the graph would cause the MST weight to increase is called a _critical edge_. On the other hand, a pseudo-critical edge is that which can appear in some MSTs but not all.

Note that you can return the indices of the edges in any order.

### Solution

Now first thing is finding if an edge is critical or not. And that's pretty simple if we after forcing the edge `e` during kruskal unionization process if we get any spanning tree of same cost as mst then this edge is not critical one. 

Now for pseudo crititical we just need to find if any mst has this edge we can do this by forscing that edge to be taken in spanning tree and then if the spanning tree formed by force has same cost then `e` is also pseudocritical. Mostly both are easy to do and one must be albe to complete both in time complexity of `O(E*E log V)`

### Minimum bottleneck spanning tree

Here instead of minimizing the total weight we minimize the maximum edge used. Every MST is also a minimum bottleneck spanning tree. However the converse fails. Since this theorum holds true our answer for this problem is the max weighted edge of MST.

Proof - The proof is based on the cut property. By converse say `T1` is any spanning treee and `T` is MST. Now for `T` to be MST we have to proof `b(T1)>b(T)`. `b(T)` is boottleneck of tree `T`. Since `b(T1)<e`  the edge crossing this cut `f` has to be atmost `b(T1)` so `f<=b(T1)<b(T)<=e` So `f<e`. ### Problem 

Given a graph wirth each node having some value. The cost of edge is `min(x1-y1,x2-y2)` where `(x1,y1)` and `(x2,y2)` are coordinates of the nodes given. What is the minimum cost of connecting entire set of notes so that all have simple path to each other. Total cost is sum of cost of choosen edges. 

### Solution

Again cost is given and we can not evaluate entire graph. The cost of movement is similar to manhattan but not exactly. 

For edge weight `min(|dx|, |dy|)`, we can split into cases:

- **Case A:** `|dx| ≤ |dy|` → cost = `|dx|`
- **Case B:** `|dy| < |dx|` → cost = `|dy|`

For **Case A** (cost = `|dx|`), sort nodes by X. For each node, only its **neighbors in sorted X order** are candidates  because inserting any node between them in X would give a cheaper edge.

Similarly for **Case B** (cost = `|dy|`), sort by Y. Now the interesting point in MST of graph only the edges from these two cases will come. So its enough to use these `2n` edges. And then run kruskal algorithm. Which will give us `MST`. To see why it works it is enough to see this visually always when you reach a node its always best to move to the smallest cost unvisited neighbour since this neighbour will minimise the cost moving forward. 

```
Sorted by X:  u --- n1 --- n2 --- v
              |____________________|
                   skip edge (u,v)
                   cost = |xu - xv|

Each hop cost ≤ |xu - xv| because each |xi - xj| ≤ |xu - xv|
So the path through intermediates is always at least as good.
```
