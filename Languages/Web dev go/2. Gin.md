Gin is a high-performance web framework for the Go programming language (Golang) designed primarily for building RESTful APIs and microservices. It is widely considered one of the fastest frameworks in the Go ecosystem due to its minimal overhead and efficient routing. 

Gin is built on three main technical pillars:

**Performance (Zero Allocation):** Unlike many other frameworks, Gin uses a **Radix Tree** (via `httprouter`) for its routing mechanism. This allows it to find the correct handler for a request in constant time without allocating memory on the heap during the routing process.

The framework operates around a few key components:

#### Engine 

The Engine is the entry point of your application. Think of it as the "Brain" that coordinates everything. When you run `r := gin.Default()`, you are creating an instance of this engine. It holds the configuration, the multiplexer (router), and the global middleware.

- `gin.Default()`: Includes a **Logger** (prints requests to console) and **Recovery** (prevents the server from crashing if a handler fails).
- `gin.New()`: A "blank slate" engine. Use this if you want total control over your middleware stack.


Basic import - `    "github.com/gin-gonic/gin"`

```go
import "github.com/gin-gonic/gin"

func main(){
	router:=gin.Default()
}
```

When you call `router := gin.Default()`, you aren't just getting a simple router; you are initializing a **Gin Engine** instance.

The `Default()` function returns a pointer to a `gin.Engine` struct that comes pre-configured with two essential pieces of **Middleware**:

- **Logger:** Automatically logs every incoming request (Method, Path, Status Code, Latency) to the console.
- **Recovery:** If your code panics somewhere during a request, this middleware catches it, returns a **500 Internal Server Error**, and keeps the server from crashing.

**RouterGroup:** The Engine actually embeds the primary `RouterGroup`. This is why you can call `router.GET()` directly on the engine.

Now we can register the function handlers for a given path by - 

```go
router.GET("/albums", getAlbums)
```

Routing groups are used to organize routes that share common logic, such as a URL prefix (e.g., `/api/v1`) or a specific set of middleware (e.g., Auth).

You create a group by calling the `.Group()` method on your engine or on another group (you can nest them!).

```go
func main() {
    r := gin.Default()

    // Group 1: Public API
    v1 := r.Group("/api/v1")
    {
        v1.GET("/login", loginHandler)
        v1.GET("/submit", submitHandler)
    }

    // Group 2: Admin routes with Middleware
    // This group prepends "/admin" to all paths and requires Authorization
    admin := r.Group("/admin", AuthMiddleware())
    {
        admin.POST("/delete-user", deleteHandler)
        admin.GET("/dashboard", dashboardHandler)
    }

    r.Run(":8080")
}
```

`Group` can take two parameters a prefix and secondly a middleware as well. Similarly we can use other http methods

```go
  router.GET("/someGet", getting)
  router.POST("/somePost", posting)
  router.PUT("/somePut", putting)
  router.DELETE("/someDelete", deleting)
  router.PATCH("/somePatch", patching)
  router.HEAD("/someHead", head)
  router.OPTIONS("/someOptions", options)
```

Finally we have method call the `router.Run("port")`

Each method accepts a path pattern and one or more `gin.HandlerFunc` values (the last one is your actual handler; earlier ones are inline middleware for that route).

**Route parameters** come in two flavours:

```go
r.GET("/users/:id", getUser)          // :id — named param, required
r.GET("/files/*filepath", serveFile)  // *filepath — wildcard, captures everything after /files/
```

Inside the handler, you read them with `c.Param("id")` and `c.Param("filepath")`. The wildcard always includes the leading `/`, so `/files/a/b/c` gives `filepath = /a/b/c`.
