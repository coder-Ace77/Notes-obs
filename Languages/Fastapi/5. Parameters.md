### Post request 

A POST request carries a "body"—usually a JSON object—containing the data you want the server to process, save, or act upon.

Now whatever request body expects we need to create a model for that. We create the model by extending the `BaseModel` class from pydrantic. We can define the fields inside of here.Once that model is created the json whatever is comming the fastapi will try to validate and convert to json data. Once that is done we can use it in our functions as paramter. 

To handle a POST request, you generally need three things:
1. **A Pydantic Model:** This defines the "shape" of the data you expect.
2. **The Decorator:** `@app.post("/path")` tells FastAPI to listen for POST calls at that URL.
3. **The Function:** Where you process the data

Basic example

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 1. Define the data structure (The Schema)
class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

# 2. Create the POST endpoint
@app.post("/items/")
async def create_item(item: Item):
    # FastAPI has already validated the data at this point
    item_dict = item.model_dump()
    if item.tax:
        price_with_tax = item.price + item.tax
        item_dict.update({"price_with_tax": price_with_tax})
    
    return {"message": "Item created successfully", "data": item_dict}
```

If a client sends a `string` where you expected a `float`, FastAPI will automatically intercept the request and return a **422 Unprocessable Entity** error before your code even runs. Note that field name must be corresponding to the json key in flight. 

Note that to make the paramter body paramter we need to be an pydrantic model. Any variable listed in the `decorator` with become the path parameter and any variable remaining will automatically be considered the query parameter. 

Note that fastapi will autmatically do the validation based on the field types which are described by the rules of type hints. Sometimes we may be wanting to have optional fields with some default value.

We again say that we can provide the default value by = in the field. As shown however if we want our field to also have `Null` to truly make it optional then we need to change its type from normal to union of `type | None`.

```python
class Author(BaseModel):
	name:str
	age:int | None = None
```

#### Validation rules 

- If you pass a string `"42"` to a field typed as an `int`, Pydantic won't crash. It will intelligently convert it to the integer `42`. However, if you pass `"forty-two"`, it will raise a `ValidationError`.
- When you call `UserProfile(username="Devin", email="dev@example.com")`, Pydantic triggers its internal validation logic before the object is even created.
- Fields can be more than just types; you can use the `Field` function to add metadata and complex constraints: **Constraints:** `gt` (greater than), `le` (less than or equal), `min_length`, and `regex` allow you to bake business logic directly into the data model.
 - **Metadata:** The `description` field is picked up by FastAPI and automatically added to your Swagger/OpenAPI documentation.

Once you have an instance of a class, you have several "superpowers" available to you:

| **Method**                 | **Purpose**                                                                   |
| -------------------------- | ----------------------------------------------------------------------------- |
| **`.model_dump()`**        | Converts the object into a standard Python dictionary.                        |
| **`.model_dump_json()`**   | Converts the object directly into a JSON-formatted string.                    |
| **`.model_validate()`**    | Takes a dictionary and turns it into a class instance (great for DB results). |
| **`.model_json_schema()`** | Generates a full JSON Schema representation of your class.                    |
#### field

Field is used to do three important things - 

 - **Validation:** Setting "legal" boundaries (e.g., "price cannot be negative").Basic numic constraints are `gt/lt`. String constraints are `min_length,max_length` or `pattern` to have regular exprtessions. 
 - We can also add metadata which will appear in the documentation. We can add three - title, description , examples. 
 - We can also add the alias which means the json can also be present in this format. 

```python
class User(BaseModel):
    first_name: str = Field(alias="FirstName")
```

#### Query and Path and Body types

Note that fastapi comes with the built in Path and query types. They add rich set of functionality like alias , description title etc. All of these can be inherited from fastapi. Note all of these are the values of the some argument not the type. 

```python
@router.get("/{book_name}")
def get_by_name(book_name:str=Path(None,
    title="Book name",
    description="This is the book name to be searched",
    alias="bookName",
)):
    for i,d in enumerate(data.db.values()):
        if d.title==book_name:
            return {"data":d}
    
    return {"data":"No book with this name found"}
```

Note that for all the types be it body , path or query the first paramter is always the default value we want to give. We can make it requred as well by making first paramter `...`. This can also be done via field. All the validators available with the field are also available with the Path , Query and Body as well. 

Example - 

```python
@router.get("/{book_name}")
def get_by_name(book_name:str=Path(...,
    title="Book name",
    description="This is the book name to be searched",
    alias="bookName",
)):
    for i,d in enumerate(data.db.values()):
        if d.title==book_name:
            return {"data":d}

    return {"data":"No book with this name found"}
```

Finally the model can come inside some model which are called nested models. 

```python
from pydantic import BaseModel

class Author(BaseModel):
	name:str
	age:int
	
class Book(BaseModel):
	author:Author
	title:str
	price:float
```
