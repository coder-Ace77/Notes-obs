### Encapsulation

Encapsulation means keeping an object’s data private and letting the object control how that data is used. You interact with it through simple methods instead of reaching in and changing its internal details yourself. It is implemented by use of access modifiers like making a field private. 

### Abstraction

Abstraction means exposing only what's essential and hiding implementation details behind clear interfaces. You define what something can do without revealing how it does it.

Abstraction is all about hiding complex implementation details. The user fo a method does not need to see the entie implementation rather only the method and what it does. In reality abstraction is done by using interfaces. We define interfaces and user knows what the function does. It needs not to know the entire implemetation by looking into the impl of a class. That's how interfaces implement the abstraction. 

An abstraction hides complexity. When your payment processing code depends on a PaymentMethod interface instead of concrete classes like CreditCardProcessor or PayPalProcessor, you can swap implementations without touching the code that uses them. The caller doesn't need to know whether you're hitting Stripe's API or storing payment tokens in a database. It just calls process() and gets a result.

### Inheritance

The important point regarding inheritance is how to decide when two classes can share the same base class. Inheritance makes sense when you have stable, shared implementation that multiple subclasses genuinely need.

The classic mistake made in interviews is using inheritance to model behavior differences. If subclasses need to override methods to provide completely different implementations, that's a sign you're using the wrong tool.

For example having car now two subtypes are electric and gas engine. Both with different total logic. Which does not makes sense. When behavior varies, the better approach is to isolate that behavior into its own abstraction and compose it.

```cpp
 class Drivetrain {
 public:
   virtual ~Drivetrain() = default;
   virtual void start() = 0;
 };
 
 class GasEngine : public Drivetrain {
 public:
   void start() override { /* gas engine startup logic */ }
 };
 
 class ElectricMotor : public Drivetrain {
 public:
   void start() override { /* electric motor startup logic */ }
 };
 
 class CarWithDrivetrain {
 public:
   explicit CarWithDrivetrain(Drivetrain& drivetrain) : drivetrain(drivetrain) {}
 
   void start() { drivetrain.start(); }
 
 private:
   Drivetrain& drivetrain;
 };
```

So we used the motor logic else where.
