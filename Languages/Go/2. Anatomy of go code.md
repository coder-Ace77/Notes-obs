Every Go file follows a predictable, top-down structure that makes it one of the most readable languages in existence. Every single Go file **must** start with a package declaration. It tells the compiler which package this file belongs to.

```go
import (
    "fmt"      // Standard library for formatting text
    "math/rand" // Nested standard library
)
```

Import is where you list the other packages your code needs. Go is very "clean"—if you import a package and don't use it, the code **will not compile**.

If your file is part of `package main`, it needs a `main` function. This is where the execution starts when you run the program. It takes no arguments and returns no values. Note that main package needs to have the 

```go
func main() {
    // This is where the magic happens
    fmt.Println("Hello, World!")
}
```

So our basic file is like 

```go
package main

import "fmt"

func main(){
	fmt.PrintLn("Hello")
}
```


Inside of go there two kinds of packages - 

- Executable - Generates a executable file which can be run. packge with the name `main` are executables. 
- Reusables - These are code used as `helper`. Any other name will not spit the executable. So building Reusable packages will not do anything. 

### Import 

In Go, the `import` statement is the mechanism used to access code from other packages. 

Go uses a **path-based** system. When you write `import "path/to/package"`, the Go compiler looks for that package in three specific places:

1. **The Standard Library:** Built-in packages like `fmt`, `os`, and `net/http` located in your `GOROOT` (where Go is installed).
2. **Your Local Module:** Any folder inside your current project. Go looks at your `go.mod` file to determine the root name of your project.
3. **External Dependencies:** Packages downloaded from the internet (e.g., GitHub) stored in your `GOPATH/pkg/mod` folder.

Standard packages are imported by their short name:

```go
import "fmt"
import "math/rand" // Nested standard package
```

For anything not in the standard library, you must use the **full path**. If your `go.mod` says `module github.com/user/myapp`, and you have a folder named `auth`, you import it like this:

```go
import "github.com/user/myapp/auth"
```

We can also use alias

```go
import f "fmt"
```

Use of . imports the entire code into the local namespace. 
Functions or variables in the different files of the same package need not be imported. Also we can declare any variable out side the functions but assignment has to be done inside some function only. 

```go
import . "fmt"
```

Rules
- No unsed packages
- No circular dependencies

Note that we need to include package and package name is used to resolve namespace conflicts. So we used `fmt.Println()`

Also note that order of functions does not matter. 

Finally if not working with module we need to specify all the files needs for the main entry point to work. This means if we are using say main.go a.go and b.go the command will be

```bash
go main.go a.go b.go
```


By convention, the package name is the same as the last element of the import path. For instance, the `"math/rand"` package comprises files that begin with the statement `package rand`.

### Exported names

In Go, a name is exported if it begins with a capital letter. For example, `Pizza` is an exported name, as is `Pi`, which is exported from the `math` package.

`pizza` and `pi` do not start with a capital letter, so they are not exported.

When importing a package, you can refer only to its exported names. Any "unexported" names are not accessible from outside the package.
