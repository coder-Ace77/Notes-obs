## Document loaders

Document loaders are responsible for taking raw data from various sources (PDFs, Word docs, Notion, websites) and converting them into a standard `Document` format (usually containing `page_content` and `metadata`).

**PyPDF (`PyPDFLoader`):** This is your workhorse for standard, text-heavy PDFs. It's fast and reliable for extracting text page by page.

**LangChain Loaders:** LangChain provides a unified wrapper around hundreds of underlying loaders (including PyPDF and Unstructured), allowing you to swap data sources without changing your core pipeline logic

```python
# pip install langchain langchain-community pypdf unstructured pdf2image pikepdf

from langchain_community.document_loaders import PyPDFLoader
from langchain_community.document_loaders import UnstructuredFileLoader

# 1. Basic PyPDF Loader
print("--- PyPDF Loader ---")
pdf_loader = PyPDFLoader("sample_contract.pdf")
pdf_docs = pdf_loader.load()
print(f"Loaded {len(pdf_docs)} pages.")
print(f"Page 1 content: {pdf_docs[0].page_content[:100]}...\n")

# 2. Unstructured Loader (Great for structure and tables)
print("--- Unstructured Loader ---")
# 'elements' mode splits by logical elements (paragraphs, titles, tables) rather than pages
unstructured_loader = UnstructuredFileLoader("sample_report.pdf", mode="elements")
unstructured_docs = unstructured_loader.load()

# Let's find a table element if it exists
for doc in unstructured_docs:
    if doc.metadata.get("category") == "Table":
        print("Found a table!")
        print(doc.page_content) # This will often be formatted text representing the table
        break
```

### Chunking 

Embedding models and LLMs have context windows. You cannot feed a 500-page book into an embedding model at once. You must "chunk" it. How you chunk dictates how accurately your system retrieves information. 

There are three main approaches to do this kind of thing

#### Fixed size chunking

- Split text into fixed size chunks of size `N`. It is simple and fast but may break sentences in half and therefore can destroy the semantic meaning. 

#### Recursive chunking 

We first split the text by paragraphs using `/n` as delimiter and then using `.` full stop as limiter finally to word level. Note that it will move to smaller level if and only if the chunk is too large. 
- _Pros:_ Respects natural language boundaries.
- _Cons:_ Can still occasionally separate related paragraphs.

#### Semantic chunking 

The most advanced method. It calculates the embedding of every sentence. It then compares the similarity between adjacent sentences. If the similarity drops below a certain threshold, it assumes the topic has changed and creates a chunk break. 

_Pros:_ Chunks represent cohesive, distinct ideas.
_Cons:_ Computationally expensive (requires running an embedding model during the chunking phase).


```python
# pip install langchain-text-splitters langchain-openai langchain-experimental

from langchain_text_splitters import CharacterTextSplitter, RecursiveCharacterTextSplitter
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings # Or any other embedding model

sample_text = """RAG is a powerful technique. It combines retrieval with generation.
However, data processing is key. If you put garbage in, you get garbage out.

Let's switch topics to Python. Python is dynamically typed. It relies on indentation."""

# 1. Fixed-Size Chunking (Avoid unless necessary)
fixed_splitter = CharacterTextSplitter(
    separator="", # No logical separation, just raw characters
    chunk_size=50,
    chunk_overlap=10
)
fixed_chunks = fixed_splitter.split_text(sample_text)
print("--- Fixed Chunks ---")
for i, chunk in enumerate(fixed_chunks): print(f"{i}: {chunk}")


# 2. Recursive Chunking (The Go-To standard)
recursive_splitter = RecursiveCharacterTextSplitter(
    chunk_size=60,
    chunk_overlap=10,
    separators=["\n\n", "\n", " ", ""] # Tries \n\n first, then \n, etc.
)
recursive_chunks = recursive_splitter.split_text(sample_text)
print("\n--- Recursive Chunks ---")
for i, chunk in enumerate(recursive_chunks): print(f"{i}: {chunk}")


# 3. Semantic Chunking (Topic-based)
embeddings = OpenAIEmbeddings() # Requires API key set in environment
# The environment variable you need to set is **`OPENAI_API_KEY`**.
semantic_splitter = SemanticChunker(
    embeddings, 
    breakpoint_threshold_type="percentile" # Splits when semantic distance is high
)
semantic_chunks = semantic_splitter.split_text(sample_text)
print("\n--- Semantic Chunks ---")
# This should ideally group the RAG sentences together, and the Python sentences together
for i, chunk in enumerate(semantic_chunks): print(f"{i}: {chunk}")
```

### Metadata enrichment

When building a RAG system, retrieving based on vector similarity alone is often not enough. For example, if a user asks, "What was our revenue in Q3 2023?", vector search might return a document talking about revenue from Q1 2022 because the words are semantically similar.

**Metadata Enrichment** solves this. By tagging every chunk with metadata (e.g., `date`, `author`, `department`, `document_type`), you can perform **hybrid search**:

- _Step 1 (Metadata Filter):_ Filter the vector database to ONLY look at chunks where `year == 2023` and `quarter == "Q3"`.
- _Step 2 (Vector Search):_ Perform the semantic search on that filtered subset.

```python
from langchain_core.documents import Document

# Raw text extracted from a loader
raw_texts = [
    "Q3 Revenue was up 15% due to enterprise sales.",
    "Our new engineering hire is John Doe."
]

# Adding rich metadata
documents = [
    Document(
        page_content=raw_texts[0],
        metadata={
            "source_id": "report_fin_03",
            "page_number": 12,
            "author": "Finance Team",
            "timestamp": "2023-10-01",
            "category": "financials"
        }
    ),
    Document(
        page_content=raw_texts[1],
        metadata={
            "source_id": "hr_update_11",
            "page_number": 1,
            "author": "HR Dept",
            "timestamp": "2024-01-15",
            "category": "human_resources"
        }
    )
]

print("--- Metadata Example ---")
for doc in documents:
    print(f"Content: {doc.page_content}")
    print(f"Metadata: {doc.metadata}\n")
    
# In a vector DB like Pinecone, Chroma, or Qdrant, you could now query:
# db.similarity_search("revenue increase", filter={"category": "financials"})
```
