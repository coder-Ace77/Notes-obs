This paradigm is used for chronological scheduling problems where entities have strict deadlines or expiration bounds, and you must select a subset to maximize total reward.

#### Abstract Mechanism

Moving chronologically forward in deadline problems creates a paradox: if you eagerly consume a time slot for a low-value task with an early deadline, you might block a high-value task; but if you hold out for high-value tasks, you might waste early slots.

To solve this, you invert the chronological axis.

**Phase 1: Time Inversion.** You identify the absolute maximum deadline across the entire dataset. You set your current time counter $T$ to this maximum bound and iterate backward toward zero.

**Phase 2: Monotonic Pool Expansion.** You maintain a dynamic pool of available candidates (a Max-Heap). At every discrete time step $T$, you inject all items that have a deadline _exactly_ equal to $T$ into the pool. You then greedily extract the single highest-reward item from the pool, assign it to time slot $T$, and decrement $T$.

#### Mathematical Justification

By moving backward, the constraint logic shifts from restrictive to permissive.

If an item has a deadline $D$, it can legally be assigned to _any_ time slot $t \le D$. When you iterate backward, an item that enters the pool at time $T$ is mathematically guaranteed to be valid for all remaining future states (which are $T-1, T-2, \dots, 0$).

Because the pool only grows with items that are universally valid for all smaller time steps, picking the maximum value at the latest possible valid moment never restricts your future choices. You seamlessly optimize the reward while deferring the most constrained items to the only slots they can fit into.

#### Example

You are given a list of jobs. Every job takes **1 unit of time** to complete, and has a specific **deadline** and **profit**. If the job is completed on or before its deadline, you earn the profit. Your goal is to maximize total profit.

### Code 

```cpp
struct Job {
    char id;
    int deadline;
    int profit;
};

int maxProfitSequence(std::vector<Job>& jobs) {
    // 1. Find the maximum deadline across the dataset
    int max_deadline = 0;
    for (const auto& job : jobs) {
        max_deadline = std::max(max_deadline, job.deadline);
    }
    // Sort jobs by deadline descending so we can easily group them
    std::sort(jobs.begin(), jobs.end(), [](const Job& a, const Job& b) {
        return a.deadline > b.deadline;
    });
    // Max-heap to store the profits of universally valid candidates
    std::priority_queue<int> max_heap;
    int total_profit = 0;
    int job_index = 0;
    int n = jobs.size();
    // 2. Iterate backward from the maximum deadline down to 1
    for (int t = max_deadline; t > 0; --t) {
        // Monotonic Pool Expansion: Inject all jobs that expire exactly at 't'
        while (job_index < n && jobs[job_index].deadline == t) {
            max_heap.push(jobs[job_index].profit);
            job_index++;
        }
        // Greedily extract the highest reward item for this time slot
        if (!max_heap.empty()) {
            total_profit += max_heap.top();
            max_heap.pop();
        }
    }
    return total_profit;
}
```

## Sweep line

This paradigm is deployed when calculating maximum concurrent density, peak load, or boundary interactions across a massive set of overlapping intervals, where sorting by start or end times alone cannot capture the dynamic active state.

Instead of evaluating an interval as a single geometric entity bounded by a start and end, this paradigm shatters the interval into two independent, infinitely thin temporal events: an "entry" event and an "exit" event.

**Phase 1: Event Decomposition.** You discard the concept of contiguous blocks. Every interval `[start, end]` is destroyed and converted into two separate coordinate points: `(start, +1)` representing an influx of density, and `(end, -1)` representing a depletion of density.

**Phase 2: Unified Timeline Sorting.** All disconnected events are pooled together and sorted strictly by their coordinate values, reconstructing a single, unified chronological axis. If an entry and an exit occur at the exact same coordinate, a tie-breaking rule resolves their priority based on the problem's boundary inclusiveness.

**Phase 3: State Accumulation.** You iterate through the sorted timeline. Because the events are independent, a running accumulator simply absorbs the $+1$ or $-1$ payloads. The state of the accumulator at any step $i$ mathematically represents the exact instantaneous density of the system at coordinate $X_i$.

An interval array represents a continuous function of density over time. Finding the maximum density directly is difficult. However, the entry and exit events represent the _discrete derivative_ (the rate of change) of that density function.

By the Fundamental Theorem of Calculus, integrating the derivative yields the original function. The Sweep-Line is simply the discrete integration of those $+1$ and $-1$ impulses. By sorting the derivative impulses chronologically and maintaining a running prefix sum, you perfectly reconstruct the instantaneous amplitude of the original overlapping system at every critical boundary, allowing you to easily extract the absolute global maximum.

#### Problem

Given an array of active tasks where each task has a `start` time and `end` time, find the minimum number of CPU cores required to execute all tasks without overlap (which is equivalent to finding the maximum concurrent overlapping tasks).

### Solution

```cpp
int minCPUCores(vector<vector<int>>& intervals) {
    // Phase 1: Event Decomposition
    vector<pair<int, int>> events;
    for (const auto& interval : intervals) {
        events.push_back({interval[0], 1});   // +1 for task start
        events.push_back({interval[1], -1});  // -1 for task end
    }

    // Phase 2: Unified Timeline Sorting
    // Sort by time. If times are equal, process the end (-1) before the start (+1)
    // to free up the core before assigning it to a new task.
    sort(events.begin(), events.end(), [](const pair<int, int>& a, const pair<int, int>& b) {
        if (a.first == b.first) {
            return a.second < b.second; 
        }
        return a.first < b.first;
    });

    // Phase 3: State Accumulation
    int current_load = 0;
    int max_load = 0;

    for (const auto& event : events) {
        current_load += event.second;
        max_load = max(max_load, current_load);
    }

    return max_load;
}
```
