The `net/http` package is the backbone of Go’s web capabilities. Everything in `net/http` revolves around this single interface:

```go
type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}
```

- **`ResponseWriter`**: An interface used to construct the HTTP response (status code, headers, body).
- **`*Request`**: A struct representing the incoming HTTP request (URL, Method, Headers, Body, Form data).

Any type that implements `ServeHTTP` can act as a web server.

When you run `http.ListenAndServe`, several technical layers activate:

1. **`tcp.Listen`**: The server opens a TCP socket on the specified port.
2. **The Accept Loop**: The server runs a `for` loop that waits for new connections.
3. **Goroutine per Request**: For every incoming connection, the server spawns a **new goroutine**. This is why Go is naturally high-concurrency—one blocked request doesn't stop the others.
4. **The Multiplexer (Mux)**: The "router" examines the URL path and matches it against registered patterns to find the correct `Handler`.

The **ServeMux** is an HTTP request multiplexer. It matches the URL of each incoming request against a list of registered patterns and calls the handler for the pattern that most closely matches the URL.

Most developers use `HandleFunc`, which is a helper that converts a standard function into a `Handler`.

```go
http.HandleFunc("/welcome", func(w http.ResponseWriter, r *http.Request) {
    fmt.Fprint(w, "Hello, Gopher!")
})
```

To understand `http.HandleFunc`, you have to understand how Go bridges the gap between a **simple function** and the **`http.Handler` interface**. `http.HandleFunc` is a helper method that registers a function as a handler for a specific pattern in the `DefaultServeMux`.

```go
func HandleFunc(pattern string, handler func(ResponseWriter, *Request))
```

It takes a string (the URL path) and a function with a specific signature. But here is the catch: the server actually requires an **interface** (`http.Handler`), not a function.

Example 

```go
func main() {
    // 1. Registering the function
    http.HandleFunc("/api/data", getData)

    // 2. Starting the server
    http.ListenAndServe(":8080", nil) 
}

// The function signature MUST match func(http.ResponseWriter, *http.Request)
func getData(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    w.Write([]byte(`{"status": "ok"}`))
}
```

httpResponse writer is actually a writer interface and thus we can also do something like this 

```go
func myHandler(w http.ResponseWriter, r *http.Request) {
    name := "Gopher"
    fmt.Fprintf(w, "Hello, %s!", name)
}
```

**What’s happening technically:**

1. The `http.ResponseWriter` is an interface that satisfies `io.Writer`.
2. `fmt.Fprintf` takes your string, processes the `%s` placeholder, and sends the resulting bytes directly into the HTTP response stream.
3. Instead of creating a temporary string in memory (like `fmt.Sprintf` does) and then writing it, `Fprintf` writes to the destination buffer more efficiently.

Although http can be used to create servers we have other packages like `gin` which allow us to write servers much easily.
