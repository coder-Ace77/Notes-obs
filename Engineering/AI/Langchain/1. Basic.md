### Prompt templates

Prompt templates in LangChain are essentially **pre-defined recipes** for generating prompts. They allow you to create a reproducible format for instructions, where specific pieces of information (variables) can be swapped out dynamically.

A prompt template typically consists of:
- **Template String:** The text with placeholders (usually in `{curly_braces}`).
- **Input Variables:** The specific keys that will be replaced by actual values.
- **Formatting Logic:** The engine that merges the variables into the string.

Standard prompt template 

```python
from langchain_core.prompts import PromptTemplate

template = "Explain the concept of {topic} to a {audience}."
prompt = PromptTemplate.from_template(template)

# Formatting the prompt
final_prompt = prompt.format(topic="quantum physics", audience="5-year-old")
```

Since most modern LLMs (like GPT-4 or Gemini) are conversational, they use a list of **messages** rather than a single string. This template helps structure those roles.

- **SystemMessage:** Sets the persona/behavior.
- **HumanMessage:** The user's input.
- **AIMessage:** Examples of how the AI should respond (few-shotting).

```python
from langchain_core.prompts import ChatPromptTemplate

chat_template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful {role} assistant."),
    ("human", "How do I fix a {problem}?"),
])

messages = chat_template.format_messages(role="plumber", problem="leaky faucet")
```

Or we can do programatically

```python
system_prompt = """

    1. Quick summary
    2. Two interesting facts
"""

summary_prompt_template = PromptTemplate(input_variables=["information"],template=system_prompt)
```
### Data sources

In the LangChain ecosystem, **Document Loaders** are the bridge between raw data (wherever it lives) and the standardized format that LLMs can actually "read."

Every loader, regardless of the source, outputs a `Document` which contains two things:
 - **`page_content`**: The actual text string.
 - **`metadata`**: A dictionary containing "data about the data" (e.g., file name, page number, URL, or creation date).

- File based - `TextLoader` , `PyPDFLoader` , `CSVLoader`
- Web based - `WebBaseLoader` , `SiteMapLoader` , 
- Cloud and SSA - `NotionDirectoryLoader`

```python
from langchain_community.document_loaders import PyPDFLoader, WebBaseLoader

# 1. Load a local PDF
pdf_loader = PyPDFLoader("annual_report.pdf")
pdf_docs = pdf_loader.load()

# 2. Load a website
web_loader = WebBaseLoader("https://python.langchain.com/")
web_docs = web_loader.load()

# Combine them into one list of documents
all_docs = pdf_docs + web_docs
```

### Chat models

This line of code initializes a **`ChatOpenAI`** object, which acts as the "brain" or reasoning engine in your LangChain application. It’s the interface between your code and OpenAI’s API.

`ChatOpenAI` is actually an wrapper over the open-ai api. Earlier models used to take a string as input and return a string as response. However modern llms are designed for the chat conversations. 

```python
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model="gpt-5-nano",temperature=0)
```

- invoke - The standard way to send a prompt and get a full response back.

```python
response = llm.invoke("Summarize this legal contract.")
# Returns an AIMessage object
```

- stream()

```python
for chunk in llm.stream("Write a 500-word essay on AI ethics."):
    print(chunk.content, end="|", flush=True)
```

 - `.batch()`
If you have 50 items to process, don't use a loop. Use `.batch()`. It sends them in parallel, which is much faster than doing them one by one.

```python
responses = llm.batch(["Translate X to French", "Translate Y to French"])
```

- `.with_structured_output()` (The "Format" Button)
- 
This is the modern way to force the LLM to return data in a specific format (like a Python dictionary or a Pydantic model) instead of just a raw string. It eliminates the need for manual parsing.

```python
structured_llm = llm.with_structured_output(MySchemaClass)
```

- `.bind_tools()` (The "Skill" Button)
- 
This tells the model, "Hey, you have access to these specific functions (tools)." When you invoke the model later, it can decide to "call" these tools if the user's question requires it.

```python
llm_with_tools = llm.bind_tools([get_weather_function])
```

If you are building an async application (like a modern web server), every function above has an async equivalent: **`.ainvoke()`**, **`.astream()`**, and **`.abatch()`**

### Chain creating

Now that we know how to create the chats and how to invoke llm. We can connect both using the `|` operator. What it does is to take the input from one end and pushes it to the other end. And propogates through the chain. The important point is that data inputted in from one side is pushed to the other side. Now note that prompt template say needs one variable or may be an input then we will have to input the data as the first part.

```python
chain = prompt | llm | output_parser
```

This pipe syntax is called `LangChain Expression Language`. 

```python
system_prompt = """
    For the given {information}. I want you to create
    1. Quick summary
    2. Two interesting facts
"""
summary_prompt_template = PromptTemplate(input_variables=["information"],template=system_prompt)

chain = summary_prompt_template | llm
response = chain.invoke(input={"information":info})
print(response)
```

Each component of the chain has to be an implementation of `Runnable` protocol. Finally we can still call the invoke on the entire chain with the information. 

The `invoke` method is the primary way to trigger a "run" in LangChain. However, its behavior changes significantly depending on whether you are talking to the raw model (`llm`) or a composed sequence (`chain`).

When you invoke the raw LLM object, you are communicating directly with the model's brain. There is no automatic formatting; you must provide the exact text or message list the model expects.
- **Input:** A simple **string** OR a **list of Messages** (`HumanMessage`, `SystemMessage`).
- **Output:** An **`AIMessage`** object.

When you invoke a chain (e.g., `chain = prompt | llm | parser`), the `invoke` method becomes a **pipeline manager**. It ensures the data is formatted by the prompt, sent to the model, and cleaned by the parser.
- **Input:** A **dictionary** `{}`. The keys must match the variable names in your `PromptTemplate`.
- **Output:** Depends on the **last component** of your chain.

#### Response

When you call `llm.invoke()`, you get back a **BaseMessage** object (specifically an `AIMessage`).Its attributes are

- content - actuall text generated
- usage_metadata - A standard dictionary containing `input_token` , `output_token` etc. 
- response_metadata - 
- tool-calls - If the model decided to use a tool (like a calculator or search), this list will contain the function names and the arguments it generated.

When you call `chain.invoke()`, the response object **morphs** based on the very last component in your LCEL pipe (`|`). If the final is llm it returns AIResponse object. Others can be `JSONOutputParser` etc. HOwever whatever the input we give is actually dependent on the first input of the chain.
