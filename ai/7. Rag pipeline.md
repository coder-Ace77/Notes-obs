To build a **RAG (Retrieval-Augmented Generation)** system, we connect the "Knowledge Base" (ChromaDB) to a "Brain" (an LLM like GPT-4o). 

### The RAG Architecture

1. **User Query:** "What is the policy on remote work?"
2. **Retrieval:** ChromaDB finds the most relevant document: _"Remote work is allowed 2 days/week."_
3. **Augmentation:** We wrap the query and the document into a prompt.
4. **Generation:** The LLM reads the prompt and answers accurately.

We'll use **ChromaDB** for storage and **OpenAI** for both embeddings and the final answer.

```python
import chromadb
from chromadb.utils import embedding_functions
from openai import OpenAI
import os

# Initialize OpenAI and Chroma
client_openai = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
chroma_client = chromadb.PersistentClient(path="./rag_db")

# Define OpenAI Embedding Function for Chroma
openai_ef = embedding_functions.OpenAIEmbeddingFunction(
    api_key=os.getenv("OPENAI_API_KEY"),
    model_name="text-embedding-3-small"
)

# Create/Get Collection
collection = chroma_client.get_or_create_collection(
    name="company_knowledge", 
    embedding_function=openai_ef
)
```

Finally we need rag function 

```python
def ask_knowledge_base(question):
    # 1. RETRIEVAL: Find the most relevant context from ChromaDB
    results = collection.query(
        query_texts=[question],
        n_results=1
    )
    retrieved_context = results['documents'][0][0]

    # 2. AUGMENTATION & GENERATION: Pass context to the LLM
    prompt = f"""
    You are a helpful HR assistant. Use the provided context to answer the question.
    If the answer isn't in the context, say you don't know.

    Context: {retrieved_context}
    Question: {question}
    """

    response = client_openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

    return response.choices[0].message.content

# Test it out
print(ask_knowledge_base("When can I work from home?"))
# Output: You can work from home on Tuesdays and Thursdays according to company policy.
```

It is better than simple chatbot reason being - 

| **Feature**         | **Standard LLM**                | **RAG System**                               |
| ------------------- | ------------------------------- | -------------------------------------------- |
| **Accuracy**        | May hallucinate facts           | Grounded in your specific data               |
| **Knowledge**       | Frozen at last training date    | Updated instantly by adding to ChromaDB      |
| **Source Tracking** | Can't "prove" where it got info | Can return the exact `id` or document source |
Although the newer models have large context window we still prefer the RAG for mainly cost benefits. 

## Simple example

```python 
# app/services/rag_service.py
import chromadb
from openai import OpenAI
from app.core.config import settings, openai_ef

class RAGService:
    def __init__(self):
        self.client = chromadb.PersistentClient(path=settings.CHROMA_PATH)
        self.llm_client = OpenAI(api_key=settings.OPENAI_API_KEY)
        self.collection = self.client.get_or_create_collection(
            name="kb_production", 
            embedding_function=openai_ef
        )

    async def retrieve_and_generate(self, query: str):
        # 1. Retrieval
        results = self.collection.query(query_texts=[query], n_results=3)
        context = " ".join(results['documents'][0])

        # 2. Generation (using GPT-4o)
        prompt = f"Context: {context}\n\nQuestion: {query}"
        response = self.llm_client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content

    async def ingest_document(self, content: str, doc_id: str):
        self.collection.add(documents=[content], ids=[doc_id])
```


```python
# app/main.py
from fastapi import FastAPI, Depends, BackgroundTasks, HTTPException
from app.services.rag_service import RAGService
from pydantic import BaseModel

app = FastAPI(title="Sapient RAG API")
rag_service = RAGService() # Singleton instance

class QueryRequest(BaseModel):
    question: str

class IngestRequest(BaseModel):
    text: str
    doc_id: str

@app.post("/ask")
async def ask_question(req: QueryRequest):
    try:
        answer = await rag_service.retrieve_and_generate(req.question)
        return {"answer": answer}
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

@app.post("/ingest")
async def ingest_data(req: IngestRequest, background_tasks: BackgroundTasks):
    # Offload the heavy embedding task to the background
    background_tasks.add_task(rag_service.ingest_document, req.text, req.doc_id)
    return {"status": "Processing in background", "doc_id": req.doc_id}
```

### Implement the hybrid search 

While embeddings are great for "vibes" and concepts, they often fail on specific product IDs, jargon, or niche technical terms (e.g., searching for "C++20" might return "C++17" because they are semantically similar, even though you need that specific version).

**Hybrid Search = Semantic Search (ChromaDB) + Keyword Search (BM25).**

To combine these results, we use an algorithm called **Reciprocal Rank Fusion (RRF)**, which re-ranks items based on their position in both lists.

The Architecture
1. **Vector Search:** Handles conceptual queries (e.g., "how to fix memory leaks").
2. **BM25 (Keyword):** Handles exact matches (e.g., "io_uring", "valgrind").
3. **RRF:** Merges the two lists into a single, optimized result set.

Since ChromaDB doesn't have a built-in BM25 engine natively in the same way Elasticsearch does, we'll implement a lightweight hybrid retriever using the `rank_bm25` library.

```python

import numpy as np
from rank_bm25 import BM25Okapi
from app.services.rag_service import RAGService # Your previous service

class HybridRAGService(RAGService):
    def __init__(self):
        super().__init__()
        # In a real app, you'd load your documents from the DB to build the BM25 index
        self.raw_documents = [
            "Memory management in Python uses reference counting and GC.",
            "io_uring is a high-performance I/O interface for Linux.",
            "The Global Interpreter Lock (GIL) limits Python concurrency.",
            "Use valgrind to detect memory leaks in C++ applications."
        ]
        # Tokenize documents for BM25
        tokenized_corpus = [doc.split(" ") for doc in self.raw_documents]
        self.bm25 = BM25Okapi(tokenized_corpus)

    def reciprocal_rank_fusion(self, vector_results, keyword_results, k=60):
        """
        k is a smoothing parameter (constant). 
        Calculates a score based on the rank in both lists.
        """
        scores = {}
        
        # Process Vector Results (Chroma)
        for rank, doc_id in enumerate(vector_results):
            scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank)
            
        # Process Keyword Results (BM25)
        for rank, doc_id in enumerate(keyword_results):
            scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank)
            
        # Sort by the new fused score
        return sorted(scores.items(), key=lambda x: x[1], reverse=True)

    async def hybrid_retrieve(self, query: str, top_n=3):
        # 1. Get Semantic Results (ChromaDB)
        vector_resp = self.collection.query(query_texts=[query], n_results=10)
        vector_docs = vector_resp['documents'][0]

        # 2. Get Keyword Results (BM25)
        tokenized_query = query.split(" ")
        keyword_docs = self.bm25.get_top_n(tokenized_query, self.raw_documents, n=10)

        # 3. Fuse the results
        fused_results = self.reciprocal_rank_fusion(vector_docs, keyword_docs)
        
        # Return top N documents
        return [doc for doc, score in fused_results[:top_n]]
```
