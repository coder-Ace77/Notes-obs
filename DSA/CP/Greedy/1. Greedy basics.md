To look into it first we need to understand that a problem where we have to take a decision `d` from set of decisions `D`. Note that any `d` is a collection of choices. In computer algorithm paradigm, we make these set of choices in a serial manner. Here we select one choice first and then move towards next and so on. 

A greedy algorthm can have access to all chocies made till now but not to the choices we are gonna make in future. To prove that greedy algortihm works we need to prove that the greedy algorthm always produces that best set of for both intermediate step `i` and also this choice is optimal for any step comming forward. 

As far as intuition is concerned we should always be able to deduce that our problem should end up with the optimal answer regardless of the step we stop. We can state the same thing as two properties - 

- Greedy choice property - A global overall optimal solution can be reached by choosing the optimal choice at any step.
- Optimal substructure - The optimal solution to the entire problem contains the optimal solution to the sub-problems. 

### Formal proof of correctness

To prove that greedy strategy works we have two idea at work here - 

- First way of proving is to first prove that the solution is actually feasible. By feasible we mean that it follows all the constraints of the problem. To prove feasibilty we seldom use induction. Note that in most problems the feasibility proof is not necessary. Second is to prove optimality.  

One of the simplest methods for showing that a greedy algorithm is correct is to use a “greedy
stays ahead” argument. This style of proof works by showing that, according to some measure,
the greedy algorithm always is at least as far ahead as the optimal solution during each iteration of the algorithm. Once you have established this, you can then use this fact to show that the greedy algorithm must be optimal.

Another way to do exchange argument.They work by showing that you can iteratively transform any optimal solution into the solution produced by the greedy algorithm without changing the cost of the optimal solution, thereby proving that the greedy solution is optimal.

However we are going to be using both of the techniques not to prove the correctness but to solve greedy problems. 

There are three main types/patterns in greedy problems 

- Intervals - sorting etc
- Schedulng - mostly heaps are used. 
- Exchange argument - Sorting etc

#### 1. Coverage (Minimum intervals to cover a range)

**Paradigm:** Greedy (Sort by Start Time)
**The Strategy:**
1. Sort the intervals by their starting points in ascending order.
2. Maintain a variable representing the `current_end` of your covered range (initially the start of the target range).
3. Iterate through all intervals that start before or at `current_end`. Among these candidates, greedily select the interval that offers the maximum ending point (`max_reach`).
4. Once you process all valid overlapping intervals, update `current_end = max_reach` and increment your interval count. Repeat until the target range is fully covered.

**Why it works:** Because you have no choice but to cover the current left boundary, you might as well pick the interval that pushes your right boundary as far forward as possible to minimize total intervals used.

#### 2. Piercing (Minimum points to stab all intervals)

**Paradigm:** Greedy (Sort by End Time)

**The Strategy:**

1. Sort the intervals by their ending points in ascending order.
2. Place your first "stab" (point) at the exact end of the first interval.
3. Iterate through the rest of the intervals. If the next interval starts _after_ your current stab point, it means it has not been pierced yet.
4. Place a new stab at the end of this new interval, and increment your point count.

**Why it works:** By sorting by end times, the first interval in the list is the one that expires the soonest. To successfully pierce it while maximizing the chance of also piercing overlapping future intervals, you must push the stab point as far right as legally possible — which is its exact end point.

#### 3. Selection (Maximum non-overlapping intervals)

**Paradigm:** Greedy (Sort by End Time)

**The Strategy:**

1. Sort the intervals by their ending points in ascending order. (This is often called the Activity Selection problem).
2. Select the first interval and record its end time.
3. Iterate through the remaining intervals. If an interval's start time is greater than or equal to the recorded end time of the last selected interval, select it and update the tracked end time.

**Why it works:** To maximize the absolute count of intervals you can fit, you want each selected interval to finish as early as possible. Sorting by start time or duration fails here; always picking the one that finishes earliest guarantees the maximum remaining room for future intervals.

It is worth noting that the Greedy paradigm only applies when all intervals are weighted equally.

If the **Selection** problem is modified so that each interval has a specific "profit" or "weight" (and you want to maximize total profit rather than the raw count), Greedy fails entirely. This transforms it into the **Weighted Job Scheduling** problem.

**Paradigm for Weighted Selection:** Dynamic Programming + Binary Search

- Sort intervals by end time.
- Let $dp[i]$ be the maximum profit up to the $i$-th interval.
- For each interval, you either include it or exclude it. If you include it, use binary search to find the latest non-overlapping interval $j$ that finishes before interval $i$ starts.
- **State transition:** $dp[i] = \max(dp[i-1], \text{weight}[i] + dp[j])$
- **Time Complexity:** $O(N \log N)$

## Exchange argument

The **exchange argument** is a mathematical proof technique used to prove that a specific greedy algorithm always yields the optimal solution.

In competitive programming, it serves a highly practical second purpose: **it is the exact mathematical tool used to derive custom sorting comparators** when standard ascending or descending sorts fail.

When you encounter a problem that smells like a greedy approach but you cannot figure out _how_ to sort the elements, the exchange argument provides a mechanical algebraic way to find the answer.

The core philosophy of the exchange argument is proof by contradiction, combined with a structural transformation. It follows a strict logical flow:

1. **Assume an Optimal Solution:** Assume there exists a hypothetical optimal solution ($O$) that is different from your greedy solution ($G$).
2. **Identify an Inversion:** Because $O$ and $G$ are different, there must be at least two adjacent elements in $O$ that are "out of order" according to your greedy rule.
3. **Execute the Exchange:** Swap those two adjacent elements in $O$.
4. **Prove No Degradation:** Mathematically prove that this single swap either strictly improves the solution or keeps the cost exactly the same.
5. **The Conclusion:** If swapping out-of-order elements never degrades the optimal solution, you can continue swapping them (like Bubble Sort) until $O$ becomes identical to $G$. Therefore, $G$ must also be optimal.

We can derive the comparators for the greedy logic. Instead of guessing the greedy logic, you can reverse-engineer the exchange argument to find the exact sorting condition.

Here is the exact framework to use during a contest:

1. Isolate two arbitrary adjacent elements, $A$ and $B$.
2. Write the formula for the cost (or profit) if $A$ is placed exactly before $B$.
3. Write the formula for the cost if $B$ is placed exactly before $A$.
4. Set up an inequality: assume the arrangement $A \to B$ is strictly better than $B \to A$.
5. Simplify the algebra until the properties of $A$ and $B$ are completely separated on opposite sides of the inequality.

The resulting inequality is your `if (A < B)` condition for your custom sorting function.
