Permutation greedy is a family of greedy problems where the main object is a permutation of the numbers 1 to n. In these problems we either build a permutation that follows some rules, change a given permutation using an allowed move, or match two arrays against each other in the best possible order. For example a problem might ask for the smallest permutation where no number sits at its own position, or for the fewest swaps needed to sort a shuffled array.

Most of these problems become simple once we notice one thing that stays the same no matter how the moves are made. Instead of simulating, we look for that one thing and count it. The sections below cover the patterns that come up most often.

### 1. Pairing two arrays

Pairing problems give us two arrays and ask us to rearrange one of them so that the pairs score as well as possible. To make the sum of `a[i] * b[i]` as large as possible, sort both arrays in the same order so that big values meet big values and small meet small. To make it as small as possible, sort them in opposite orders. For example with `a = [1, 5]` and `b = [2, 10]`, pairing 5 with 10 gives `1*2 + 5*10 = 52`, while pairing 5 with 2 gives only `1*10 + 5*2 = 20`.

The reason is easy to see with just two pairs. If a big value is paired with a small partner while a small value has the big partner, swapping the two partners never lowers the total. Keep doing such swaps and you end up with the sorted pairing.

A common variant counts wins instead of adding up products. This is the old horse racing story. We have our horses, the opponent has theirs, and we want to win as many races as possible. Go through the opponent's horses from fastest to slowest. If our fastest remaining horse can beat theirs, send it. If it cannot, that race is lost anyway, so send our slowest horse and save the good ones for races we can win.

```cpp
vector<int> advantageCount(vector<int>& a, vector<int>& b) {
    int n = a.size();
    sort(a.begin(), a.end());
    vector<int> idx(n);
    iota(idx.begin(), idx.end(), 0);
    sort(idx.begin(), idx.end(), [&](int x, int y) { return b[x] > b[y]; });

    vector<int> ans(n);
    int lo = 0, hi = n - 1;
    for (int i : idx) {
        if (a[hi] > b[i]) ans[i] = a[hi--];   // we can win, use our best
        else              ans[i] = a[lo++];   // we lose anyway, use our worst
    }
    return ans;
}
```

Problems - LC 455 Assign Cookies, LC 870 Advantage Shuffle.

### 2. Fewest moves to sort a permutation

These problems give us a shuffled permutation and one allowed move, and ask for the fewest moves needed to sort it. The answer depends entirely on which move is allowed. For each move we either find something that every move changes by exactly one, or we find the part of the array that never needs to be touched.

| Allowed move | Fewest moves |
|---|---|
| swap any two elements | n minus the number of cycles |
| swap two neighbours | number of inversions |
| move any element to the front | n minus how many of the largest values are already in order |
| take out any element and insert it anywhere | n minus the longest increasing subsequence |

**Swap any two elements.** Draw an arrow from each position i to the position where `p[i]` should go. The arrows split the array into separate cycles. A cycle of length L needs exactly L - 1 swaps, because every swap puts one element in its final place and the last swap fixes two at once. Adding this up over all cycles gives n minus the number of cycles. For example `[2, 3, 1, 5, 4]` has the cycles (1 2 3) and (4 5), so it needs 5 - 2 = 3 swaps.

```cpp
int minSwaps(vector<int>& p) {          // p is a permutation of 0..n-1
    int n = p.size(), cycles = 0;
    vector<bool> seen(n, false);
    for (int i = 0; i < n; i++) {
        if (seen[i]) continue;
        cycles++;
        for (int j = i; !seen[j]; j = p[j]) seen[j] = true;
    }
    return n - cycles;
}
```

**Swap two neighbours.** An inversion is a pair where the bigger number comes before the smaller one. Swapping two neighbours that are out of order fixes exactly that one pair and leaves every other pair as it was. So each move removes exactly one inversion, and the answer is simply the number of inversions. It can be counted in n log n with a Fenwick tree or merge sort.

**Move any element to the front.** The elements we never touch get pushed to the back and keep their order, so they must be the largest values n, n-1, n-2 and so on, already standing in increasing order. Walk down from n and count how many of these largest values already appear left to right, then move everything else. For example in `[3, 1, 4, 2, 5]` the values 3, 4, 5 already appear in order but 2 comes after 3, so we keep 3 values and need 5 - 3 = 2 moves.

**Take out and insert anywhere.** The elements we never touch must already be in increasing order, and we want to touch as few as possible. So we keep the longest increasing subsequence and move everything else, giving n minus the LIS.

### 3. Smallest permutation that follows the rules

When the answer must be the lexicographically smallest permutation, we fill the positions from left to right. At each position we try the smallest unused number, and we accept it only if the remaining positions can still be filled correctly. A smaller number at an earlier position always beats anything that happens later, so this greedy is safe as long as the "can the rest still be completed" check is right.

**Smallest topological order.** We are given a graph and must list the vertices so that every edge goes from left to right, with the list as small as possible. This is Kahn's algorithm with a min-heap in place of a normal queue. At every step we take the smallest vertex that has no remaining incoming edges.

```cpp
vector<int> smallestTopo(int n, vector<vector<int>>& adj, vector<int>& indeg) {
    priority_queue<int, vector<int>, greater<int>> pq;   // min-heap
    for (int v = 1; v <= n; v++) if (indeg[v] == 0) pq.push(v);
    vector<int> order;
    while (!pq.empty()) {
        int v = pq.top(); pq.pop();
        order.push_back(v);
        for (int u : adj[v]) if (--indeg[u] == 0) pq.push(u);
    }
    return order;
}
```

**The labels trap.** A very similar looking problem asks something different. Give every vertex a label from 1 to n so that every edge goes from a smaller label to a bigger one, and make the list `label[1], label[2], ..., label[n]` as small as possible. Here we care about the label of vertex 1 first, then vertex 2, and so on. Running the min-heap order above and handing out labels in that order is wrong.

For example take 3 vertices and a single edge 3 → 1. The min-heap order is 2, 3, 1, which gives the labels `(3, 1, 2)`. But the labels `(2, 3, 1)` also follow the rule and are smaller, because vertex 1 gets label 2 instead of 3.

The fix is to work backwards. Instead of asking who gets the smallest label, ask who gets the biggest label. Among the vertices that are allowed to take the biggest label, give it to the vertex with the biggest number, so that small numbered vertices are kept free for small labels. In practice this means reversing the edges and using a max-heap.

```cpp
// edge u -> v means label[u] < label[v]
vector<int> minimalLabels(int n, vector<pair<int,int>>& edges) {
    vector<vector<int>> radj(n + 1);
    vector<int> outdeg(n + 1, 0);
    for (auto [u, v] : edges) { radj[v].push_back(u); outdeg[u]++; }

    priority_queue<int> pq;                               // max-heap of vertex numbers
    for (int v = 1; v <= n; v++) if (outdeg[v] == 0) pq.push(v);

    vector<int> label(n + 1);
    for (int cur = n; cur >= 1; cur--) {
        int v = pq.top(); pq.pop();
        label[v] = cur;
        for (int u : radj[v]) if (--outdeg[u] == 0) pq.push(u);
    }
    return label;
}
```

**Free swaps inside groups.** Sometimes we may swap elements as many times as we like, but only between certain pairs of positions. Positions that are connected through these pairs form a group, and inside a group any arrangement can be reached. So we find the groups with union find, sort the values inside each group, and put them back into that group's positions from smallest to largest.

Problems - LC 1202 Smallest String With Swaps, LC 2948 Make Lexicographically Smallest Array by Swapping Elements, LC 1505 Minimum Possible Integer After at Most K Adjacent Swaps On Digits, CF 825E Minimal Labels.

### 4. Building a permutation from scratch

Constructive problems ask us to produce any permutation with a given property, such as an up and down pattern or an exact number of distinct differences. These are usually solved by spotting a simple shape like a zigzag or a reversed block, and then checking that the shape really works.

**Following an I and D pattern.** We are given a string where `I` means the next number is bigger and `D` means it is smaller. Keep the smallest and largest unused numbers. On `I` use the smallest, since everything after it will be bigger. On `D` use the largest, since everything after it will be smaller.

```cpp
vector<int> diStringMatch(string s) {
    int lo = 0, hi = s.size();
    vector<int> ans;
    for (char c : s) ans.push_back(c == 'I' ? lo++ : hi--);
    ans.push_back(lo);
    return ans;
}
```

If the answer must also be the smallest such permutation, start with `1, 2, ..., n` and reverse every block that covers a run of `D`. For example `DI` turns `[1, 2, 3]` into `[2, 1, 3]`.

```cpp
vector<int> findPermutation(string s) {
    int n = s.size() + 1;
    vector<int> p(n);
    iota(p.begin(), p.end(), 1);
    for (int i = 0; i < (int)s.size(); ) {
        if (s[i] == 'I') { i++; continue; }
        int j = i;
        while (j < (int)s.size() && s[j] == 'D') j++;
        reverse(p.begin() + i, p.begin() + j + 1);
        i = j;
    }
    return p;
}
```

**Exactly k distinct differences.** Zigzag between the small and large ends of `1 .. k+1`, which produces the differences k, k-1, ..., 1, then write the rest in plain increasing order. For example with n = 5 and k = 3 we get `[1, 4, 2, 3, 5]` with differences 3, 2, 1, 2.

```cpp
vector<int> constructArray(int n, int k) {
    vector<int> ans;
    int lo = 1, hi = k + 1;
    while (lo <= hi) {
        ans.push_back(lo++);
        if (lo <= hi) ans.push_back(hi--);
    }
    for (int v = k + 2; v <= n; v++) ans.push_back(v);
    return ans;
}
```

**Smallest permutation with no fixed point.** We need `p[i] != i` everywhere. Swap neighbours in pairs to get `2, 1, 4, 3, ...`. If n is odd the last number is still in its own place, so swap the last two. For example n = 5 gives `[2, 1, 4, 5, 3]`.

Problems - LC 942 DI String Match, LC 484 Find Permutation, LC 667 Beautiful Arrangement II, CSES Permutations.

### 5. Giving each position a number from its range

Here every position i must get a different number from 1 to n, and that number must lie between `L[i]` and `R[i]`. We hand out the numbers in increasing order. When it is time to give out the number v, look at all positions that can take v and still have nothing. Give v to the one whose range ends soonest, because that position is the most at risk of being left empty. If even that position's range has already ended before v, no valid answer exists.

This is the same idea as always doing the task with the earliest deadline first.

```cpp
// ranges[i] = {L, R}. Returns the number given to each position, or empty if impossible.
vector<int> assignInRanges(vector<pair<int,int>>& ranges) {
    int n = ranges.size();
    vector<int> order(n);
    iota(order.begin(), order.end(), 0);
    sort(order.begin(), order.end(), [&](int x, int y) { return ranges[x].first < ranges[y].first; });

    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;  // (R, position)
    vector<int> ans(n);
    int j = 0;
    for (int v = 1; v <= n; v++) {
        while (j < n && ranges[order[j]].first <= v) {
            pq.push({ranges[order[j]].second, order[j]});
            j++;
        }
        if (pq.empty() || pq.top().first < v) return {};
        ans[pq.top().second] = v;
        pq.pop();
    }
    return ans;
}
```

This pattern shows up inside bigger problems more often than as a problem of its own.

### 6. Next permutation and the k-th permutation

The next permutation is the smallest permutation that is bigger than the current one. Walk from the right and find the first position i where `a[i] < a[i+1]`. Everything to the right of i is in decreasing order, so it is already as large as it can be. Swap `a[i]` with the smallest number on its right that is still bigger than it, then reverse the part after i so that it becomes as small as possible.

```cpp
void nextPermutation(vector<int>& a) {
    int n = a.size(), i = n - 2;
    while (i >= 0 && a[i] >= a[i + 1]) i--;
    if (i >= 0) {
        int j = n - 1;
        while (a[j] <= a[i]) j--;
        swap(a[i], a[j]);
    }
    reverse(a.begin() + i + 1, a.end());
}
```

To find the k-th permutation directly, fill the positions one at a time. With m numbers still unused, each choice for the current position starts a block of `(m-1)!` permutations. Dividing k by that block size tells us which unused number goes here, and the remainder tells us where we are inside that block.

```cpp
string getPermutation(int n, int k) {
    vector<int> fact(n + 1, 1), nums;
    for (int i = 1; i <= n; i++) { fact[i] = fact[i - 1] * i; nums.push_back(i); }
    k--;                                        // switch to 0-indexed
    string ans;
    for (int m = n; m >= 1; m--) {
        int idx = k / fact[m - 1];
        ans += to_string(nums[idx]);
        nums.erase(nums.begin() + idx);
        k %= fact[m - 1];
    }
    return ans;
}
```

Problems - LC 31 Next Permutation, LC 60 Permutation Sequence.

### Quick recap

- To pair two arrays, sort them the same way to make the total large and opposite ways to make it small.
- To count the fewest moves, first ask what the allowed move changes by exactly one, or what never needs to move.
- To find the smallest permutation, fill left to right and always check that the rest can still be completed.
- When labels are asked for vertex by vertex, work backwards and hand out the biggest label first.
- For constructive problems, look for a zigzag or a reversed block and then check it.
