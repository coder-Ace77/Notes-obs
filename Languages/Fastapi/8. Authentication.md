### OAuth2 

OAuth 2.0 is the industry-standard protocol for **authorization**. OAuth allows an app to access specific parts of your data without ever seeing your password.

Before OAuth, if a third-party app (let’s call it "PrintMyPhotos") wanted to access your Google Photos, it would have to ask for your **Google username and password**.

This created several massive security headaches:

- **The "All or Nothing" Problem:** Once the app had your password, it could read your emails, delete your files, and change your settings.
- **Trust Issues:** You had to trust a random app developer to store your password securely.
- **Revocation Nightmare:** If you wanted to stop the app from accessing your photos, you had to change your Google password, which would break every other app you used.

### Key components

|**Component**|**Role**|**Real-world Example**|
|---|---|---|
|**Resource Owner**|The user who owns the data.|**You**|
|**Client**|The application requesting access.|**PrintMyPhotos App**|
|**Authorization Server**|The server that verifies your identity and issues tokens.|**Google Accounts**|
|**Resource Server**|The server holding the data you want to share.|**Google Photos API**|

The most common "flow" used for web applications is the **Authorization Code Flow**. It’s a bit of a back-and-forth dance to ensure maximum security.

1. **The Request:** You click "Login with Google" on the PrintMyPhotos app.
2. **User Authorization:** The app redirects you to Google’s site. Google asks, "Do you want to let PrintMyPhotos see your photos?"
3. **The Grant:** You click "Yes." Google sends you back to the PrintMyPhotos app with a temporary **Authorization Code**.
4. **The Exchange:** PrintMyPhotos takes that code and sends it back to Google behind the scenes (server-to-server), along with a secret "Client ID."
5. **The Token:** Google verifies the code and the secret, then issues an **Access Token**.
6.  **Access:** PrintMyPhotos now presents that token to the Google Photos API to get your pictures.

##### Advantages of OAuth 2.0

- **No Password Sharing:** The third-party app never sees your login credentials.
- **Granular Permissions (Scopes):** You can allow an app to _read_ your files but not _delete_ them.
- **Easy Revocation:** You can go into your Google/Facebook settings and "Revoke Access" for a specific app at any time without changing your password.
- **Better User Experience:** Users don't have to create a new username and password for every single website they visit.


### Login/signup using oauth2

To implement a username and password login/signup system using OAuth2 in FastAPI, we use the **OAuth2 with Password (and hashing), Bearer with JWT tokens** flow.

In this flow:

1. The user sends their username and password directly to a specific endpoint (usually `/token` or `/login`).
2. The server verifies the credentials and returns a **JSON Web Token (JWT)**.
3. For subsequent requests, the user sends that JWT in the `Authorization` header (as a "Bearer" token).

```python
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from pydantic import BaseModel
from passlib.context import CryptContext
import jwt
from datetime import datetime, timedelta, timezone

# --- Configuration ---
SECRET_KEY = "your-super-secret-key-change-this-in-production"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

app = FastAPI()

# This tells FastAPI where the client should send the username/password to get a token
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="login")

# Password hashing configuration
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# --- Mock Database ---
# In a real app, you would use SQLAlchemy, Motor, etc.
fake_users_db = {}

# --- Pydantic Models ---
class UserCreate(BaseModel):
    username: str
    password: str

class UserResponse(BaseModel):
    username: str

class Token(BaseModel):
    access_token: str
    token_type: str

# --- Helper Functions ---
def verify_password(plain_password, hashed_password):
    return pwd_context.verify(plain_password, hashed_password)

def get_password_hash(password):
    return pwd_context.hash(password)

def create_access_token(data: dict):
    to_encode = data.copy()
    expire = datetime.now(timezone.utc) + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    encoded_jwt = jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
    return encoded_jwt

# Dependency to get the current authenticated user
async def get_current_user(token: str = Depends(oauth2_scheme)):
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username: str = payload.get("sub")
        if username is None:
            raise credentials_exception
    except jwt.InvalidTokenError:
        raise credentials_exception
    
    user = fake_users_db.get(username)
    if user is None:
        raise credentials_exception
    return user

# --- API Endpoints ---

@app.post("/signup", response_model=UserResponse)
async def signup(user: UserCreate):
    if user.username in fake_users_db:
        raise HTTPException(status_code=400, detail="Username already registered")
    
    hashed_password = get_password_hash(user.password)
    fake_users_db[user.username] = {
        "username": user.username,
        "hashed_password": hashed_password
    }
    return {"username": user.username}

@app.post("/login", response_model=Token)
async def login(form_data: OAuth2PasswordRequestForm = Depends()):
    # OAuth2PasswordRequestForm expects form data, NOT JSON
    user_dict = fake_users_db.get(form_data.username)
    
    # Check if user exists and password is correct
    if not user_dict or not verify_password(form_data.password, user_dict["hashed_password"]):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",
            headers={"WWW-Authenticate": "Bearer"},
        )
    
    # Generate the JWT Token
    access_token = create_access_token(data={"sub": user_dict["username"]})
    return {"access_token": access_token, "token_type": "bearer"}

@app.get("/users/me")
async def read_users_me(current_user: dict = Depends(get_current_user)):
    # This route is protected! It requires a valid JWT token.
    return {"message": f"Hello, {current_user['username']}! You are authenticated."}
```


- **`OAuth2PasswordRequestForm`**: This is a FastAPI class dependency that strictly enforces the OAuth2 specification. The spec states that for a password login flow, the client _must_ send the data as `application/x-www-form-urlencoded` (form data), **not** JSON.
    
- **`OAuth2PasswordBearer`**: This tells FastAPI that the API is secured using OAuth2 Bearer tokens. When you inject it into a route via `Depends()`, FastAPI will automatically look for the `Authorization` header, strip the word "Bearer ", and give you the raw JWT string.
    
- **`Depends(get_current_user)`**: This is how you lock down a route. Any route that includes this dependency cannot be accessed without a valid token.

Explaination

In this setup, your FastAPI application is actually playing **two roles** from our earlier OAuth explanation: it is acting as both the **Authorization Server** (issuing the tokens) and the **Resource Server** (holding the protected data).

First we have configuration and setup

```python
SECRET_KEY = "your-super-secret-key-change-this-in-production"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="login")
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
```

**The Secret Key:** This is the most important string in your app. It is used to cryptographically "sign" your JWTs (JSON Web Tokens). If a hacker gets this key, they can forge tokens and log in as anyone.

- **The Algorithm:** `HS256` is the standard hashing algorithm used to sign the token.
- **`OAuth2PasswordBearer`:** This is FastAPI's built-in magic. By setting `tokenUrl="login"`, you are telling FastAPI: _"When a client (like the Swagger UI frontend) needs a token, tell it to send the username and password to the `/login` endpoint."_
- **`CryptContext`:** We use `passlib` with the `bcrypt` algorithm. You **never** save passwords as plain text. This object handles converting a user's password into a scrambled, irreversible hash.

JWT creation

```python
def create_access_token(data: dict):
    to_encode = data.copy()
    expire = datetime.now(timezone.utc) + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    encoded_jwt = jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
    return encoded_jwt
```

When a user logs in successfully, this function builds their JWT.

1. **The Payload (`data`):** We pass in a dictionary, usually containing `"sub": username` ("sub" stands for subject, a standard JWT claim).
2. **Expiration (`exp`):** Tokens shouldn't last forever. If a token is stolen, an expiration limits the damage. We set it to expire in 30 minutes.
3. **Encoding:** `jwt.encode` takes the data, slaps the expiration on it, and locks it all together using your `SECRET_KEY`.

Now we implement a dependency as the security guard if the user is not found or is not logged in this function will return `401` unauthorised. 

```python
async def get_current_user(token: str = Depends(oauth2_scheme)):
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username: str = payload.get("sub")
        if username is None:
            raise credentials_exception
    except jwt.InvalidTokenError:
        raise credentials_exception

    user = fake_users_db.get(username)
    if user is None:
        raise credentials_exception
    return user
```

Note that usually we try to put the userid or username in the `sub` part of jwt token. 

This function is the bouncer for your protected routes.

- Because we use `Depends(oauth2_scheme)`, FastAPI automatically intercepts the incoming request, looks for an `Authorization: Bearer <token>` header, and extracts the `<token>` string.
    
- `jwt.decode` verifies the token. It checks two things: **Did I sign this with my Secret Key?** and **Has the `exp` time passed?** If either fails, it throws an error.
    
- If it passes, it extracts the username, grabs the user from the database, and hands that user object to your endpoint.

Finally we have this current_user which is populated due to dependency injection. 

```python
@app.get("/users/me")
async def read_users_me(current_user: dict = Depends(get_current_user)):
    # This route is protected! It requires a valid JWT token.
    return {"message": f"Hello, {current_user['username']}! You are authenticated."}
```

```python
import jwt

SECRET_KEY = "your-super-secret-key-change-this-in-production"

ACCESS_TOKEN_EXPIRE_MINUTES = 30

app = FastAPI(title="JSON OAuth2 Backend Example")

# We still use OAuth2PasswordBearer to extract the token from headers on protected routes.
# The tokenUrl="login" points to our route, but remember the Swagger UI "Authorize" button 
# will fail because it tries to send Form Data, while our route now requires JSON.
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="login")
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# --- 2. Mock Database ---
fake_users_db = {}

# --- 3. Pydantic Models (The JSON Schemas) ---
class UserCreate(BaseModel):
    username: str
    password: str

# This model is what forces the /login route to expect JSON
class LoginData(BaseModel):
    username: str
    password: str

class UserResponse(BaseModel):
    username: str

class Token(BaseModel):
    access_token: str
    token_type: str

# --- 4. Helper Functions ---
def verify_password(plain_password, hashed_password):
    return pwd_context.verify(plain_password, hashed_password)

    return pwd_context.hash(password)

        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )

        # Decode and verify the token
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username: str = payload.get("sub")
        if username is None:
            raise credentials_exception
    except jwt.InvalidTokenError:
        raise credentials_exception
    
    # Fetch the user from the database
    user = fake_users_db.get(username)
    if user is None:
        raise credentials_exception
    return user

# --- 5. API Endpoints ---

@app.post("/signup", response_model=UserResponse)
async def signup(user: UserCreate):
    if user.username in fake_users_db:
        raise HTTPException(status_code=400, detail="Username already registered")
    
    # Hash the password before saving
    hashed_password = get_password_hash(user.password)
    fake_users_db[user.username] = {
        "username": user.username,
        "hashed_password": hashed_password
    }
    return {"username": user.username}

@app.post("/login", response_model=Token)
async def login(login_data: LoginData):
    # Notice we access the data via login_data (our Pydantic model)
    user_dict = fake_users_db.get(login_data.username)

    if not user_dict or not verify_password(login_data.password, user_dict["hashed_password"]):

    return {"access_token": access_token, "token_type": "bearer"}

@app.get("/users/me")
async def read_users_me(current_user: dict = Depends(get_current_user)):
    # This route is protected. It requires the JWT in the Authorization header.
    return {
        "message": f"Welcome, {current_user['username']}!",
        "note": "You have successfully accessed a protected route using a JSON-obtained token."
    }
```


Final flow 

- **The Request Arrives:** A request hits your `/users/me` endpoint. The user's browser or frontend app has attached the header: `Authorization: Bearer eyJhbGciOiJIUzI1...`
    
- **FastAPI Checks Dependencies:** Before running the code inside your `read_users_me` function, FastAPI looks at the parameters. It sees: `current_user: dict = Depends(get_current_user)`. It knows it has to run `get_current_user` first.
    
- **The Chain Continues:** FastAPI goes to run `get_current_user`. But wait! It looks at _that_ function's parameters and sees: `token: str = Depends(oauth2_scheme)`. It knows it has to run `oauth2_scheme` first.
    
- **The Extraction:** `oauth2_scheme` is a built-in FastAPI class (`OAuth2PasswordBearer`). Under the hood, this class is programmed to do exactly one job:
    
    - It grabs the raw incoming HTTP request.
        
    - It looks for the `Authorization` header.
        
    - It checks if the value starts with "Bearer ".
        
    - It chops off the word "Bearer " and returns _just_ the raw token string (`eyJhbGciOiJIUzI1...`).
        
- **Passing it Back Up:** Now that `oauth2_scheme` has the token string, it passes it into the `token` variable of `get_current_user`. Your function decodes it, finds the user, and passes that user into the `current_user` variable of your final endpoint.

Note - Oauthscheme needs the tokenUrl only for the swagger ui. 

### Implementing the login with google 

To implement a "Login with Google" feature in a React + FastAPI stack, the industry standard is to use the **Google ID Token Verification Flow**.

Google provides a clean popup on your React frontend. Google hands React a secure **ID Token**, which React sends to FastAPI. FastAPI verifies the token with Google, creates the user if they don't exist, and then issues your application's own JWT.

### Step 1: Get Your Google Credentials

Before writing any code, you need to tell Google about your app:
1. Go to the [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project (or select an existing one).
3. Navigate to **APIs & Services > Credentials**.
- Click **Create Credentials > OAuth client ID**.
- Choose **Web application** as the application type.
- Under **Authorized JavaScript origins**, add your React app's URL (e.g., `http://localhost:3000`)
- Click **Create** and copy your **Client ID** (you won't need the Client Secret for this specific flow).

Google provides an official, modern React library that handles the UI and the token generation perfectly.

```python
npm install @react-oauth/google axios
```

```js
import React from 'react';
import { GoogleOAuthProvider, GoogleLogin } from '@react-oauth/google';
import axios from 'axios';

const clientId = "YOUR_GOOGLE_CLIENT_ID.apps.googleusercontent.com";

function App() {
  
  const handleGoogleSuccess = async (credentialResponse) => {
    // 1. Google gives us an ID token (credentialResponse.credential)
    const googleToken = credentialResponse.credential;
    
    try {
      // 2. Send this token to our FastAPI backend
      const response = await axios.post('http://localhost:8000/auth/google', {
        token: googleToken
      });
      
      // 3. Our backend returns OUR app's JWT. Store it!
      const myAppToken = response.data.access_token;
      localStorage.setItem('token', myAppToken);
      
      console.log("Successfully logged in to our backend!");
      
    } catch (error) {
      console.error("Backend authentication failed", error);
    }
  };

  return (
    <GoogleOAuthProvider clientId={clientId}>
      <div style={{ padding: '50px' }}>
        <h2>Login to My App</h2>
        
        {/* This renders the official "Sign in with Google" button */}
        <GoogleLogin
          onSuccess={handleGoogleSuccess}
          onError={() => console.log('Google Login Failed')}
        />
        
      </div>
    </GoogleOAuthProvider>
  );
}

export default App;
```

```python
from fastapi import FastAPI, HTTPException, status, Depends
from pydantic import BaseModel
from google.oauth2 import id_token
from google.auth.transport import requests

# --- Configuration ---
GOOGLE_CLIENT_ID = "YOUR_GOOGLE_CLIENT_ID.apps.googleusercontent.com"
# (Assume SECRET_KEY, ALGORITHM, and create_access_token are already defined from previous examples)

app = FastAPI()

# --- Mock Database ---
fake_users_db = {}

# --- Pydantic Model for incoming request ---
class GoogleToken(BaseModel):
    token: str

@app.post("/auth/google")
async def google_login(token_data: GoogleToken):
    try:
        # 1. Verify the token with Google's servers
        # This confirms the token was actually issued by Google and is intended for your app.
        idinfo = id_token.verify_oauth2_token(
            token_data.token, 
            requests.Request(), 
            GOOGLE_CLIENT_ID
        )
        
        # 2. Extract user data from the verified token
        email = idinfo.get("email")
        name = idinfo.get("name")
        google_id = idinfo.get("sub") # 'sub' is Google's unique, permanent ID for this user
        
        if not email:
            raise HTTPException(status_code=400, detail="No email provided by Google")

        # 3. Database Logic: Signup or Login?
         user = fake_users_db.get(email)
        
        if not user:
            # SIGNUP: This is a new user! Create an account for them in your database.
            # Notice we don't need a password since Google handles authentication.
            fake_users_db[email] = {
                "username": email,
                "full_name": name,
                "google_id": google_id,
                "auth_provider": "google"
            }
            print(f"Created new user account for: {email}")
            
        else:
            # LOGIN: User exists. You might want to update their name or profile picture here.
            print(f"Logged in existing user: {email}")

        # 4. Generate OUR application's JWT
        # From here on out, the frontend uses THIS token, not the Google token.
        access_token = create_access_token(data={"sub": email})
        
        return {"access_token": access_token, "token_type": "bearer"}
        
    except ValueError:
        # If the token is expired, forged, or for the wrong Client ID, this exception is raised.
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid Google token"
        )
```
